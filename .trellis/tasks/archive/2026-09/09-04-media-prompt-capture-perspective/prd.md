# 修正媒体提示词的拍摄视角补全规则

## Goal

让媒体提示词在缺少明确拍摄方式时，仍然生成物理关系自洽的画面：人物数量、拍摄关系、镜面反射、手机/相机是否入镜不能互相矛盾，也不能出现“第三方拍摄者突然入镜”或“自拍却看见手持拍摄设备”等常见错误。

本任务只处理媒体提示词的拍摄视角补全（问题 1）。生图完成后的 LLM 质量判断、失败后的提示词修订和重试工作流属于后续独立任务，不在本任务实现。

## 已确认的仓库事实

- Go Worker 在 `apps/core-go/internal/core/media.go:64` 以 `media_prompt` 角色调用 Provider，将已持久化的媒体意图提示词转换为 ComfyUI 的最终提示词；当前系统提示已覆盖一般自拍与第三人称逻辑，但没有明确“单人/多人 + 未指定拍摄方式”的补全规则。
- `apps/core-go/internal/core/media_context.go:113` 只负责把认知阶段冻结的场景、活动、地点和当前外观绑定到媒体提示词，不负责推断镜头语义。
- `.trellis/spec/backend/media-prompt-contract.md` 规定拍摄关系由 AI 人格/提示词主模型负责，服务端不得通过关键词、正则或默认分支猜测人物数量、自拍、第三方视角、设备可见性等视觉语义。本任务应在媒体提示词模型的契约/系统指令及其测试层解决，不能把规则下沉为服务端文本解析。
- 当前提示词输出仍要求只返回英文、连续的 provider prompt；既有的主体、动作、场景、光影和输出格式约束需要保持。

## Requirements

### R1. 拍摄关系的决策边界

媒体提示词模型必须先识别已声明的真实人类主体和明确拍摄关系，再补全缺失的镜头关系。衣服、道具、宠物、屏幕、镜面/倒影和环境物体不能被计入人物数量，也不能被改写成人类主体。用户或上游概念已经明确的自拍、镜子拍摄、第三方拍摄、取景角度和构图优先于补全规则。

### R2. 单人画面规则（已确认“构图优先”映射）

当画面只有一名真实人类主体时，模型必须先判断目标构图（身体局部、上半身/近距离、全身等），再补充能够实现该构图的摄像头和拍摄关系；不能先随意选“自拍”再强行填入不可能的画面。已确认的核心映射为：身体局部特写 → 后摄手机自持拍摄；上半身/脸部近景 → 前摄手机自拍；全身自拍 → 全身镜；第三方拍摄可实现任意构图。

- 身体某一部分的局部特写：优先补充“后摄手机自持拍摄”，使镜头能够对准身体局部；不得误写成主体看向前摄镜头的正面自拍。手机本体通常不入镜，除非明确是镜子拍摄或要求设备入镜。
- 上半身或脸部近距离特写：优先补充“前摄手机自拍”；手机/相机设备默认不入镜，主体视线和透视应符合前置镜头自拍。
- 全身构图：普通前摄或后摄手机自持自拍不能直接实现；单人自己拍到全身时必须补充“全身镜拍摄”。全身镜需要足够覆盖全身，手机可以且通常应在镜中或画面中出现；普通小镜面不能被补全成全身镜。三脚架、定时器或其他固定远距离机位不作为本任务的隐式回退方式，除非上游明确声明这种拍摄方式。
- 第三方拍摄：如果明确由画面外第三方拍摄，单人可以是全身或其他构图，但拍摄者与拍摄设备均不入镜。

### R3. 多人画面规则

当画面包含两名或以上真实人类主体时，也必须先判断目标构图，再选择能够实现该构图的拍摄关系；多人场景沿用同一“构图优先”原则。已确认的核心映射为：多人身体局部特写 → 后摄手机自持拍摄；多人上半身/近距离合照 → 前摄多人自拍；多人全身自拍 → 全身镜；第三方拍摄可实现任意构图。

- 多人身体局部/细节特写：可补充“后摄手机自持拍摄”，镜头聚焦被拍者的局部，不写成所有人同时看向前摄镜头的自拍合照。
- 多人上半身或近距离合照：优先补充“前摄多人自拍”，保持近距离群体自拍透视；拍摄手机默认不直接出现在画面中。
- 多人全身合照：多人自己完成时必须补充足够大的全身镜；不能用普通前摄/后摄手持自拍直接声称拍到完整全身。三脚架、定时器或其他固定远距离机位只有在上游明确声明时才可使用。
- 多人镜子合照：镜面大小必须支持所声明的构图；镜面和拍摄手机可以可见，反射关系必须自洽。
- 第三方/观察者拍摄：相机位于画面外的第三方视角；可实现上半身、局部或全身等构图，但拍摄者本人和拍摄设备都不得出现在成片中。

### R4. 物理一致性和冲突消解

模型必须以构图目标为第一决策轴，并消除镜头关系冲突：不能把身体局部后摄自持拍摄写成前摄正面自拍，不能把上半身前摄自拍写成第三人称旁观，不能在非镜面自拍中同时展示拍摄手机，不能在第三方拍摄中加入摄影者或相机，不能因全身构图而假装普通手持手机已经拍到了全身。单人/多人规则只决定缺失信息，不能覆盖已锁定的明确要求。

### R5. 保持现有提示词边界

继续输出单条英文 provider prompt，并保留现有主体身份、动作、场景、光影、风格、负面约束和上下文绑定语义。不得新增服务端关键词/正则分支、人物计数器或根据字符串猜测拍摄关系的 fallback；不得在媒体 worker 中编写第二套视觉语义编译器。

### R6. 规则必须由媒体提示词 LLM 执行

上述构图与拍摄关系映射、设备可见性、摄影者排除和完全模糊请求的默认值，必须作为 `media_prompt` 角色的系统提示词/模型契约明确告诉 LLM，由 LLM 结合媒体描述和已绑定上下文做判断。Go Worker 只能传递输入、调用 Provider、处理模型返回并提交最终 prompt，不得把这些规则实现为服务端规则引擎或关键词判断。

当上游既没有明确构图范围，也没有明确“自拍/镜子/第三方”时，已确认的默认值是：单人使用上半身或脸部近景 + 前摄手机自拍；多人使用多人上半身近距离合照 + 前摄多人自拍；手机默认不入镜；只有上下文明确要求身体局部或全身时，才分别应用后摄手机自持或全身镜/第三方拍摄。

## Acceptance Criteria

- [ ] 媒体提示词系统指令或等价的模型契约明确写出单人自拍、单人镜子、多人自拍、多人镜子、多人第三方五类关系，以及各自的设备可见性和摄影者可见性规则。
- [ ] 单人、未指定拍摄方式的 fixture 在采用确认后的默认策略时稳定得到手机自拍或镜子拍照，且全身构图不会让手机意外入镜。
- [ ] 单人前摄自拍 fixture 只能得到上半身/近距离特写，不会生成普通前摄全身自拍。
- [ ] 单人身体局部特写 fixture 会补出后摄手机自持拍摄，不会被写成主体看向前摄镜头的正面自拍。
- [ ] 单人上半身/脸部近景 fixture 会补出前摄手机自拍，设备默认不入镜。
- [ ] 单人全身构图只有在全身镜或画面外第三方等具备物理条件时成立；普通前摄/后摄手持自拍和普通镜面不能被补成全身镜拍摄。
- [ ] 单人镜子 fixture 明确包含镜面关系，并允许手机可见；不会被补全成普通自拍或第三方拍摄。
- [ ] 多人自拍、多人镜子和多人第三方 fixture 分别保持正确的入镜主体、镜面/自拍关系和设备/摄影者排除规则。
- [ ] 多人身体局部特写 fixture 可补出后摄手机自持拍摄；多人上半身/近距离合照 fixture 可补出前摄多人自拍；多人全身构图需要全身镜或明确的固定/第三方拍摄条件。
- [ ] 多人第三方 fixture 不出现拍摄者或拍摄设备；多人自拍 fixture 不被写成“画面外摄影者拍摄”。
- [ ] 明确要求的 capture/view/device/framing 事实优先于单人/多人补全规则，冲突时不被默认策略覆盖。
- [ ] 衣物、道具、宠物、屏幕、倒影等非人类对象不会改变人物数量或触发错误的自拍/多人规则。
- [ ] 回归测试确认 `media_prompt` 调用仍只返回 provider prompt，且现有上下文绑定、ComfyUI `{{prompt}}` 注入和媒体任务幂等行为不受影响。
- [ ] 源码/回归检查确认没有新增服务端视觉关键词、正则或人物数量默认分支。

## Out of Scope

- 生图完成后由 LLM 进行质量验收。
- 不合格图片的提示词修订、自动重试、重生成和“合格后才发送”工作流。
- 图生图参考图、头像一致性或媒体资产版本策略。
