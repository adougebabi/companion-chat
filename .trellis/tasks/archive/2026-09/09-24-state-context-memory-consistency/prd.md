# 当前状态、上下文投影与分层记忆一致性增强

## 目标

在现有 Go Core、Eino Agent Loop、Tool、Provider、数据库和工作流上，让当前事实、送模上下文与可追溯记忆共享一致的版本和作用域规则。普通对话、WakeUp、Reflection、初始化及相关任务必须接入正式链路；保留已有 Working Persona、动态生活和自治设计。

## 已确认基线

- Working Persona 已持久化且校验 Foundation、overlay、profile habits 的源版本；当前身体/衣柜/穿着已由 Effective Life 表持有，初始化 backfill 使用 `ON CONFLICT DO NOTHING`。
- 主聊天、WakeUp、Reflection 等已有投影组装入口；初始化和部分一次性任务仍直接调用 `ComposeTaskMessages`。Eino 工具调用和结果由原生循环配对；工具收据与业务效果同事务落库。
- Raw History、Active Memory、conversation summary、durable `memories`、Working Memory 已存在。长期记忆有修订和治理记录，摘要有来源摘要，但 Episode 与 Resident 没有明确的发布契约，跨层来源和失效传播不完整。

## 范围与约束

1. 按字段收敛权威：稳定身份/受保护人格、激活人格/已生效演进、可变身体与生活、衣柜/搭配/穿着、意愿/计划/行动结果、历史/主观判断各有明确读写来源。初始化值只在一次性创建/迁移时进入当前态；未知、清空、删除、未初始化区分。
2. 状态变化由合法 Tool、确认事件或成功的虚拟行动结果生效，带主体/作用域、版本、来源、幂等和发生/记录时间。意愿、计划、正在执行、成功、失败/取消、未确认不得混淆。
3. 原始记录保持完整；每次模型请求使用只读、预算受控、有来源映射的上下文投影。各 Agent 保留任务指令、工具权限与所需数据；未消费的原生工具调用/回执保持完整、配对，更新后按需刷新当前态。
4. 记忆记录来源、主体/可见性、类型、版本、状态、发生与记录时间、多来源依赖。引用由宿主验证；纠正、删除和来源失效传播至派生层、索引、检索及投影，后台旧结果不能复活失效内容。
5. 在现有存储/任务设施上形成可追溯 Episode → Long-term → Resident。三层职责不同，增量触发、代际一致发布；Resident 的裁剪不得影响底层搜索。
6. 迁移历史数据可重跑、可核对；无法可靠追溯的内容标为 legacy/来源未知，不能提升为已证实当前事实。最终清理旧注入/回填路径，不保留正常运行时双写或静默回退。
7. 不新增模型分级、Nimble、Jev、System-1、新 Agent 框架、向量库、消息队列、事件溯源平台或付费服务。不自动提交、推送或直接修改生产数据。

## 可观察验收

- 当前事实：剪发成功后跨轮次、重启/跨天/反思仍为短发；仅有剪发或购买意愿不更改外观/库存；获得物品可复用且重复结果不重复入库；库存、搭配、穿着独立；人格切换/场景变化不改穿着；用户与角色隔离；迟到写入拒绝。
- 投影：同一字段不同时注入矛盾的“当前”值；人格约束、当前输入、未消费工具回执和关键失败不被预算裁掉；原始消息不变；不同主体/覆盖范围不误去重；工具更新后的下一请求读取新状态；资料不升级为指令，不泄漏未授权记忆。
- 记忆：三层均可追溯原始依据；摘要不增加独立证据数；唯一来源删除后不再召回，多来源仍可保留有效支持；纠正影响检索与下一轮；旧后台任务不能复活；legacy 不伪装已验证；未变化不重跑；跨天未完成事项保留；Resident 裁剪不损坏搜索；人格共享/专属权限正确；失败不发布半成品。
- 真实运行：使用项目实际入口、现有模型配置和自然语言多轮场景验证事实变化、未执行意愿、非 Resident 记忆检索、纠正生效、无工具闲聊无固定额外模型调用；保存首次/后续实际请求、工具回执、持久化重读和模型调用次数。凭据/环境不可用时如实标记 BLOCKED。
- 交付：代码、可重复迁移、确定性测试、真实运行证据和独立 Markdown 报告，分别标记实现、确定性验证、真实模型验证状态及残余风险。

## 不在范围

完整购物产品、全新生活模拟引擎、核心人格重设计、普通对话强制规划/反思/记忆整理、新模型和其他架构升级。
