# 给本地 Codex 的复刻说明

## 目标

把这个 Demo 的视觉和交互逐页移植到 `companion-chat` 正式项目。以本 Demo 的实际运行界面为 UI/UX 基准，以正式项目已有 API、业务契约、领域模型为数据基准。

保留当前项目功能，不重新猜一套界面。不要在复刻过程中自行增加配色、阴影、卡片层级、操作按钮或第三套布局。

## 建议直接交给本地 Codex 的任务

> 先运行这个 Demo，阅读 `src/App.tsx`、`src/index.css`、`src/components/shared.tsx` 和目标页面组件。请逐页一比一复刻到正式项目：布局、间距、字号、颜色、图标、按钮位置、详情打开方式和保存/返回行为都以 Demo 为准。正式业务请求复用现有服务与领域控制器，不把 Demo 的模拟器、localStorage 或固定示例数据接入生产逻辑。一次只移植一个模块，先完成公共壳层与设计变量，再完成目标页。每页完成后用相同视口截图对照，验证浏览、编辑、取消、保存、返回和错误恢复。不要在未完成对照前扩展其它页面，也不要顺手重构不相关业务代码。

| 页面标题 | 27 px / 600；上方 9 px 英文辅助标识，下方 12 px 简介            |
| 卡片     | 12 px 圆角，1 px 边框，通常 23 px 内边距                        |
| 控件     | 统一 shadcn/ui；输入约 39 px 高，按钮约 36 px，高优先级 42 px   |

## 移植顺序

1. **公共壳层**：导航、角色切换、面包屑、标题、按钮、输入、详情、确认和状态标签。
2. **角色库与聊天**：建立首屏，验证角色作用域和聊天草稿隔离。
3. **生活模块**：此刻、日程、目标、衣柜、日记、记忆。
4. **世界与联系**：运行世界/地点、人物关系、关于你、动态、媒体。
5. **创作中心**：资源列表、类型编辑、草稿、发布、版本、应用、沙盒。
6. **初始化**：生活世界、四种来源、分组预览、七项准备和恢复。
7. **管理中心**：设置二级目录、模型连接和用途、诊断、任务、数据管理。

## 必须保持的交互区分

| 场景           | 交互合同                                                   |
| -------------- | ---------------------------------------------------------- |
| 草稿与正式保存 | 表单输入不等于保存；取消应保留或还原到正确基线             |
| 世界复用       | 复制背景、规则和地点配置；为新角色建立独立世界             |
| 资源发布       | 先保存草稿，再发布明确版本；发布不会自动应用到运行角色     |
| 初始化空白     | 跳过分析，不提交 foundation 或 analysisId                  |
| 非空白初始化   | 分析、预览、编辑、确认；保留完整嵌套结构与未知扩展         |
| 初始动机       | 取消采用目标/意图，不删除初始关系                          |
| 初始化回退     | 激活前可以编辑前序步骤；激活后只查看快照与恢复原任务       |
| 结果未知       | 核对原请求，不以新请求再次创建                             |
| 准备进度       | 以七个阶段的确认完成状态计算，不能用计时伪装后端进度       |
| 衣柜           | 保存方案与请求换装分离；实际穿着确认后同步到此刻与聊天     |
| 日程           | 提交调整建议，区分待处理、采纳和拒绝；不无条件覆盖执行事实 |
| 目标           | 请求核对进展，由实际证据确认结果                           |
| 记忆           | 纠正正文、保留来源和历史；类型、评分等不冒充普通可改字段   |
| 人格切换       | 目标、原因、确认、请求状态与历史均可查看                   |
| 关于你         | 用户自填资料，与角色已有认识/关系指标分开                  |
| 视觉           | 定义、候选参考、接受的规范参考、设定图和显示头像分开       |
| 模型配置       | 服务连接与四种用途绑定分开，模型 ID 可选择或手填           |
| 异步操作       | 接收请求、任务运行、产物读回不是同一种成功状态             |

## 状态与数据的正式对接

Demo 的 `useDemoData` 是本地原型状态，不是正式的数据访问架构。移植时把页面输入与 UI 状态保留，把数据读取/写入替换为项目现有 controller/client。

`useRuntime()` 是为了保证聊天、此刻和衣柜在演示中一致。正式项目应读取同一领域快照，不应在每个页面各写一份当前穿着、位置或日程。

所有具有后果的按钮需要明确结果：保存结果、修订记录、任务状态、应用差异或已确认的产物。不要只显示一个成功 toast 就当作完成业务。

## 每页验收

- 与 Demo 相同视口下比较：侧栏、主内容宽度、标题、卡片间距、控件尺寸、文字层级。
- 所有可点击元素都有正确动作；搜索、过滤和无结果状态可用。
- 编辑后取消不意外保存，保存后回到原上下文。
- 打开与关闭详情不会让用户丢失列表位置、筛选或当前对象。
- 返回上一步保留需要保留的输入；创建完成后不会因回退重复激活。
- 失败、未知、待审阅与配置缺失分别有可理解的下一步。
- 键盘可聚焦，弹窗可 Escape 关闭，窄屏没有横向溢出。
- 同一业务字段在聊天、此刻、档案和衣柜等页面保持一致。

## 不要复制到正式环境的部分

`setTimeout` 模拟结果、固定聊天回应、示例插画候选、假发布版本、演示日期、浏览器密码输入演示、本地 JSON 工作区备份、`demo-*` 请求 ID。这些仅用于明确界面与交互状态。

后端流程的暂停、取消和恢复必须按正式接口的 `allowed_actions` 决定。初始化页没有任意跳过衣柜/日程/图像步骤的开关；也没有把前端停止等待解释为取消后端任务。
