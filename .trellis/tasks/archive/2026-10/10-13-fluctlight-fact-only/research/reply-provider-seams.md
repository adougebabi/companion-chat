## Nested queue leases and context hazards

- `provider.go:314-324` explicitly installs queue bypass for the *outer ADK loop*: “Queue each call ... instead of holding one lease for the full Agent loop.” The outer runProviderQueued therefore does not occupy a generated slot while ADK invokes tools.
- `eino_model_runtime.go:114` physical Generate clears that bypass (`withoutProviderQueueBypass(ctx)`), gives each physical call a separate attempt, applies assignment timeout, records queued model_run and calls runProviderQueued at :132. That queue wraps only `m.inner.Generate` (:139). Thus physical Generate completes and its local task finishes before Tool execution can start; Redis defer release occurs before Generate returns. No parent lease is intentionally held across Tool callbacks.
- `provider_queue.go:134-193`: runProviderQueued checks bypass first; otherwise acquires Redis slot, defers releaseRedis, submits physical fn to local queue. `ai/model/queue.go:243-250` sends task.Done then decrements running under mutex. There can be a tiny scheduling delay before a pending nested request starts, but no synchronous dependency that retains parent running slot across tool execution.
- `eino_model_runtime.go:574-676`: streamed lease deliberately stays through inner.Recv EOF or close; worker observes EOF and returns, then writer.Close makes terminal EOF visible. Redis release is deferred in goroutine. Child submission could momentarily wait while outer goroutine finishes its defers, but should not permanently deadlock. A meaningful regression test uses generated concurrency 1 and a Tool that starts child Reply Agent, in both Generate and Stream paths; assert bounded completion and no tools on child request. No such new test was executed here.
- **Do not pass the parent Tool context unfiltered**: `conversation_publication_policy.go:43` enables publication policy by context policy type, independent of Agent ID. `eino_model_runtime.go:944` rejects final result if that policy remains enabled and fresh child trace has no authoritative reply. Its request policy also forces tools before publication (:18-31). Merely using child Definitions=nil does not clear inherited physical policy. Parent Kev/admission/refresh and diagnostic/run identity contexts also deserve explicit isolation.
- RunADKStructuredTask does replace formal definition and ADK invoker/trace, but reads inherited runtimeContextRefreshPlan (:600) and prior prompt diagnostics. `formal_prompt_projection.go:43-62` overwrites context_projection only, preserving other inherited diagnostics. A child-specific context is necessary while keeping cancellation and approved execution guard semantics.
- Outer ADK request creates `context.WithTimeout(runCtx, assignment.Timeout)` in `provider.go:345`; child still inherits remaining parent deadline unless isolation deliberately controls it. Freezing the child timeout does not extend inherited deadline.
