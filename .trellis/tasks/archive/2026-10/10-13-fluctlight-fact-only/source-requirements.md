# 摇光：Fact-only 双模型私聊接入与可选视觉理解能力

> 交给本地 Codex 的实施任务。实施目标是交付可独立构建、部署、回滚的功能分支，不是只写分析报告。
>
> 日期：2026-10-13。依据：用户在本次对话中的测试反馈、`test_reply_10rounds_v4.py` 的实验设计。本文没有假定已读取当前业务仓库；实际文件、类名、配置项、服务名和发布入口必须先从仓库确认。

## 0. 已确认的方向与本轮边界

用户已经确认：LM Studio 中的 Cydonia 人格表现与目标推进符合预期，不再重复建设或验证 `direct/guided/fact-only` 三分支实验平台。下一步是在真实摇光里接入 **fact-only**，争取尽量保留其单独聊天时的表现，同时使用 Qwen 的工具执行和事实处理能力。所谓达到八九成是用户的体验期待，不是已经定义或测出的性能指标。

本轮必须完成三个主交付：

1. **Fact-only 私聊链路**：Qwen 保持认知 Agent 与原生 Tool Loop；调用 `conversation.reply` 时，在工具内部调用 Cydonia 生成人物回复，再通过现有发送链路提交真实消息，结果回填给 Qwen。
2. **分支发布与回滚**：从 `master` 创建独立功能分支，GitHub Actions 构建对应镜像标签；不把业务改动合并到 `master`，保留稳定版构建与镜像回滚路径。
3. **可选视觉理解开关**：参考项目现有 kev 的配置及启停方式，增加独立视觉理解能力配置。没有配置或关闭时，跳过依赖看图的步骤，不得顺带关闭生图或视频生成。

同时处理接入直接带来的媒体意图、事实/状态边界、可观测性和测试，避免将实验中的已知问题原样带入真实私聊。

### 不做的事情

- 不训练 LoRA，不建设语料生成/AI Judge 平台，不重新证明纯 Cydonia 是否好用。
- 不替换 Eino/ADK，不另写一套 Agent Loop，不重新实现 Goal、Memory、Persona、物品、日程系统。
- 不把所有 Agent 都改成双模型；首轮只覆盖普通私聊，以及已有主动行为最终走同一私聊回复入口的部分。群聊、朋友圈等其它发布渠道维持原行为。
- 不改变既有权限、人格切换权、睡眠/日程触发条件、事务、幂等、Outbox、持久化和任务调度边界。
- 不新增表情包功能，不重建生图/视频流水线，不自动下载或常驻加载第三个视觉模型。
- 不把脚本的“每次都必须回复”“第 N/10 轮”“10 轮必须完成”写成生产全局规则。真实 Goal 的时限和完成条件来自现有 Goal 数据；测试时可以单独注入期限。
- 不采用“Qwen 先写正文，Cydonia 润色”的实现，也不在 Cydonia 生成后让 Qwen 常规重写为客服语气。

## 1. 总体链路与权责

### 1.1 普通文本私聊

```text
现有用户消息入口 / 已获准的主动私聊入口
  → 原有 Qwen Cognition Agent（Eino/ADK）
  → 按需执行真实查询/状态工具并消费结果
  → 原生 conversation.reply ToolCall
  → ReplyContextBuilder 从结构化权威来源装配上下文
  → Cydonia Reply Provider 自主决定社交策略与回复
  → 有限事实/能力边界检查
  → 现有消息提交/Outbox/发送链路
  → 真实 Tool Result 回填 Qwen
  → Qwen 完成原有认知合同
```

每次外部消息启动一次完整处理。一次处理内部允许多次工具调用；调用次数与聊天轮数不等价。Qwen 的最终普通文本、最终 schema、`response_plan` 均不直接作为私聊消息发送。

Eino 的 Agent-as-tool 机制支持把独立子任务结果返回父 Agent，但此处优先复用项目已有 Tool、模型适配器与 Agent/Task 封装；不为采用某个示例而升级框架或复制编排层。[R1]

### 1.2 权责表

| 事项 | 负责方 | 禁止事项 |
|---|---|---|
| 工具发现、权限、执行、结果消费 | Qwen + 现有 Tool 系统 | Cydonia 伪造工具调用或执行成功 |
| 事实来源与当前有效状态 | 现有数据库/工具结果/证据解析器 | 把 Qwen 自由总结当权威状态 |
| 当前人格、Goal、Actor 关系 | 现有系统，装配器直接读取 | Qwen 每轮重写人格、删去目标、重定义关系 |
| 如何接话、主动表达、等待、推进目标 | Cydonia | Qwen 通过 direction/tone/建议暗中规定 |
| 真实操作能否执行 | 既有能力和权限规则 | 用“用户比较冷淡”代替真实权限判断 |
| Goal 状态更新 | 现有 Goal 流程，依据真实事件 | 回复已生成/已发送就认定对方接受或目标完成 |
| 发送及去重 | 现有统一提交/发送层 | Qwen 与 Cydonia 两边各发送一次 |

**硬边界和社交判断必须区分**：用户明确说“不要再提这件事”属于需要尊重的真实输入；“用户简短回复，所以暂时不要推进”是模型社交判断，不得被 Qwen 包装为事实约束传给 Cydonia。

## FO-01：独立测试镜像与 master 回滚路径

### 1. 标签和渠道

沿用原有 registry、镜像仓库名、Dockerfile、构建架构和认证方式。不要迁移镜像仓库。

约定实验镜像至少具有：

```text
fact-only-latest                         # 功能分支的可变更新入口
fact-only-<commitSHA>-<runId>-<attempt>   # 不复用的构建标识
```

具体长度按现有规范调整，但必须能唯一定位构建，记录每个镜像的 digest。`master` 继续保留其原稳定标签，例如原先已有的 `latest`。**功能分支默认不得覆盖稳定 `latest`。**

如果实际部署包含 core、worker、bff、web 等多个镜像，按仓库实际发布集合提供一致的发布清单，不得只让后端更新而遗漏本轮修改过的前端/worker。清单记录各服务的源 SHA、tag、digest；部分镜像构建失败时，不发布“完整版本就绪”。更新分支可变标签前，应确认本次所需构建全部成功；部署端优先从同一清单选择 digest，避免把多镜像标签更新误当成原子操作。

GitHub 官方发布流程支持沿用登录、metadata 与 build/push action 生成并发布标签；以当前仓库版本为准，不随意换 action 版本。[R2]

### 2. 工作流

- 功能分支 push 能触发相应构建；路径过滤包含本轮所有实际改动及 workflow/部署文件。
- 保留 `master` 原有构建能力，核对其手动重建或重跑入口；文档给出仓库中真实可用的操作。
- 手动构建若允许选择 source ref，限制在明确允许的分支；实际 checkout 的 SHA 决定镜像来源，不能选了功能分支却构建 `master`。
- PR 验证不使用发布凭证推送可部署标签；fork PR 不获得写权限。不以 `pull_request_target` 执行未经信任的分支代码并发布。
- 权限沿用最小范围；GHCR 才按需要授予 package 写权限，不假设所有 registry 都使用相同认证。
- 构建记录和镜像 labels 写入 source revision、ref、run URL；禁止写入 API Key、模型完整请求或私聊内容。
- 同一分支的并发发布要防止较旧构建覆盖较新别名；只保留 `concurrency` 配置还需检查发布时的分支 head/版本顺序。
- 功能分支第一次构建优先依赖 push。不要假定“仅存在于新分支的 workflow”马上就会在 GitHub UI 出现手动运行按钮；核对默认分支注册条件与当前仓库行为。[R3]

不得为了方便显示按钮而擅自把功能业务合入 `master`。若稳定流水线确实缺少所需重建入口，单独列出最小 CI 引导改动及原因；未获得修改 `master` 的授权前保持隔离，并保留已有稳定 digest 的即时回退方式。

### 3. 部署与回滚交付

按实际 Compose/部署方式生成可执行命令或现有脚本的最小修改，必须覆盖：

```text
切测试：选择 fact-only-latest 或本次不可变 tag → pull → 重建受影响服务 → 核对实际 digest/健康检查
日常测试更新：继续拉同一测试渠道的最新镜像
回稳定：选择 master 对应稳定 tag/digest → pull → 重建 → 恢复兼容配置 → 核对健康与私聊
```

**明确提醒：部署如果仍指向 `fact-only-latest`，只重新构建 `master` 不会使它自动回滚。** 回滚脚本/步骤必须切回稳定镜像引用，不能只写“重建 master 后拉最新”。

保留用户“重建 master 再更新镜像”的使用方式，同时提供不依赖重新构建的已知稳定 digest 回退；重新构建不能代替已知稳定产物。

本轮数据/配置变更优先向后兼容，不删除旧字段、改变旧枚举含义或做破坏性迁移。旧版本对未知配置严格校验时，回滚必须恢复旧配置备份。新增待处理任务需有兼容/隔离或排空策略，不能让回滚后的旧 worker 错误消费新协议任务。存在长生命周期工作流时沿用项目已有的版本化方式，不能破坏在途任务重放。

### 验收

提供分支构建成功证据、镜像引用和发布清单；验证测试构建没有覆盖稳定标签；交付真实可执行的测试更新与稳定回滚步骤。没有权限执行远端构建/部署时，分别标记未执行，不将本地 YAML 校验当作构建或回滚成功。

## FO-02：模型角色配置与开关

### 1. 最小新增配置

复用现有模型管理及 kev 配置形态，以下只是语义名称，落点必须服从项目规范，不另建重复配置中心：

| 回复模型引用 | 独立绑定 Cydonia/LM Studio 的现有模型配置 |
| 回复采样参数 | 温度、top_p、输出上限等独立于 Qwen，优先保留用户测试有效的值 |
| 上下文预算/超时/并发 | 可配置，不写死测试脚本参数 |

回复模型不可用不得把所有后台 Agent 判为不可用。启用 `fact_only` 但回复配置缺失，应明确显示配置错误并按指定策略处理，不暗中恢复成纯 Qwen 后仍标记为 fact-only。

LM Studio 的 Chat Completions 支持通过请求传入聊天历史与推理参数；复用项目现有兼容适配器。不要把网页聊天模板再次手工包到 `messages` 里。[R4]

### 2. 配置界面

在现有模型/能力设置页增加“私聊回复模型”和“视觉理解能力”区域，风格及保存方式参考 kev。至少显示：是否启用、绑定模型、配置是否完整、最近调用状态、最近失败原因。密钥沿用脱敏机制，不回传明文。

视觉区域注明“用于看图、视觉身份/设定卡分析与校验，不控制图片或视频生成”。提供显式测试入口，未启用时不自动发测试图、不自动加载视觉模型。

### 验收

## FO-03：Fact-only 上下文装配，不让 Qwen 代写人格和方向

### 1. 从结构化来源构建 ReplyContext

不要复制测试脚本用正则从整段 Prompt 删除“行动规则”的实现。生产中必须复用现有 Slot/上下文组件，从字段来源装配一份 **独立、完整但有预算的回复上下文**。

| 信息 | 来源与处理 |
|---|---|
| 当前激活人格、Working Persona、聊天偏好 | 当前有效人格配置；不经 Qwen 临时压缩改写，不硬编码姓名/性格 |
| 活动 Goal、完成条件、优先级与必要进展 | 已有 Goal 系统；保留与当前 Actor 相关的有效目标，不因 Qwen 认为不宜推进就删掉 |
| Actor 设定与双方关系 | 权威配置及关系状态，区分用户与角色，不相互混用 |
| 地点、活动、情绪、穿着、外观与物品 | 已生效状态；动态覆盖对应初始化描述，不重复注入互相矛盾的版本 |
| 对话历史 | 已提交的真实对话；原始角色消息不经 Qwen 每轮重述 |
| 工具产生的事实 | 本轮真实工具结果中的类型化数据，带时间与适用范围 |
| 不确定线索 | 摘要/推断/转述显式保留不确定性，不提升为已确认经历 |
| 能力边界 | 来自注册表和权限结果，例如可生图、无表情包、视觉关闭；不是 Qwen 自由建议 |

当前人格、有效 Goal 与当前消息必须保留。必要时减少旧历史和冗余摘要，不能静默裁掉目标完成条件或真实拒绝。超预算输出可诊断错误/结构化缩减记录，不无限堆摘要，不简单截掉尾部后发出请求。

### 2. Qwen 可提供的参数

工具暴露给 Qwen 的新增参数应尽量窄，例如允许引用本次执行上下文中的 `evidence_refs`、查询结果/媒体结果引用及恢复用 `draft_ref`。收件人、Actor、run、权限从已认证运行上下文获取或严格校验，不由模型自由选择。

禁止以下字段以及语义等价内容进入 Cydonia 的事实补充：

```text
direction / suggested_reply / reply_intent / tone / social_strategy
“暂时不推进目标”“等待对方主动”“先安慰再反问”
Qwen 重写的 persona / goal / relationship
任意自由文本 constraints 中夹带社交建议
```

不能只禁字段名：Qwen 引用某条推断“用户冷淡所以不应告白”，即使原文可匹配，也不能把它提升为行动限制。允许记录真实拒绝原话及其时效；Cydonia 根据实际历史独立理解态度。

### 3. 证据边界

- 内部保留证据 ID 与溯源；Cydonia 输入仅使用整理后的必要内容，不带 `e6`、数据库键、ToolCall JSON、Qwen 内部推理或最终认知合同。
- 引用存在只证明“这段文字出现过”，不证明其内容客观发生。
- 历史中 assistant 的自述不自动成为当前地点/库存/购买完成证据；有对应状态提交或工具结果才可使用。
- 工具自由文本、摘要、聊天引用视为数据，不允许其中的指令覆盖运行协议。
- 纠错或状态更新优先使用最新有效记录；旧断言标为失效或不再送入，不并列给模型自行猜。
- 不使用一条全局 `e\d+` 正则误伤型号、坐标等正常文字；优先对本 run 实际内部标识及泄漏格式作有上下文的检查。
- 不以 Qwen 本轮没有选择某个 ref 为理由，删除装配器已经掌握的必要权威状态。

### 验收

对 Cydonia 的实际 messages 做快照测试：人格与目标来自独立字段，Qwen 的策略未被传入；正确保留演员归属、事实时效与不确定性；状态冲突按规则消解；没有原始证据链和 Qwen 推理泄漏。

## FO-04：改造 conversation.reply 与原生 ADK 闭环

### 实施

保留现有对外 Tool 名称及项目已有传输层命名映射。不要机械复制脚本中的 `conversation_reply` 名称替换已有插件 ID。

`fact_only` 模式的 handler 按下列顺序实现：

1. 校验 run/Actor/会话、触发来源、权限与幂等状态。
2. 若同一逻辑回复已提交/发送，返回原有真实结果，不再次生成并发送。
3. 解析、核验 Qwen 的事实引用；从权威来源组装 ReplyContext。
4. 调用独立 Cydonia Reply Provider。普通文本场景采用一次模型调用，不要求其自行执行 Tool Loop。
5. 处理需要真实工具的媒体意图，或进行有限输出检查。
6. 走现有消息提交/Outbox/发送链路，保存实际最终正文与结果。
7. 将真实结果作为原生 Tool result 返回当前 Qwen Agent，由其完成本轮认知合同。

复用现有 Agent/Task/模型调用基础设施，Tool 必须可脱离 Agent 在合法执行上下文中独立测试。不要在 handler 中重启一套递归 Qwen Agent 或写替代 ADK 的 while-loop。

### 发送状态与重试

使用项目已有的状态枚举，内部映射至少能区分：草稿已生成、等待真实工具、已提交待发送、已送达、失败、被权限拒绝。没有送达确认时不得报告 `delivered=true`。测试模式 `generated_not_sent` 不能原封不动当成生产成功语义。

Qwen 消费 Tool result 时可以看到最终实际消息及必要状态，用于准确记忆和 Goal 事件判断；但这些内容不能二次发送。对话历史只写已按系统规则提交的用户可见消息，不写 Qwen 草稿、失败候选和内部 JSON。

幂等键基于现有逻辑回复/入站消息/会话约定，不仅依赖每次会变的 ToolCall ID。发送成功但最终认知失败、网络响应丢失或任务重试时，不得重复发送。外部渠道没有幂等能力且送达结果未知时，保留 delivery_unknown 并按现有回执/查询机制核对，不能盲目重发，也不能仅凭本地去重宣称端到端 exactly-once。延迟到达的 Cydonia 结果在 run 取消/过期后不得突然发送。

### 不照搬脚本的强制策略

正常用户私聊在既有规则允许回应时，不允许 Qwen 仅输出最终认知而绕过真实回复工具。缺少回复 ToolCall 应按现有有限补救机制处理并记录。

但不把 `tool_choice=required` 永久用于所有认知步骤：真实系统还需要其它工具，最终认知步骤也必须能够结束。用户明确要求不回复、权限禁止、主动唤醒原本允许静默等情况仍保持既有语义。不得因为 Qwen 自己觉得用户冷淡，就擅自跳过 Cydonia 的社交判断。

### 验收

真实 ADK 完整消费 Tool result；每次外部消息的正文均可追溯到指定回复模型；去重/取消/失败语义成立；关闭模式后旧路径仍正常。失败不能伪装成 Cydonia 成功回复。

## FO-05：分离运行协议，保留 Cydonia 的人格与目标判断权

### 1. 修改范围

找到真实 Prompt/Slot 组装源、初始化模板、可编辑协议配置及缓存/编译产物的更新路径。修改源头并按既有版本机制失效缓存；不能只在最终大字符串后追加一段相互矛盾的指令，也不能遗漏已初始化角色仍使用的旧协议。

仅调整 fact-only 私聊相关条款，其它 Tool 的自述/推断区分、actor 归属、物品使用、日程执行、最终合同等原规则保留。

主 Agent 私聊段采用以下语义，具体格式适配项目：

```text
私聊回复必须通过真实原生 conversation.reply ToolCall 完成。
fact-only 模式下，你负责补齐必要事实、调用真实工具、处理执行结果；
不代写私聊正文，不指定回复方向、语气、关系推进节奏或等待策略。
工具将直接读取当前有效人格、目标、关系、状态和真实聊天历史，
由回复模型独立进行社交判断并生成正文。
不得因为你主观判断对方冷淡，就删除有效目标或阻止本应进入的回复流程。

事实引用必须可回溯，摘要、引用、推断和愿望不得升级为已发生事件。
如工具返回待执行的媒体/能力请求，按现有权限和能力规则处理真实工具，
消费结果后继续完成同一个回复任务；不得把待执行等同于完成。

必须消费真实回复工具结果后再完成认知合同。
最终 schema、普通 text、response_plan 不负责发送消息，不得复制正文再次发布。
Goal 事件依据实际已发生的互动与结果；送达不等于接受，表达不等于双方确认。
```

这里的“完成认知合同”仍沿用原有 schema：`claims`、证据引用、人格切换/输出偏好、Goal 候选等字段不因为新增 Cydonia 而被删除。内部证据引用留在内部合同，不转交给回复模型照抄。

### 2. Cydonia 的独立回复协议

保持短且按职责分组：人格/目标/关系来自独立上下文，事实来自有效状态及带来源的消息，模型自行决定本轮互动方式。Qwen 不是上级话术规划器。

不得硬编码“年轻女性”“温柔”“克制”“短回复”“每次反问”“不准列点”等全局风格。角色可以严谨、毒舌、冷漠、话多、不配合，具体表现由当前人格与场景决定。用户需要分析或者人格本来喜欢分析时，允许分析。

目标相关协议要表达：目标持续有效时，应自主寻找机会；用户积极配合时可以主动提出具体下一步，不需要等待 Qwen 的社交许可；不因连续闲聊而遗忘目标。真实拒绝、事实不具备或目标已取消时按真实条件处理，不伪造完成。

时间限制仅保留真实 Goal 自带的约束。测试 fixture 有 10 次聊天期限时，原样注入且两侧一致；生产不能默认附加“不必完成”或“第10轮必须完成”。

神态/语气描述保留人物表现空间，按项目现有格式使用中文全角括号。表情、轻微姿态描写不自动等于需要持久化的现实操作；但移动地点、更换服装、购买、外出等改变权威状态的内容，不能仅靠一句括号描写宣告已经发生。

### 3. 事实校验的限制

先做可确定的结构、已知内部标识、能力结果与状态冲突检查。不能承诺正则能识别所有虚构事实。

复用已有语义校验能力时，只允许输出“违反哪条有来源的事实/权限约束”，不输出新的社交建议；不得因回复大胆、含蓄、长、冷淡或没安慰而否决。

需要修复时，把具体矛盾与有效事实交回 Cydonia 至多一次，不让 Qwen重写整段正文。仍有硬性错误则失败或走明确开启的降级模式；降级结果必须标明 provider/mode，不能计为 fact-only 通过。

### 验收

实际发送给 Cydonia 的消息中没有 Qwen 话术计划；不同人格仍可表现出差异；对积极用户不会被中间层统一要求等待；有来源的拒绝和操作限制依旧有效。

## FO-06：媒体意图回交 Qwen，不能把“发图描述”当成已发图

用户已经在测试里观察到 Cydonia 生成“发表情包/发图片”的文字。本轮不应忽略该问题，也不通过直接删除所有动作描写规避。

### 1. 最小输出契约

Reply Provider 在程序侧返回逻辑上的 `ReplyDraft`，至少能区分：

```text
text                  人物正文
media_requests        可选媒体意图，例如 image + 简要画面意图
```

这不是让 Cydonia 学习 Qwen 的工具 schema，也不向它开放真实工具。优先复用已有媒体意图提取/结构化输出机制；普通文本路径保持一次普通回复调用。确需给 Cydonia 增加输出 envelope 时，只保留 text 与可选媒体意图，不增加推理、计划、事实评分等复杂字段，并验证它未明显削弱此前自然对话表现。

不能把模糊的自然语言关键词匹配当成可靠的媒体执行授权。输出解析失败时不直接发布原始 JSON/占位符；有限纠正后返回真实错误。

### 2. 有媒体意图时的闭环

```text
Qwen → conversation.reply
     → Cydonia 生成带媒体意图的草稿
     → 工具保存草稿并返回 needs_action / 尚未发送
Qwen 消费结果 → 调用现有真实生图/媒体能力
     → 获得生成/失败/等待等真实结果
     → conversation.reply(draft_ref, action_result_refs)
     → 核验原草稿、权限、资产和当前状态
     → 必要时让 Cydonia 根据真实结果局部调整
     → 现有消息/媒体发送层提交
     → 最终真实 Tool Result 回填
```

`draft_ref`、动作结果归属、会话权限由服务端核验，不能信任模型传入任意资产引用。恢复同一草稿不能自动再次生图。为一个逻辑回复配置有限的动作回交次数，防止无限往返。

- Cydonia 决定“想发什么”的表达意图，Qwen 负责权限、能力、真实生成与结果处理；Qwen 不以自己的保守社交建议替换媒体意图。
- 生图参数继续走现有媒体提示词/kev/工作流选择机制，使用真实当前人物、衣物、地点状态。Cydonia 的描述不能让不存在的衣物凭空入库，也不能把角色从家里瞬移到户外。
- 图片尚未生成或生成失败，不能先发送“照片发你了”或裸露的媒体占位描写。先暂停依赖该图片成立的正文，或让 Cydonia 根据真实失败生成不虚构成功的文本。
- 图片生成成功不等于发送成功；发送状态仍以现有消息链路为准。
- 生成提示词只证明“请求生成什么”，不证明成图实际内容。视觉理解关闭时，不声称已看图确认完全符合人设。
- 文本与媒体是否分开提交沿用现有消息模型；部分成功时记录组件状态，只重试未成功部分，不整条重发。
- 未安装表情包工具时，不新增该功能，也不把“（发了个表情包）”视为真实资产消息。普通 Unicode 表情与实际表情包附件必须区分，不能一律删除表情字符。
- 无可用生图能力时，返回 capability unavailable，由 Cydonia 自主调整文本；不能谎称已经发图。

正常文本回复不因此每轮多调用一个 Qwen 校验 Agent。需要附加动作才走这条回交路径；不在 `conversation.reply` handler 内递归进入父 Agent。

### 验收

至少覆盖文本、图片成功、图片失败、图片异步完成、附件发送失败后重试、无表情包能力六种情况。所有“已发送/已完成”陈述均有对应结果；草稿和待执行意图不污染聊天历史与事实状态。

## FO-07：视觉理解能力开关与全入口治理

### 1. 能力定义

**视觉理解是“向模型输入图片，识别/分析/比较/校验图中内容”。** 它不是图片生成，也不是视频生成。真正的图片输入需要实际支持视觉输入的模型及相应传输；不能仅依据模型名称或原始家族推断当前裁剪/量化部署还支持看图。[R5]

下列字段语义必须分开，可复用现有名称：

```text
vision_understanding.enabled + model_ref
image_generation.enabled / 原有生成配置
video_generation.enabled / 原有生成配置
```

用户当前常驻 Qwen 已移除视觉能力。不得因它原始家族曾具备视觉能力就路由图片给它；也不得自动把图片交给 Cydonia 猜。

### 2. 状态矩阵

| 开关/配置 | 视觉步骤行为 | 其它功能 |
|---|---|---|
| 关闭，不论有没有保留模型配置 | 不创建/调用视觉执行任务；记录 skipped_disabled | 聊天、生图、视频生成不因此关闭 |
| 开启但未绑定/配置不完整 | 有限明确提示配置不完整；可选视觉步骤 skipped_unconfigured | 主对话/初始化非视觉步骤继续 |
| 开启且配置完整、能力有效 | 依赖视觉的步骤调用指定视觉模型 | 其它功能保持原路由 |
| 开启且配置完整，但服务超时/无视觉支持/返回错误 | 明确 unavailable/failed；按步骤必需性降级或返回错误 | 不伪装 disabled，不无限重试，不退给无视觉 Qwen |

开关的“配置齐全”和模型健康的“当前可调用”分开显示。能力未知时通过管理员显式测试或首次真实请求验证，不靠启动时批量加载所有模型来探测。

### 3. 入口清单必须从代码确认

至少检查以下可能位置，并在交付报告列出实际发现的所有调用点：

| 场景 | 关闭视觉时 |
|---|---|
| 人物设定卡/视觉身份的文本设定 | 继续已有文本逻辑 |
| 设定卡、头像、参考图的视觉分析/评分 | 跳过相应视觉步骤，不输出假评分 |
| 生图 → 看图判断 → 再生成的验证循环 | 不进入视觉校验循环；仍可按已有生成能力产图并保存 |
| 已有已确认的视觉身份/参考图 | 保留，不因关闭视觉删除或失效 |
| 新生成但未视觉校验的参考资产 | 标记未校验；不得自动冒充“视觉校验通过” |
| 用户消息中的图片理解 | 图片接收/存储按原逻辑；理解能力不可用时不编造图片内容 |
| 其它视觉 Tool、后台任务、管理端手动入口 | 入口和执行处都检查能力，不遗漏旁路 |

人物初始化不能因为缺少可选视觉校验无限等待或整体失败；文本人格、日程和聊天仍可完成。若现有业务必须审核后才能激活某张参考图，则保留旧有效资产，新图处于待人工确认/未校验状态，而不是把 skipped 当 approved。

视觉关闭期间生成图片，关闭的只是自动“看图判定”，不是整个媒体流水线。视频若有可选“抽帧视觉校验”，同样只跳过该步骤，不更改视频生成开关。

### 4. 后端/前端/后台统一

- 使用一个能力解析入口统一判断，不能前端禁用按钮但后台 cron/worker 仍不断调用。
- 关闭/未配置时，Agent 不暴露看图工具为可执行能力；明确的外部直调返回可识别的 unavailable/skipped 状态，不能空成功。
- 调整注册表、capability catalog/discover 与后续完成条件，避免流程因为“找不到视觉工具”反复请求安装，或等待永远不会产生的结果。
- 后台队列里已有视觉任务，在执行前按项目配置生效约定处理；关闭后的任务进入明确 skip 状态，不无限重试/自我重排。
- 将 skipped 与 failed、passed 区分；新开视觉后，未来任务恢复，旧跳过任务不自动集中补跑或加载模型。需要重评由用户/既有显式任务触发。
- 跨 core/worker/bff 的配置要一致；热更新或需重启的规则沿用现有配置体系并在页面说明。

### 验收

视觉关闭/未配置时，测试服务收到的视觉请求数为零，初始化和私聊可完成，生图/视频配置不被改写。启用后只调用所配置的视觉 Provider；伪视觉模型和运行失败不会成为“校验通过”。

## FO-08：上下文、内存、超时与稳定性

用户已调整 mlx-serve 内存策略并跑过十轮；本轮不再擅自更换量化版本、扩大上下文或修改服务内存策略。

- Qwen 进入工具阶段后，不得持有 Cydonia 必须再次申请的同一执行锁，避免嵌套死锁。
- 多 worker/多进程时明确并发控制实际覆盖范围；进程内锁不能被报告为跨所有模型服务的全局串行。
- 串行请求不代表卸载常驻权重。该改造不保证两模型或第三个视觉模型一定能同时装入内存；记录实际运行结果，不依据模型文件大小作保证。
- 视觉关闭时禁止为它创建预热/自动加载请求。视觉开启按需调用，是否卸载由现有模型服务策略管理；本轮不自动停掉用户的 Qwen、Cydonia 或 ComfyUI。
- Writer 不继承主 Agent 全量工具定义、推理过程、认知合同和重复大历史；使用 FO-03 的独立预算。
- 对当前人格、目标、重要关系/状态和本轮消息设置保留要求；历史缩减与 token 使用要可观察。不得每轮递归总结造成内容自增。

- 默认不静默 fallback。显式启用旧回复模式降级时，仍用同一发送入口、同一幂等键，并在 trace、消息元数据和测试报告中标出降级。

连续 10–20 次真实聊天能完整走链路；每轮分别有输入 token、输出 token、时延和错误记录。没有死锁、无界重试和重复发送；不能以“理论模型大小之和够用”替代实测。

## FO-09：诊断、可追踪请求与隐私保护

用户曾经无法判断“Cydonia 到底看到了什么，是否只是润色 Qwen”。本轮必须能从现有诊断中心看清这一点，但不新建独立监控产品。

一个 run 至少关联：

```text
run_id / conversation_id / actor_id / inbound_message_id
reply_mode / config_version / prompt_version
qwen_model_ref / reply_model_ref / optional_vision_model_ref
Qwen 原始 ToolCall 参数及校验结果
ReplyContext 的来源与实际发送给 Cydonia 的 messages
Cydonia 原始回复、解析后的草稿、实际发布内容
媒体意图、工具执行结果、草稿恢复与发送状态
Qwen 收到的 Tool result、最终认知状态
失败/跳过/降级原因，各阶段耗时与 token 使用
source_commit / build_tag / image_digest（按服务可获得范围）
```

调试模式允许授权管理员查看/导出实际请求与参数；普通日志默认仅存摘要、长度、hash、模型与状态。密钥、授权头不得记录。完整私聊、人格和证据内容按现有权限、保留周期及脱敏规范处理，不上传进 GitHub Actions 公开 artifacts。

同一对话中“实际发出的话”与“内部认知/草稿”在 UI 中明确分开；错误按时间倒序，不让旧错误长期盖住新问题。

诊断界面另外展示视觉能力：disabled/unconfigured/ready/unavailable，以及本次流程哪些视觉步骤被跳过。禁用造成的预期 skip 不刷成连续严重故障。

### 验收

随机选择一轮，可追溯 Cydonia 的真实输入、Qwen 是否越权指导、实际消息及发送结果；无需读海量普通日志才能判断回复来源。查看权限和脱敏测试通过。

## FO-10：测试与验收矩阵

### 1. 自动化测试必须执行真实代码路径

单测可以 mock 模型返回，但集成测试必须经现有 Tool registry/handler、ADK 结果回填与测试发送出口。不能只验证一个 DTO 或手工调用 Provider 后宣称 Agent Loop 已通过。

| 编号 | 用例 | 必须断言 |
|---|---|---|
| T01 | 旧配置/legacy | 不调用 Cydonia，旧回复功能不变 |
| T02 | fact-only 普通私聊 | Qwen → 原生 reply Tool → Cydonia → 发送入口 → Tool result → Qwen 最终合同 |
| T03 | Tool 独立运行 | 合法上下文可运行；缺少权限/上下文返回真实错误，无隐藏 Agent 依赖 |
| T04 | Qwen 夹带回复方向 | direction/tone/“暂不推进”等不得进入 Writer；真实拒绝原话保留 |
| T05 | 人格/Goal 完整性 | 不经 Qwen 重写、不因其保守判断漏掉有效目标，不默认固定女性/高冷模板 |
| T06 | e6 与错误摘要 | 未证实线索不变事实，内部标识不泄漏；正常型号/代码不被无差别删除 |
| T07 | 状态与物品 | 当前地点/着装不被一句草稿改变；无库存物品不能被宣称已拥有/正在使用 |
| T08 | 图片成功/失败/异步 | 意图回交真实 Tool；完成后续接；失败不发占位成功语；不重复生图 |
| T09 | 表情包不可用 | 不伪造附件；合法文字表情不被全部误删 |
| T10 | 发送后认知失败/重试/取消 | 消息最多按既有幂等语义提交一次；迟到生成不再发 |
| T11 | 模型不可用/截断/OOM | 分类、有限重试、无静默成功；降级可辨认 |
| T12 | 视觉关闭/未配置 | 视觉 HTTP 请求 0；相关步骤是 skip 而非 passed；无后台重试风暴 |
| T13 | 视觉启用/错误模型 | 图片只发指定有效视觉模型；服务失败不转给无视觉 Qwen 猜 |
| T14 | 生图开启 + 视觉关闭 | 能生成/保存图片，未视觉校验不自动通过；视频生成配置不受影响 |
| T15 | 人格/设定卡初始化 | 可选视觉缺失不阻塞非视觉初始化；旧已确认资产保留 |
| T16 | 普通私聊/WakeUp | 应回复时真实 Tool 路由；原有静默、拒绝、睡眠/权限规则未被“每轮必回”覆盖 |
| T17 | 多轮与配置快照 | 一次用户输入一次完整处理；内部重试不加聊天轮数；run 内 schema 不漂移 |
| T18 | CI 与镜像渠道 | 测试标签隔离、source SHA 正确、发布集合一致、回滚不会仍拉实验 tag |
| T19 | 老版本回退 | 新配置/数据/待执行任务不使稳定版无法启动或错误消费 |
| T20 | 诊断与隐私 | 可查看真实 Writer 输入及发送内容；普通日志/CI 不含密钥和完整私聊 |

### 2. 真实模型验证，不再重跑 Direct 基线

使用用户已验证过的固定人格/目标与一份真实运行上下文，执行 fact-only 实际链路。可复用已有测试脚本作为测试输入来源，但不能依赖它替代业务接口。优先做：

- 一条用户逐渐配合的 10 次聊天，检查角色是否主动利用后续机会。
- 一条人格明显不同的 10 次聊天，检查是否仍是同一种语气模板。
- 一条含事实纠错、图片意图或当前状态约束的 10 次聊天，检查能力边界与状态连续性。

上述每轮按实际已发出的回复继续，保留原始输出和参数；没有重跑 direct 的要求。固定条件允许重复少量运行观察波动，不要求新增模型竞技平台或 AI 裁判系统。

目标效果记录“首次出现明确推进”“提出具体下一步”“用户配合后有无继续推进”“实际完成事件及依据”，同时保留用户主观评价。八九成体验不转化为虚构的自动分数，也不通过放宽真实完成条件制造成功。

用户提供的 Goal 明确限定 10 轮时，测试保留该约束；未明确时不由脚本或生产协议擅自增删期限。目标推进改善不代表允许忽略明确拒绝或凭空完成真实操作。

### 3. 发布验收

检查全部受影响服务的构建、镜像来源、配置与健康检查。回滚演练在可用测试环境进行，不能未经授权对生产替换镜像。远端 CI、真实模型或部署环境不可访问时，分别输出“未执行”及具体命令，不能把 mock 测试等同真实通过。

## FO-11：提交、文档与结束条件

按可检查的功能提交，而不是末尾混成一个无法回退的大提交。建议次序：

```text
分支/接入盘点与构建隔离
→ 配置与上下文契约
→ fact-only 私聊闭环及协议
→ 媒体回交与状态边界
→ 视觉能力可选化与设置页
→ 回归、诊断、部署/回滚说明
```

同一功能分支完成全部任务后停止，等待用户真实测试，不自动合并 master。

至少交付以下资料，放在仓库已有 docs/报告目录；没有规范时再选择合适路径：

| 交付物 | 内容 |
|---|---|
| 实施报告 | 实际改动文件、任务状态、核心调用链、配置变更、已知风险 |
| 配置示例 | 旧行为、fact-only + 视觉关闭、fact-only + 独立视觉三种可用配置 |
| 视觉调用点清单 | 每个入口的调用位置、开关行为、关闭时如何继续/结束 |
| 部署与回滚手册 | 分支、镜像 tag/digest、真实构建命令、测试渠道更新、master 回退、配置恢复 |
| 测试报告 | 逐项命令与结果，明确 mock/集成/真实模型/CI/部署分别是否执行 |
| 一轮脱敏 trace 示例 | Qwen Tool 参数 → Writer messages → Cydonia 输出 → 发送结果 → Qwen 回读 |
| 发布清单 | 每个受影响服务的 source SHA、镜像引用及 digest |

最终回复用户必须区分：已实现、已执行验证、未执行验证、需要用户操作。不得把“新增了测试文件”“mock 全过”表述为“真实摇光可用”。

### 最终禁止清单

- 不合并 master、不覆盖稳定 latest、不自动切生产。
- 不通过 guided 方案偷偷恢复 Qwen 社交建议。
- 不把“不够温柔/不够保守”当作事实校验错误。
- 不把 generated/queued 当 delivered，不把 delivered 当 accepted/goal completed。
- 不把视觉 disabled/skipped 当验证通过，不让它关闭生图或视频生成。
- 不复制实验脚本的全文正则删 Prompt、固定10轮规则、单工具假设和模拟发送语义到生产。
- 不以当前模型长时间响应为由无限重试、同时加载多个大模型或私自修改用户模型服务设置。

**完成标准：功能分支上具备可部署、可回滚、可关闭的 fact-only 私聊能力；Cydonia 不受 Qwen 的社交话术限制，但不能越过真实工具、事实和状态边界；视觉理解可选，缺失时相关步骤明确跳过，其它生成与聊天能力仍可运行。**
