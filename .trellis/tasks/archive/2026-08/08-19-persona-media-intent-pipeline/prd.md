# 人格媒体意图、模板化与结果验收管线

## Goal

当 AI 人格在对话或活动中判断需要交付图片或视频时，它必须在调用图片/视频能力的当下，传入自己已经确定的结构化媒体概念、当前事件和临时外观变化。下游只将这些已确定事实模板化为 provider prompt、执行生成，并验证生成结果是否忠实符合人格原本的媒体意图。

## Confirmed Facts

- 当前媒体链路为：聊天人格产生 `<media-intent>` 标记 → 创建 durable media job → worker 调用 LLM 生成人格媒体概念 → worker 再调用 LLM 生成固定八段提示词模板 → provider 执行。
- `generatePersonaMediaConcept()` 当前以人格身份、当前生活状态、关系、媒体请求、临时外观变化和事件构造概念；`fillMediaPromptTemplate()` 再以权威事实 + 概念输出 provider prompt 模板。
- 当前一次媒体作业通常需要两次配置 LLM 调用，且人格做出媒体交付承诺时持久化的只是简化的 `kind/request/count`，没有持久化当时已决定的结构化媒体概念。
- 过去将概念生成留在 worker 内，会使作业执行或重试时重新解释人物、地点、动作、入镜关系和镜头语义，不能保证人格承诺与最终生成的媒体一致。
- 用户已确认：所有图片和视频都必须经过硬一致性检查；仅因明确违背人格概念、明显生成失败或安全问题而拦截，不以主观审美作为拦截依据。

## Requirements

- **A：人格媒体概念。** AI 人格识别需要调用图片/视频能力时，必须在该 function call 的参数中直接提供经过校验的结构化人格媒体概念：要拍的图片/视频、地点/场景、人物与非人对象、人格外观、动作、情绪、入镜关系和自拍/他拍/POV 等镜头关系。
- 同一 function call 还必须传入当前事件与临时外观变化；不得只传自由文本 `request`，再由 function、worker 或重试阶段猜测、补全或重新生成画面概念。
- 新 durable media job 在创建时必须持久化 function call 的人格概念、当前事件、临时外观变化及其他权威事实快照。重试复用同一快照，不得重新决定画面语义。
- **B：最终提示词模板。** 下游模板阶段仅使用已传入/持久化的人格概念和权威事实输出固定八段 provider prompt；它不能重新决定或推翻人物、场景、动作、外观、拍摄关系或入镜关系。
- 服务端只负责调用授权、schema/长度校验、持久化、模板段落的固定顺序渲染、重试与 provider 调用；不得通过关键词、正则、人数计算、默认镜头、负面词拼接或其他启发式规则推断视觉语义。
- **C：人格一致性与结果验收。** 每一项图片和视频生成后均使用已冻结的人格概念、当前事件和临时外观变化进行受约束的视觉验收。视频通过有界的关键帧集合检查，不要求逐帧视觉理解。
- C 阶段只评估人格/外观连续性、叙事事实、主体与镜头关系、明显生成失败及安全问题，不进行主观审美评分。验收结论必须为结构化 `pass`、`retry` 或 `reject`，并附可诊断的事实违例。
- C 阶段复用当前配置的 AI 人格模型及其视觉输入能力，不新增独立的媒体验收模型配置。若该验收调用在实际运行时不可用、不支持视觉输入、超时或无法给出可校验结论，则记录安全的降级诊断并跳过 C 阶段，直接交付该次已成功生成的媒体；不得将验收基础设施故障伪装成内容不合格。
- C 阶段请求重试时，A 阶段概念和事实快照仍被冻结；B 阶段只能依据明确诊断加强表达后重新模板化。重试不得把原概念改写成新的故事、人物、地点、动作或镜头关系。
- C 阶段判定 `retry` 时，每项图片或视频最多自动重新生成 1 次。两次候选媒体均明确不合格时，拦截错误媒体、保留原聊天文本或动态，并显示安全的失败状态/诊断；不能为了交付媒体而放行明显错误结果或生成服务端猜测的 fallback prompt。
- 聊天触发、动态触发和调试媒体触发应维持同一事实/概念/验收契约与安全校验。旧作业必须安全兼容，或在缺少必要快照时明确失败。
- 此版本启用前已创建、但 payload 缺少已冻结 `personaMediaConcept` 的旧 media job，不得使用旧 worker 的概念 LLM 补造语义，也不得调用 provider；应将其媒体目标明确标记为失败，保留聊天或动态正文，并提供“该请求创建于新版媒体意图契约之前，请重新生成”的安全说明。
- 调试诊断必须能区分 function call 的事实与概念、B 阶段模板、最终 provider prompt、C 阶段验收和失败/重试；不得把 API key 或敏感数据暴露到客户端。

## Acceptance Criteria

- [ ] 人格发起图片/视频 function call 时，参数包含经过校验的结构化人格媒体概念、当前事件和临时外观变化，而非只有自由文本 request。
- [ ] A 阶段概念能表达所拍内容、地点/场景、明确的人类主体、非人对象、人格外观、动作、情绪与镜头/入镜关系；服务端不从自然语言重新推断这些视觉语义。
- [ ] 新媒体作业在创建时持久化 A 阶段概念与事实快照；worker 及重试均复用它们，且不再调用概念 LLM 重新解释画面。
- [ ] B 阶段只接收冻结的事实和概念，输出固定八段模板；provider 收到由该模板渲染的最终 prompt，且 B 阶段不能改变 A 阶段的画面事实。
- [ ] 每个图片生成结果均经过 C 阶段硬一致性检查；每个视频结果均经过有界关键帧检查。明确违背冻结概念、明显生成失败或安全问题的结果不会交付给用户。
- [ ] C 阶段复用当前 AI 人格模型的视觉能力；当视觉验收实际不可用、超时、不支持输入或无法判定时，媒体可安全降级为跳过验收并交付，同时保留不含敏感数据的诊断。
- [ ] C 阶段的 `retry` 具有结构化违例与有限重试次数；重试保持 A 阶段概念不变，仅允许 B 阶段据诊断调整表达。重试耗尽后媒体被安全拦截而聊天文本/动态保留。
- [ ] 每项图片或视频至多发生 1 次由 C 阶段触发的自动重新生成；第二个候选结果仍被 C 阶段判为不合格时，绝不交付该媒体。
- [ ] 三类媒体触发入口（聊天、活动、调试）遵循同一事实、概念、模板和验收契约；旧作业仍能安全处理或明确失败。
- [ ] 缺少冻结 A 阶段概念的旧 media job 在不调用概念 LLM 或 provider 的情况下失败；对应聊天/动态正文保留并显示可安全理解的重新生成提示。
- [ ] 媒体 function call、A/B/C 阶段边界、provider 提交、拦截、失败与重试均有回归测试，且测试覆盖人物/物体误判、镜头关系错误、临时外观遗漏和不合格结果拦截。

## Out of Scope

- 用主观审美、艺术风格偏好或“是否足够漂亮”作为自动拦截条件。
- 无限自动重试、在重试中重新创作 A 阶段人格媒体概念，或用服务端启发式 fallback prompt 替代人格意图。
