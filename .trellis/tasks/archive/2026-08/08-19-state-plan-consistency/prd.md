# 人格状态与当天计划一致性

## Goal

确保同一人格的当天计划、当前状态投影、聊天上下文和回答中的时间事实使用同一条时间线，不允许旧默认作息覆盖已存在的当天计划，也不允许模型在缺少事实时间时编造结束时间。

## Requirements

### R1. 当天计划与当前状态必须同源

- 当天计划存在且为 ready/有效时，状态解析不得回退到 legacy student routine 来覆盖该计划。
- 在当天计划的第一个显式块开始前、两个块之间和最后一个块结束后，系统必须返回计划定义的基线状态或人格默认房间状态，而不是默认“上课中”。
- 旧人格必须在读取或计划生成时获得兼容的 v2 生活模型/基线状态，避免仅因 role 是“学生”就自动进入课程状态。
- 已确认：当天计划 ready 后是全天连续状态的唯一权威；legacy routine 只在当天计划尚未生成、失败或不存在时作为保守 fallback。

### R2. 全天状态连续性

- 一天的时间线必须覆盖状态空隙：睡眠、起床前、空闲、回到房间、等待、日程间隙等都是明确状态。
- “睡到十点后打游戏”不能只被表示为从 10:00 开始的一条模糊块；10:00 前的状态必须可解析为睡眠或休息，且具备可信地点/房间。

### R3. 聊天回答中的时间事实

- 聊天上下文必须传递当前状态来源、是否存在可信 `endsAt`、下一条已确认时间线边界和当天计划摘要。
- 当不存在可信结束时间时，模型不得编造“十点半下课”等具体时间；应使用不确定性表述或说明没有精确安排。
- 当存在可信 `endsAt` 时，模型可以引用该时间，但不得改变或延伸该时间。

### R4. 回归与兼容性

- 新增精确回归案例：当天计划首块为 10:00 后的睡醒/游戏状态，在 08:47 读取当前状态不得得到“上课中”；询问结束时间不得回答无事实依据的“10:30”。
- 保持显式用户日程、固定 life-model 槽位、机会事件、睡眠延迟批次和既有聊天 SSE 合同的兼容性。
- 不修改当前工作树中其他任务的未提交文件；修复范围限定于本任务的状态/计划/聊天一致性路径与对应测试、规格。

## Confirmed facts

- 2026 年 8 月 19 日，本地数据库中的人格“苏芷柠”当天计划为 `10:00–13:00` 的“睡到自然醒，宿舍打游戏看番”。
- 在该计划开始前，服务曾把该人格解析并持久化为 `routine: 上课中`；对应 life event 出现在 `2026-08-19T00:00:38Z`、`00:20:38Z`、`00:40:38Z` 等时间点。
- 同一会话随后出现了“上午两节连着上……大概十点半才彻底解放”的助手回复；当天计划没有对应课程或 `10:30` 结束时间。
- 当前 `scheduledState()` 的顺序是：活跃事件 → 已开始的日程 → legacy routine。计划在 10:00 前尚未开始时，大学生默认 routine 的 `08:00–12:00 上课中` 成为状态来源。
- 当前聊天状态层传递当前情况和场景，但没有把经过验证的当前计划结束时间作为事实字段传给模型；模型能据“上课中”自行补全不可信的下课时间。
- 该人格的已持久化 blueprint 仍缺少 v2 life model 字段，因此旧人格没有自动获得稳定的默认房间、全天基线和结构化 fallback。

## Acceptance Criteria

- [x] 当天 ready 计划存在时，计划外时间不再回退到 legacy student routine。
- [x] 计划首块前的状态能够正确解析为睡眠/休息或默认房间基线；地点和房间可投影到普通 UI 与聊天上下文。
- [x] 当前状态、当天计划、state API、媒体上下文和聊天 prompt 在同一时刻返回同一个事实来源。
- [x] 聊天回答只在状态来源带有可信结束时间时才可给出具体结束时间。
- [x] 精确回归场景稳定通过：`08:47` 不会把 `10:00–13:00` 的睡醒/游戏计划人格说成上课，也不会编造 `10:30` 下课。
- [x] 现有全量回归、语法检查和跨层契约检查保持通过。

## Resolved decisions

- 当天计划 ready 后是全天连续状态的唯一权威；服务端必须把计划补齐为覆盖 00:00–24:00 的连续时间线。
- legacy routine 仅在当天计划尚未生成、生成失败或不存在时作为保守 fallback。
- 聊天只能引用状态层提供的可信结束时间；缺少可信时间时必须使用不确定表述，不能依据角色身份编造课程或结束时间。
