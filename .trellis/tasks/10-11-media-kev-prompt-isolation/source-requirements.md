# 摇光媒体提示词：Kev 拍摄方案补充与分支上下文隔离

> 本地 Codex 实施任务 · v1.0 · 2026-10-11
>
> 目标链路：摇光已有的大概描述 → Kev 补充画面／拍摄方案 → 按入镜对象装配上下文 → 现有 LLM 生成规范化提示词 → 现有生图能力。
>
> 这是一轮局部功能改造与缺陷修复，不是重新设计摇光的认知、Agent、Tool 或图像工作流体系。

## 0. 直接执行要求与任务依据

在当前仓库中完成定位、实现、配置、测试及报告。先建立真实入口映射，随后继续实施；不要只交一份新计划，不要在每个步骤后等待额外确认。下文对象名是逻辑职责，优先映射到现有实现，不要求照搬目录或新建同名类。

### 0.1 用户已确认的行为

1. 摇光已经会先决定要生成什么，并产生图片的大概描述。保留此行为，不新增一个替她决定拍什么的 Agent。
2. Kev 只对这份描述进行有限的类型判定、画面／视图补充；不生成长篇提示词，不重新选择生活主题或目标。
3. 后续仍由现有 LLM 生成规范化的中文生图提示词。
4. 当前最需要解决的问题是：无人物图片仍被补入人物属性、身份或自拍规则，导致规范化提示词变成自拍。
5. Kev 已参与部分现有逻辑。复用仓库实际已有的 Client、决策配置、日志、超时和服务端点；不要重新实施前一轮七个决策点。
6. 延续 Kev 直接生效、全局／分项可关闭、异常回退、每次判定留痕的要求。

### 0.2 尚未核实的部分

当前没有针对仓库媒体链路的源码审计结果。以下均为需要核实的可能污染入口，不是已经确认的根因：共享 System Prompt、Working Persona、外观／着装 Slot、历史消息、自拍示例、默认摄影参数、提示词后置追加、固定身份参考图、人物 LoRA、工作流节点默认值。

报告中必须给出真实路径、符号、必要行号或配置键，说明找到的原因；不能仅因用户说“改过后只会自拍”，就宣称某一模块已经被证实存在硬编码。

### 0.3 本轮范围

包含：媒体意图与拍摄方案的边界、Kev 媒体判定、分支上下文装配、规范化提示词、最终请求检查、现有生图参数路由所需的最小修改、诊断、单点测试与集成回归。

不包含：更换主模型、升级 Kev 权重、改动动态加载脚本、重建视觉身份、重新训练 LoRA、新增物品购买流程、重写日程／目标系统、建立全局多模型调度、新建前端项目、全量替换 ComfyUI 工作流、增加自动视觉评审／反复生图闭环。

生成图片不得反向修改角色的地点、服装、外貌、物品持有、关系或目标完成状态。

## 1. 必须成立的设计原则

### 1.1 拍摄者、任务所属 Actor、入镜者是三个概念

媒体任务属于摇光，不代表摇光出现在画面中。

“我拍一张窗外的猫”中的“我”是拍摄者；“拍一张我抱着猫的照片”中的“我”才是入镜者。两者不能共用同一套人物属性注入。

仅因为存在 `actor_self_id`、请求来自 WakeUp，或描述中出现“我”，不能启用 Visual Identity、自身外观或自拍模板。

### 1.2 描述决定内容，Kev 补充表达方式

原始描述和明确要求优先于 Kev 补充，Kev 不能：

- 将猫、咖啡、海面改成人像；为纯风景添加摇光。
- 将明确的他拍改成自拍，或将对镜全身照改成手持近景。
- 为了完成画面而虚构朋友在场、已经购物、已经换装或已经出门。
- 把人物当前有效状态改成初始化设定。

Kev 可以在没有明确指定且不冲突时，补充观察视角、景别、机位等有限画面参数。未提供足够依据的字段允许保持 `unspecified`，不要求每个字段都填满。

### 1.3 先分支，后加载人物上下文

不允许先拼接完整人格、外观、衣柜和自拍规则，再告诉规范化 LLM“这次忽略人物信息”。

正确顺序是先形成入镜范围与拍摄方案，再按白名单读取、投影并装配该分支允许的信息。无人物分支的人物信息应当在请求构造阶段就不存在，而不是以空值、折叠字段、负向提示词或“仅供参考”形式继续附带。

### 1.4 缺陷修复与 Kev 开关分离

本轮包含两件独立工作：

- **始终生效的媒体修复**：取消公共自拍默认值；按入镜对象隔离上下文和身份条件。
- **可关闭的 Kev 增强**：由 Kev 补充媒体分类、拍摄方式和视图参数。

关闭 Kev 时，回到“修复后的原媒体 LLM 路径”，不是重新启用已经确认的自拍污染。前一轮“关闭回原流程”在本媒体路径的基线相应更新；其他既有决策点的关闭语义不变。

不能把清除无人物分支的人物属性放进 `if kevEnabled` 内。

特别检查“第一人称摄影骨架”“高机位约 45°”“手机不入镜”是否被所有任务共用。它们不能成为全局默认规则。

保留基线用例与现有定制配置。模板升级应有版本、差异和可恢复备份，不无条件覆盖用户自定义模板；用户模板与新分支契约冲突时，在诊断／设置中明确报出，而不是静默带入不兼容字段。

## 3. 单次媒体任务的目标链路

```text
已有媒体 Tool／任务接收摇光形成的大概描述
    ↓
保留原意，整理已有显式要求与必要指代绑定
    ↓
媒体主体／入镜范围判定（Kev 开启时；关闭或失败则走原 LLM 回退）
    ↓
按适用范围补充拍摄方式、景别和机位
    ↓
校验并形成 MediaCapturePlan
    ↓
按分支白名单生成 MediaPromptContext
    ↓
现有规范化 LLM 生成中文提示词（不继承角色聊天上下文）
    ↓
结果契约校验及最终生图参数检查
    ↓
现有图像执行器 → 真实图片结果 → 原有返回／发布流程
```

没有人物时，不执行自拍／他拍的专属判定，也不读取自身外观和当前穿搭。存在人像但不是摇光时，也不读取摇光身份。

正常路径不得新增“主 LLM 再想一次拍什么”，不得给每个小字段新增独立 Agent。原有规范化过程如果是单次 Task，保留单次 Task；如果已经依赖 Eino 工具循环，复用该循环，不另写运行器。

## 4. 输入和拍摄方案契约

优先扩展现有媒体 DTO，而不是平行维护两套字段。字段名称可以适配代码，但以下语义必须保留。

### 4.1 MediaIntent：已有大概描述的包装

| 字段 | 要求 |
| --- | --- |
| `intent_text` | 原始大概描述，保留原文，不能被 Kev 结果覆盖 |
| `source` | 用户请求、主动行为、独立 Tool 等现有来源 |
| `task_actor_id` | 任务所属 Actor，仅用于权限、来源和状态查询，不代表入镜 |
| `explicit_constraints` | 已存在的明确主体、人数、无人、拍法、构图、排除项；携带来源 |
| `referent_bindings` | 仅解决“你、她、这只猫、那双靴子”等本次必要指代 |
| `scene_facts` | 本次确实需要的环境、时间或地点事实，不带人物画像 |
| `reference_assets` | 本次已提供的参考资产及用途，不自动加入本人身份图 |

显式约束优先复用已有 Tool 参数和已验证的意图解析结果。输入只有自然语言时，不假装已经存在可靠结构化约束；按本轮判定与规范化契约解析，并保留依据。禁止用 `contains("我")`、`contains("人")`、`contains("自拍")` 等单词规则取代语义识别。

不把整段聊天历史、所有目标、反思记录、完整 Working Persona 作为媒体判定输入。指代解析需要补充上下文时，提供最小必要片段，而不是恢复全量历史。

### 4.2 MediaCapturePlan：内部结构化结果

| 字段 | 建议值／语义 |
| --- | --- |
| `primary_subject` | `landscape / animal / object / person / mixed / other / unknown` |
| `human_presence` | `none / partial / present / unknown`；以最终画面为准，不以谁拍摄为准 |
| `self_in_frame` | `yes / no / unknown`；摇光是否实际入镜 |
| `visible_subjects` | 入镜对象的候选 ID、类型、来源及可见范围；不能生成新 Actor ID |
| `capture_method` | `handheld_selfie / mirror_selfie / self_timer / external_photo / unspecified` |
| `viewpoint` | `subject_facing / pov_outward / observer / reflection / unspecified` |
| `framing` | `detail / close_up / half_body / full_body / wide / unspecified` |
| `camera_angle` | `eye_level / high_angle / low_angle / top_down / unspecified` |
| `intent_constraints` | 来自原意的约束，禁止被后续字段覆盖 |
| `render_constraints` | 根据分支生成的人物／身份注入和渲染限制 |
| `field_sources` | 各字段来自 `explicit / kev / original_llm / neutral_default`，及必要来源引用 |
| `plan_version` | 本次契约版本 |

这些字段是内部摄影语义，不要求 ComfyUI 工作流存在同名参数。

### 4.3 必须区分的情况

**主体类型不等于是否有人。** “猫与咖啡”可以是 mixed 但没有人；“猫是主体，远处有一位路人”可以以 animal 为主但有人。不能只用 `primary_subject != person` 跳过人物范围检查。

**有第一人称视角不等于自拍。** “从我的视角看海”是向外看的主观视角，不能默认看见自己的脸。用户沿用“第一人称手持自拍”说法时，要结合原意识别是手持前置、本人面对镜头，还是向外拍摄；不能把两种空间关系同时写进 Prompt。

**全身与镜前是独立维度。** 全身可以是他拍、定时自摄或镜前自拍；镜前自拍也可以只有半身。

**局部人体不等于完整人像。** “手拿咖啡”“低头看自己穿的靴子”属于 partial，只需要可见手部、裤脚、鞋等相关信息，不应注入脸、发型、身高、胸部或完整身体参考。

**人形物品不是摇光。** 人偶、雕塑、印有人物的海报等按原意描述其外观或载体，不能绑定为现实 Actor 或因此加载摇光身份。

**镜中人、剪影、背影、背景路人也可能是入镜人物。** “无人物”限制不能通过换成倒影、影子或局部身体规避。环境本身的倒影不受此限制。

### 4.4 组合校验

- `human_presence=none` 时，`self_in_frame=no`，不得选三个 selfie／self_timer 方法，不得启用人物身份条件。
- `human_presence=unknown` 时，不能默认转成 present，更不能默认 self；后续仍按未知处理。
- `self_in_frame=no` 时，不加载摇光脸部、身体身份或当前着装；其他明确人物使用自己的来源。
- `capture_method=handheld_selfie` 应与原意中的入镜人物及面向镜头关系一致；不能同时是完全向外看的 POV。
- `mirror_selfie` 需要反射关系，不能套用“镜子不存在／手机绝不入镜”的手持自拍默认模板。
- `self_timer` 或 `external_photo` 不应额外补入手持手机前置自拍动作。
- `half_body/full_body` 的使用要与主体相适应。动物全身可以保留；纯物品／风景不套用人体半身模板。
- 明确 `framing=full_body` 时，要保留头顶到脚底的范围要求；不能被自拍近景默认值覆盖。明确要求手持自拍且全身时，保留要求，不能静默改成镜前自拍。
- 明确用户要求与 Kev 结果冲突时，不采用冲突字段并记录原因；不能改写 raw answer 伪装成 Kev 已正确判断。
- 外部机位是一种画面关系，不代表某个未提及的朋友真实在场。不得生成新的摄影师 Actor、日程或事件。

以上校验只约束摄影方案和资料使用，不宣称能保证图像模型百分之百还原构图。

## 5. Kev 媒体判定

### 5.1 复用基础设施，新增媒体命名空间

建议分为三个逻辑决策点：

| 点 | 职责 | 触发条件 |
| --- | --- | --- |
| `media.subject_route` | 主体类别、是否有人、是否本人入镜、必要的入镜对象选择 | 媒体任务进入，相关字段尚未可靠确定 |
| `media.capture_plan` | 手持自拍、对镜自拍、定时自摄、他拍等适用拍法 | 已确认有人入镜且有相应候选 |
| `media.view_plan` | 景别、向外 POV／观察视角、机位等补充 | 对本次主体适用且未被显式约束固定 |

逻辑分层不等于必须调用三次 HTTP。先批量询问主体与入镜范围，再将适用的拍法／视图问题合并为一批，通常最多两个阶段。已明确的字段不重复询问；完整明确的任务允许 Kev 零调用。

不逐个枚举所有摄影细节反复请求，也不递归“判定→让 LLM 改描述→重新判定”。

### 5.2 状态必须保持小且不被人物资料预先污染

第一阶段只包含原始描述、明确约束、必要指代和中性场景信息。即使 task_actor 是摇光，也不要在这一阶段添加她的性别、年龄、脸、身材、衣服、恋爱目标或自拍偏好。

第二阶段可以带第一阶段已接受的有限字段以及可行拍法。尚未确定需要的外观资料仍然不带入。

未知的拍摄设备、镜子或帮拍者不能自动成为已存在的生活事实。缺少设备资料时，优先保留中性机位或 unspecified；本轮不新增物品查询／购买链路来强行补齐摄影参数。

### 5.3 题目示例与版本

沿用当前已验证的 System One 协议与 `choice`。下面是媒体判定的初始问题模板，不代表这些新问题已经通过真实模型测试。[S1]

```json
{
  "state": "intent_text: 我想拍一张窗外雨后的街道，路面映着灯光，不要有人入镜。\nexplicit_constraints: 画面无人。",
  "questions": {
    "human_presence": {
      "type": "choice",
      "instructions": "What human presence belongs in the requested image? Classify the visible image, not the author or photographer.",
      "criteria": {
        "none": "No human, human reflection or human body part is depicted",
        "partial": "Only a human body part, such as a hand or feet, is depicted",
        "present": "One or more people are depicted, including a background person, silhouette or reflection",
        "unknown": "The description does not establish whether a human is depicted"
      }
    },
    "primary_subject": {
      "type": "choice",
      "instructions": "What is the main subject of the requested image?",
      "criteria": {
        "landscape": "A natural scene, street, building or environment",
        "animal": "An animal",
        "object": "An object, food, product or still life",
        "person": "A person or group of people",
        "mixed": "Multiple equally important subject types",
        "other": "A clearly specified subject outside these categories",
        "unknown": "The subject cannot be determined"
      }
    }
  }
}
```

`self_in_frame` 问题明确询问 task_actor 是否可见；其他 Actor 或对象只能从此次输入的有限候选中绑定。对于无人物结果，不继续询问 self 自拍形式。

拍法问题的选项中保留 `unspecified`，描述其语义为“原意没有要求，且没有足够依据做合理选择”，不能用它暗指默认自拍。`unknown` 是无法判断；`other` 是明确但不在常见类型内，两者不能都映射成人像。

问题、选项、状态表示和候选集合变化都要留版本。默认沿用当前 choice 策略，不悄悄新增统一 0.8 门槛；已有 guarded 配置仍可使用。无有效答案时按字段或阶段回退，不把弃权解释为“没有人物”。

### 5.4 只应用合法结果

保留原始响应并校验题目 ID、type、候选值、概率及整体字段兼容性。继承现有响应大小、并发和超时预算；动态加载由现有服务处理，不在每次媒体调用前额外健康探测或预热。

人物关系是后续身份资料的上游依赖；若第一阶段无可靠结果，不能拿第二阶段意外返回的 selfie 值反向证明画面有人。未应用的结果必须记录，不因下游缺字段就套用旧自拍缺省值。

## 6. MediaPromptContext：以白名单装配规范化输入

### 6.1 不继承聊天 Agent 的完整提示词

规范化 LLM 执行的是“视觉提示词编译任务”，不是继续扮演摇光聊天。复用 LLM 调用基础设施，不复用主聊天的人格 System Prompt、历史消息、目标／反思上下文和完整 Slot 集合。

即使只有一条描述，也应通过独立的媒体装配函数生成本次请求。禁止共享可变 Map／messages／workflow 对象后原地删除，以免前一张自拍的数据留到下一张猫或跨 Actor 串用。

通用基础协议只保留该任务所需的语言、输出格式、事实来源、约束优先级。头像、性别、身体比例、着装和自拍空间关系不得成为规范化任务的全局基础协议。

### 6.2 分支资料矩阵

| 分支 | 允许装配 | 不允许自动装配 |
| --- | --- | --- |
| 无人物：风景／动物／物品／混合静物 | 原意、相关对象特征、环境、光影、合法视图和构图；有依据的动物／物品参考 | 摇光姓名画像、脸／身材／发型、当前穿搭、人物 Visual Identity、自拍规则、人物身体 LoRA |
| 人物存在但没有摇光 | 原意中的人物及各自已知特征、人物对应参考、拍法和场景 | 摇光身份或穿搭；把匿名人物补成摇光 |
| 摇光本人完整或主体入镜 | 本人稳定视觉身份 + 当前有效外观 + 此时有效穿着，按 visible scope 投影 | 初始化过期外观、历史穿搭、不存在的物品、整个人格和关系目标 |
| 本人与他人／动物同框 | 按 subject ID 分开装配每个对象的信息 | 用摇光的一套外观覆盖所有人；漏掉同行对象 |
| 仅局部人体 | 原意要求的可见部位与相关衣物／物品；确有必要的局部特征 | 未入镜的脸、完整身体身份图、发型、体型数值、全套穿搭 |
| 入镜范围未知 | 原意、已确认约束、中性画面信息；必要的原 LLM 解析 | 自动加载本人资料，自动设为 self_capture |

`human_presence=none` 不意味着拒绝所有参考图；场景、动物、商品等与任务相符的参考仍可使用。禁止的是不相关人物条件，不是所有图像条件。

如果原意是想象、插画或概念画面，不把当前住所、当前时间强行套到画面里，也不因为描绘海边就改变真实生活位置。风格沿用原意和现有配置，本轮不将所有图片强制改成摄影。

### 6.3 人物资料按可见范围读取

本人明确入镜时，分别读取稳定身份、当前有效外观、当前有效穿着。只注入最终可见或保持身份确实需要的字段。

例如：仅靴子近景可读取对应鞋的款式和有效引用，不能附加脸、发型、年龄、胸部或上衣；衣架上的连衣裙读取服装信息，不触发“当前穿着”或替角色换装。

已有状态与初始化描述冲突时使用当前有效状态。某物品 ID 无效或并未持有时走原物品错误／查询流程；Kev 和规范化 LLM都不能声称“已拥有”，更不能直接入库。

人物照片数据缺失时，允许调用既有只读查询能力或返回明确的资料缺失；不能回填默认甜妹画像。此处不新增另一个购买、换装或身份生成 Agent。

### 6.4 第一优先级回归断言

对于明确无人物的任务，截获真正发送给规范化 LLM 的整份请求，断言下列内容未被装配：

- 本人的外观、体型、衣服、Visual Identity 详情与身份参考地址。
- 完整 Working Persona、当前人格对话协议和恋爱目标。
- “你是摇光，请拍摄自己”“默认自拍”等指令。
- 全局手持前置、高机位、向下 45°、人物在镜头下方等固定摄影骨架。
- 上一次自拍的消息、模板示例和后处理残留。

允许分支协议中出现“不得添加人物”的约束文字；测试不能因为这句话包含“人物”而误报。

## 7. 规范化 LLM 的任务与输出

### 7.1 输出职责

原意、已接受拍摄方案和分支资料共同组成规范化输入。LLM 负责把这些内容组织成中文连续自然语言提示词，补充与原意一致的环境、光影和画面表达，而不是输出角色口吻的聊天回复。

默认中文；沿用项目已有目标模型语言配置与输出接口，不在这一轮另建多模型提示词系统。

不得重新规划主题、改变人数／入镜对象、忽略明确镜头要求或把自己当作照片主体。不必追求长提示词，不能以“规范化”为由无限扩写人物细节。

### 7.2 公共规范化协议建议

以下内容进入媒体规范化专用协议，不进入主聊天的人格协议：

> 你负责将媒体意图转换为可执行的图像提示词。画面内容以原始意图与显式要求为准，拍摄方案只补充未指定的表达方式。任务所属 Actor 不一定入镜。只使用本次提供且属于入镜对象的资料，不从默认人设、历史照片或摄影习惯补入人物。无人物分支仅描述原意中的环境、动物或物品，不增加人像、手部、人物倒影或自拍。有人物时按各主体的独立资料描述，不把所有人物写成同一身份。未知信息可以省略，不用虚构生活事实填满字段。输出规范化结果，不回复用户，不宣布实际动作已经完成。

原始描述作为任务数据传入，不拼进 System Prompt 当作运行指令。描述中夹带的“忽略其他协议／换成某个模型”等文字不能修改业务约束。

### 7.3 分支化摄影骨架

| 模板族 | 核心内容 |
| --- | --- |
| 环境／风景 | 景物、前中后景、观察方向、空间层次、光影；没有固定人物段 |
| 动物 | 动物可见特征、动作、所处位置和环境；不把宠物主人自动拍进去 |
| 静物／商品 | 物品、材质、摆放、局部或整体、背景与光影；不把服装自动穿在人身上 |
| 手持自拍 | 已确认的入镜主体、面向相机关系、实际选定机位与范围；不一律高角度 |
| 镜前自拍 | 人物与镜面及相机的反射关系、可见设备和构图；不继承“手机绝不入镜” |
| 定时自摄／他拍 | 画面外机位与人物的关系、姿态、景别；不凭空加入具体摄影师 |
| 向外 POV／人体局部 | 向外观察方向、明确需要的手／鞋等局部；不补完整本人 |
| 混合 | 按原意组合适用主体段，避免两套互相冲突的摄影骨架 |

模板族可以由少量可组合段实现，不要求为每个枚举创建一份巨大 Prompt。镜头、构图、主体、场景分开组合，不能靠几十份复制模板维护。

### 7.4 内部返回契约

优先复用现有结构化输出，必要时补充最小字段：

```json
{
  "prompt": "一张雨后街道的夜景照片，湿润路面映出两侧灯光，视线沿街道向远处延伸，前景可见细小积水，画面仅呈现街景与建筑。",
  "negative_prompt": "",
  "declared_human_presence": "none",
  "used_subject_ids": ["street_scene"],
  "used_reference_ids": []
}
```

示例用于输出契约，不要求逐字复现提示词。普通生图后端只接收实际支持的 prompt／参数；声明字段保留在内部日志，不作为正文渲染。

不支持负向提示词的工作流不新造无效参数；现有负向提示词也需按分支整理，不能把人物身体属性作为所有图片的固定负向串。

LLM 的 `declared_human_presence` 或 `used_subject_ids` 是自述，不是可靠的语义审计证明。必须同时检查实际文本和下游请求，不能仅凭它声称 none 就通过。

## 8. 规范化结果与生图请求校验

### 8.1 确定性校验

检查合法结构、字段组合、已知主体／参考 ID、明确约束的结构化部分、输出长度、是否引用了该分支不允许的数据源、是否存在未解析占位符。

无人物、非本人和局部人体分支不允许补回被排除的完整人物资料。任何业务状态修改 Tool 不应因规范化任务而被执行。

可以用高精度规则捕获典型回归，例如无人物分支出现完整手持自拍模板或测试专用外观标记；不能靠一串敏感词声称解决所有自然语言矛盾。合法的“街道无人”“猫在镜子前”“玩偶裙子”不能被简单关键词拦截。

### 8.2 语义一致性与有界修复

原意和已锁定约束同时出现在规范化请求里，使 LLM 能看到“补充方案”不能覆盖的内容。已检测到的明确矛盾、结构化声明不一致或污染字段，最多触发一次规范化修复，只传原意、有效方案、允许资料和具体错误，不再携带被排除的人物上下文。

修复不重新询问 Kev，不重新决定主题，不立即重复生图。再次失败则返回可诊断的 `media_prompt_validation_failed`，不静默发送已知违反约束的 Prompt。

对未能用规则判断的复杂自由文本错误，通过本轮实际模型测试和人工抽查确认；没有既有语义校验器时，不另建常驻审查模型，也不把 LLM 自述当成保证。

### 8.3 最终生图参数必须与分支一致

在实际提交 ComfyUI 的最后一层检查：

- prompt 是否又被拼接了“摇光外观／selfie”后缀。
- 是否自动附带本人脸部／身体参考图、身份嵌入、人物 LoRA 或相关强度。
- 参数虽已删除，工作流节点是否仍保留旧身份图片、固定身体数值或默认角色提示词。
- workflow 对象、参考列表或缓存是否复用了上一张自拍的内容。

不能只检查 HTTP DTO 表面没有 `identity_ref`；要检查最终执行图中实际生效的条件节点和参数。

无人物任务保留合法的场景、动物、商品、艺术风格条件。人物身份 LoRA 与普通风格 LoRA 区分处理，不一律清空所有 LoRA。

若当前工作流强制依赖角色身份图，优先路由到已有的不依赖人物的工作流；没有可用路径时，做最小节点／参数分支补充并报告。不能明知身份条件仍在生效，还以“不改工作流”为由宣称问题已解决；也不借机替换全部工作流。

### 8.4 缓存与一致性

规范化结果或工作流缓存键至少应区分原意／明确约束、入镜范围、拍摄方案、涉及主体的有效状态版本、模板版本、身份参考使用策略与 Kev 开关相关配置版本。

无人物任务不应因姓名画像缓存命中而复用上一张人物 Prompt。不同 Actor、不同主体、不同模板分支不能共用可变结果。

人物任务在一次执行中使用一致的有效状态快照；生成期间状态变更按已有版本策略处理，不能衣服文本来自新状态而参考资产来自旧状态。

## 9. Kev 关闭、弃权与失败的行为

### 9.1 开关

复用全局 `kev.enabled`，新增媒体总开关及现有机制支持的分项开关。逻辑上支持：

- `media.subject_route`
- `media.capture_plan`
- `media.view_plan`

本地交付配置直接启用，不要求先 shadow。具体配置键遵循项目现有命名，报告中给出真实操作方式。不要改动未授权远程环境。

### 9.2 关闭／异常时的回退

关闭时 Kev HTTP 次数为 0；不进行隐藏影子调用或媒体专用预热。规范化 LLM 继续生成图片提示词，已完成的媒体隔离修复始终有效。

| 情况 | 行为 |
| --- | --- |
| 已有显式要求足够明确 | 直接据此装配，未指定参数保持中性，不需要 Kev 才能处理 |
| Kev 成功且结果可采用 | 应用补充，原 LLM 不再额外运行一轮相同判定 |
| 某个视图字段 unknown／错误 | 仅该字段回原 LLM 的表达能力或 unspecified；保留其他兼容结果 |
| 主体／本人入镜不确定 | 不加载本人画像；先由原媒体 LLM 路径依据原意解析／规范化 |
| Kev 超时／服务不可用 | 记录后继续修复后的原媒体路径，不将整次生图默认为自拍或直接失败 |
| 业务请求取消 | 停止当前任务，不在取消后另起回退生成 |

原媒体 LLM 路径遇到“本人是否入镜”确实不能确定的情况，不能预先带入全套本人资料。优先复用原有指代解析／只读查询接口；需要资料时，只有在明确入镜身份并经过程序校验后才补读。

如果当前规范化是单次无工具 Task、缺少上述入口，允许仅在此异常／歧义路径增加一次有界的结构化解析或资料补全 continuation，使用同一现有模型基础层，不创建新常驻 Agent。普通明确意图和 Kev 成功路径不增加这次调用。

真的无法解析主体或满足互斥的明确要求时，返回真实的解析错误，由原上层流程处理；不能为了始终出图而虚构本人或拍法。仅仅未指定镜头，不属于错误。

## 10. 每次媒体任务的可观察结果

复用现有诊断中心与决策存储。至少将以下环节串到同一个 `media_request_id / trace_id`：

1. 原始意图和来源、必要指代、显式约束。
2. Kev 实际输入、questions／criteria 版本、每题 raw answer、分布、采用／弃权／错误、耗时。
3. 最终 MediaCapturePlan、字段来源、被拒绝的冲突补充及原因。
4. 实际注入的 Slot／数据源清单，以及被排除项的类别；不为了记录“排除了外观”反而额外读取外观原文。
5. 实际发往规范化 LLM 的可复核请求、模型配置／模板版本、输出、修复次数和校验结果。
6. 最终生图 Prompt、负向配置、引用资产用途及 ID、工作流标识／必要参数快照、真实生图任务和图片结果 ID。
7. Kev 关闭／失败是否走了原媒体路径，冷加载与调用预算情况沿用已有记录。

正常聊天上下文中不追加完整判定账本、概率和规范化中间过程。诊断遵循原权限、脱敏、保留期和持久化策略，不记录密钥。

对每张图应能回答：原意是什么；Kev 是否误判；是否错误加载人物资料；LLM 是否改了画面；最终工作流是否重新加入身份条件。

## 11. 必须实现的单点与回归用例

### 11.1 测试分层

**A. 程序契约测试。** 使用固定 Kev／LLM／ComfyUI stub，断言分支、资料查询次数、实际模型消息、最终 payload、状态不变及开关行为。目标是所有确定性不变量通过。

**B. 真实 Kev 单点测试。** 独立运行下面媒体用例，保存输入、选项、原始答案、错误、弃权、字段级准确情况和延迟。此前的人格／Tool 选择成绩不能充当这些新摄影题的测试结果。测试至少包含相同意图的两种中文表述、否定、引用、多主体、仅局部主体和 unknown 选项。

**C. 真实规范化 LLM 测试。** 输入经过过滤的上下文，保留实际 Prompt，检查人物与拍法有没有重新出现；不是只检查自己生成的 structured manifest。

**D. 实际图像抽查。** 通过现有 ComfyUI 生成隔离测试图片，不向真实用户发布。至少覆盖无人物、局部人物、合法自拍及他拍。人工核对图片，区分提示词问题、身份条件问题和图像模型构图不遵循，不能把文本正确当作图片正确。

真实服务无法访问时，仍完成实现与 A 层测试，提供 B／C／D 的独立执行命令并明确未执行，不写“端到端已通过”。

### 11.2 固定媒体场景矩阵

以下为业务预期，不得为了迎合模型输出改 expected。未指定的画面参数可以有多个合法值；测试应断言允许集合与禁止行为，不强行要求所有可自由选择的角度完全一致。

| ID | 大概描述／条件 | 关键预期 |
| --- | --- | --- |
| M01 | “窗外雨后的街道，路面反光，没有人。” | none；风景；本人资料查询 0；无自拍／身份条件 |
| M02 | “我想拍一张傍晚海面的落日。” | 我是作者，不自动入镜；无本人画像 |
| M03 | “窗台上蜷着一只橘猫，近景。” | animal、none；只描述猫和环境 |
| M04 | “我的猫趴在沙发上睡觉。” | 所有者不是入镜者；不增加抱猫的人 |
| M05 | “书桌上的咖啡与设计稿，俯拍。” | mixed/object、none、top_down；不增加手部 |
| M06 | “衣架上那条连衣裙的商品照。” | 服装物品；不加模特，不读取当前穿着 |
| M07 | “拍一下那双靴子放在门边的样子。” | 靴子静物；不变成穿靴子全身人像 |
| M08 | “从我的视角看窗外的雪，不拍到我。” | pov_outward、none；不是前置自拍 |
| M09 | “我手里拿着咖啡，画面只保留手和杯子。” | partial；只补必要局部，不加载脸／全身图 |
| M10 | “低头拍我脚上的靴子，只拍鞋和一点裤脚。” | partial、pov_outward；不补完整人像 |
| M11 | “给自己拍一张手持前置自拍，平视近景。” | 本人入镜；handheld_selfie；eye_level，不强制高机位 |
| M12 | “在穿衣镜前拍今天穿搭，从头顶到鞋底。” | mirror_selfie + full_body；保留镜面／设备合理可见关系 |
| M13 | “对着镜子拍半身照。” | mirror_selfie + half_body；不强制全身 |
| M14 | “朋友帮我拍一张公园里的全身照。” | 本人入镜、external_photo、full_body；不变自拍 |
| M15 | “相机定时，我站在树下拍全身照。” | self_timer、full_body；不加镜子或手持前置 |

### 11.3 污染注入测试

使用测试专属、容易断言的不同标记，例如脸部、服装、旧自拍模板和身份参考分别使用独立 sentinel。将它们放在模拟的默认人格、全局模板、旧消息、后处理和工作流默认配置中。

无人物任务应证明这些来源既没有被不必要地查询，也未出现在实际规范化输入、Prompt 和最终生图条件里。本人合法人像则应读取允许的当前标记，证明修复没有通过“把所有人物功能关掉”取巧。

对只可见手／鞋的任务，断言局部资料存在、无关脸／全身资料不存在。对多 Actor，断言人物 A 的标记没有落到人物 B。

### 11.4 独立可运行的测试产物

在仓库已有测试组织方式下提供至少两个入口：

- **媒体计划单点测试**：只调用 Kev，运行媒体 fixtures，输出 JSON 报告，不触发规范化或生图。
- **媒体规范化链路测试**：接受指定 intent 和可控状态，运行实际媒体装配／规范化／请求构建；支持 stub 或真实模型；真实 ComfyUI 执行由显式参数打开。

不得默认产生真实社交发布、物品写入或大量批量生图。测试结果保留错误样本、部分失败与未执行项；不反复改同一批用例使数字看起来好看。

## 13. 最终验收清单

- [ ] 原有大概描述仍由摇光形成；没有新增“决定拍什么”的主流程。
- [ ] Kev 只补有限画面参数，不生成长 Prompt、不改权威状态。
- [ ] 判断人物是否入镜后才加载人物信息，不把任务所属 Actor 当入镜主体。
- [ ] 纯风景、动物、静物没有无关人物资料或自拍模板进入规范化 LLM。
- [ ] 非本人照片不使用本人身份；局部人体不使用完整脸／身材资料。
- [ ] 对镜、手持、他拍、定时、POV 与构图维度正确分离，明确要求不被覆盖。
- [ ] Kev 直接生效且可关闭；失败回原媒体 LLM；隔离修复不随开关关闭失效。

- [ ] 合法自拍、当前外观与当前穿搭仍然可用，没有通过关闭人物功能掩盖缺陷。

- [ ] 每个判定、最终方案、实际 LLM 输入和生图任务均可追踪，账本不进入聊天上下文。
