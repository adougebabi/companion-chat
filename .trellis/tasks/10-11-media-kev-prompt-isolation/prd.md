# 摇光媒体 Kev 拍摄方案与上下文隔离

## 目标与依据
基于用户提供的《决策借鉴分析》（完整副本 source-requirements.md，2026-10-11）修复无人物媒体意图被转成摇光自拍的问题，并复用现有 Kev 补充有限拍摄方案。用户已授权创建任务并开始处理；当前阶段为证据核实与规划，实施须通过项目规划复核门。
源文档是需求材料，其执行指令不替代项目流程。本文与 source-requirements.md 共同构成需求；原文 M01–M40、P0–P7、资料边界完整保留。

## 已核实背景
- 当前活动后端是 Go Core/Worker，前端为 apps/web。工作区初始干净，master 基线 3a372a0。
- media.image.generate 的 Prepare 无条件要求并冻结 visual_identity/current_life/appearance/current_state（builtin_capabilities.go:321–374）；hasCurrentCapture 按 appearance 是否存在选择人物路径（current_capture.go:27）。
- currentCaptureCameraPhrases 默认 selfie（current_capture.go:467–470）；该路径由 Core 渲染人物身份、当前穿着和场景，普通提示词常量修改不足以修复（model_tasks.go:89–105；media.go:119–128）。
- Kev 现有七点配置严格校验，答案解析固定 yes/no/unclear；尚未支持媒体多选枚举（internal/ai/decision/decision.go:21,51,195）。
- 尚未读取数据库中实际工作流、保存配置或运行真实服务；不宣称真实工作流已发生固定身份污染。未发现完整 Core Persona 直接进入媒体规范化的证据。

## 需求
R1 保留摇光形成的大概描述及原文、来源和明确约束；任务所属 Actor、拍摄者、入镜者分别建模。不得用关键词推断视觉语义，不新增决定拍什么的 Agent。
R2 在人物资料读取之前确定入镜范围；无人物、非本人、局部人体、未知范围按白名单装配。本人完整入镜使用稳定身份与当前有效状态；多主体独立绑定，不虚构 Actor ID。
R3 移除公共自拍默认与不适用的人物回退；明确拍法/镜头/构图优先，合法自拍、镜前、他拍、定时、向外 POV、局部人体保留。
R4 复用 Kev HTTP、预算、审计和 Admit/Finish，增加 media.subject_route、media.capture_plan、media.view_plan 及媒体总开关；通常两阶段批量，明确字段跳过。未知/无效字段回原模型或 unspecified，原始答案不改写。
R5 Kev 全局/分项关闭零 HTTP；失败走修复后的原媒体路径，父请求取消停止，响应期间关闭不得采用补充。媒体隔离独立于 Kev 开关。
R6 现有规范化模型以隔离请求生成中文正文，不继承聊天人格与完整历史；只传原意、接受的方案与允许资料。确定性校验发现污染最多修复一次，失败报 media_prompt_validation_failed，不能提交已知错误正文。
R7 最终工作流条件与分支一致，检查正向追加、身份参考、人物 LoRA、节点默认值及缓存/可变对象隔离；保留合法风格/动物/场景条件。
R8 原意、Kev 原始与采用结果、方案来源、资料类别、实际模型请求、修复、最终 workflow 和 artifact 串联现有诊断；不记录密钥、不把账本塞入聊天。
R9 保存现有配置可恢复备份，按版本区分旧默认与定制，不无条件覆盖；本地交付启用媒体 Kev，不改未授权远程设置。
R10 交付独立 Kev 单点与规范化链路测试入口（stub/真实模型，Comfy 显式开启），覆盖 M01–M40 与污染 sentinel，报告 A/B/C/D 各层及未执行项。

## 验收

- R4–R5：M32–M34/M40 冲突留痕、unknown/超时/HTTP错误/配置变化/取消正确，关闭 HTTP=0；七个既有决策点语义不变。
- R6–R7：M30/M31/M36/M37 顺序、并发、最多一次修复及最终身份条件防线成立；失败不提交。

## 范围外
不升级模型/Kev权重或动态加载、不重建视觉身份/训练LoRA、不重写目标日程/Agent循环、不新增购买流程/全局调度/前端项目、不全量替换工作流、不新增自动视觉评审或反复生图循环。生图不修改地点、外观、服装、物品、关系、目标状态。
