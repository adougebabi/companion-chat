# Agent / Tool 插件化收敛与双 E2E 验证闭环

## Goal

全部完整任务 Agent 通过自身入口使用同一 Eino 原生循环；全部业务 Tool 脱离 Main、认知轮次及阶段独立完成真实业务；生产入口使用同一已验证路径。交付实际代码、测试、规范和可复核真实验收证据，不以框架/PoC/局部编译通过替代完成。

## Background and confirmed facts

当前代码证据清单在 research/inventory.md（每项含 file:line），锁定版本在 research/eino-version.md，环境预检在 research/preflight-results.json 与 research/config-presence.json。基线为当前工作树，已有 52 项未提交改动必须保留。已核实：15 项注册业务 Tool、多数写工具外层提交；16 类完整模型任务，仅三种 schema 进入两轮 ADK；真实媒体测试与独立全覆盖不足。

## Requirements

原始请求 request.md 全部条款作为本 PRD 的规范性附录，以下 ID 用于验收映射，不缩减任何条款。

- R1 全部完整任务有正式 Agent：自有任务 prompt、输入/上下文、模型配置、工具装配和输出契约；公共片段/Slots/Embedding 不机械变 Agent。
- R2 唯一原生循环：原生 ToolCall 唯一执行依据；实际工具结果进入后续模型输入；支持普通写入和业务失败后继续、多轮/同轮多调用；只有最终输出接受最终 schema 校验。不解析正文/reasoning/JSON sidecar 成第二协议，不做旧文本兜底。
- R3 全部业务 Tool 直接调用和 Eino 适配共享正式参数解析、执行及结果序列化；不要求伪造人格/Agent/source stage；参数、资源归属与业务条件必须显式校验。
- R4 实际副作用：查询真查、写入真写、发布使用正式通道；回复、动态、记忆、人格、视觉保存全部覆盖。局部事务+outbox；真实异步 accepted 不冒充 completed。
- R5 幂等与失败：稳定业务 operation ID 与 native ToolCall ID 分离；同键不同参数拒绝；已提交事实在模型失败/取消/非法最终输出后保留，禁止整轮重跑造成重复。依赖异常、程序错误、超时/超限不变成功。
- R6 全生产入口迁移：API、对话、后台使用正式 Agent；外层不解析/执行工具、不拼工具结果、不决定续接；视觉实际图片进入正式多模态模型路径；运行状态隔离。
- R7 Tool 真实 E2E：全部当前业务能力（固定基线+新增提取项）覆盖有效调用、真实业务失败、独立产物核验、依赖异常、重复语义、正式适配等价；不启动 Main。
- R8 Agent 真实 E2E：每个正式 Agent 有自身证据；按职责覆盖无工具/一次/至少两轮工具与三次模型决策/失败继续/写后查/同轮多调用/提交后模型失败/异常结束/隔离；生产流式必测。受控回归单列，不替代真实 Provider。
- R9 证据有效性：随机记忆答案只在库中，经正式认知 Agent 真实工具获取；关联请求、ToolCall、执行、产物、下一请求和最终输出；断回填和假成功写入两个破坏性实验必须使相应用例失败，恢复后全跑。缺项、零匹配、SKIP、BLOCKED、失败一律不能总体成功。
- R10 清理与交付：删除旧续接、重复 dispatcher、代执行、冲突门禁/兜底及旧实现细节测试；保留产品契约。同步原有 Trellis 规范；完整矩阵、命令、退出码、版本、配置说明与阻塞事实脱敏交付。
- R11 媒体质量恢复：首张图片未通过质量检查时，把检查返回的结构化违规项、观察事实和优化建议交给正式 Media Prompt Agent，在相同冻结概念下重新优化提示词并生图一次；第二张仍未通过时，保留真实检查结果但接受并交付第二张图片，不再因质量失败卡死或发起第三次质量重试。此流程只定义一次质量修正，不限制通用 Tool 调用。

## Acceptance criteria

- AC1（R1,R2,R6）：research/inventory.md 中每类任务和完整视觉任务都有正式注册/入口/生产调用证据；无单次 Task 旁路；通用 loop 不含业务分支。
- AC2（R3,R4,R5,R7）：全部基线 Tool 和提取出的业务 Tool 均可在无 Agent 状态下运行，结果与独立查库/消息/对象/任务核验一致；同一实现经 Eino 调用也有证据。
- AC3（R2,R5,R8）：多轮真实闭环、流式、失败恢复与隔离通过；罕见错误由单列受控回归覆盖；没有把运行保护当成功条件。
- AC4（R7,R8,R9）：两套完整套件都实际完成，所有必需行有 case ID、测试类型、状态和证据位置；两个破坏性实验失败如预期且恢复后最终套件通过。
- AC5（R6,R10）：生产入口和规范收敛；有效历史回归通过；用户修改保留；提交时机变化清晰；实现和真实验收状态分别报告。
- AC6（R4,R7）：受控回归覆盖首检未通过→结构化反馈进入 Media Prompt Agent→第二次生图；第二张无论质量 pass/retry/reject 都以同一真实候选资产完成发布，诊断保留原 verdict 和最终 `retry_accepted` 状态，且没有第三次质量生图。

## Out of scope and constraints

不整体重构、不替换前端/BFF/Go、不迁移 Temporal/数据库/基础设施、不升级 Eino、不复制框架、不建第二 runtime/工作流/测试平台、不引入动态插件安装。不得生产迁移/写入/远程发布/强推。仅隔离环境与测试账号；不输出密钥。

## Risks and deferred verification

具体各 Tool 参数与底层事务在修改前逐一完整读取；这是实现研究，不缩小范围。现有 .env 有模型/媒体配置但尚未验证真实服务；可从既有配置恢复，缺失依赖不阻止独立实现，受阻行不得计为通过。保留 Temporal 持久恢复与媒体任务身份，同时移走其代替 Agent 的模型续接决策职责。

需求边界已由 request.md 明确，无待用户裁决的产品问题。当前状态 in_progress；用户已批准实施，最终真实验收待代码回归收敛后串行执行。
