# v3 页面 1:1 还原、遗漏补全与组件化验收

## Goal
按用户最新纠偏要求，当前阶段只交付完整可交互的 v3 Mock 页面供用户验收。用户明确验收页面通过之前，不继续真实 API 填充和业务联调。

## Requirements
- UI1：以 /Users/vinson/Documents/文档/个人/ai/fluctlight/prototype-v3 为唯一已确认视觉与交互基准，保持 C 鼠尾草青绿；恢复全部既有页面、子页、标签、抽屉、弹窗及流程，不以旧 Vue 业务视图替换页面。
- UI2：全部数据来自明确隔离的 Mock 数据源。正常、空、加载、失败、未接入、冲突、部分成功均可演示；当前入口不调用 Core、真实认证、模型、媒体或其他业务 API。
- UI3：组件化、通用化。复用原 DOM 和样式语言拆分公共组件、领域展示组件与页面组合；不能只给整页套组件，也不能复制另一套页面状态。
- UI4：依据既有 v3、Quasar、蓝图补齐遗漏的“关于你”、NPC 管理及其子页面操作。新增部分沿用 v3，不变更原页面布局或已确认流程。
- UI5：用户验收是阶段硬边界。只有用户明确确认页面通过，才开始将 Mock 适配层的数据替换为真实接口。旧后端 WIP 保留但冻结，不混作本阶段验收成果。

## Acceptance Criteria
- 全部原型 55 路由及新增遗漏页面有可达入口、返回路径、可演示交互与状态。
- 核心页面在桌面和窄屏对照原型检查布局、样式、素材、间距、文案与交互；差异必须可解释且仅限新增能力。
- 原型纠错、取得物品换装、创作草稿发布应用等演示链可走通，修改后 Mock 读回及刷新保持。
- 公共控件、表单、卡片、页签、弹窗抽屉、状态反馈、来源、聊天重复结构实际组件化并多处复用。
- 浏览器网络没有真实 /api、/auth、模型或媒体业务请求；没有旧业务视图替换 v3 页面。
- 交付可打开的页面验收入口、覆盖台账、验证记录与截图，然后等待用户验收；不得自动进入真实接口阶段。

## Constraints
不做桌宠、Live2D、时间线回档；永久性伤害保持禁用。不删除既有用户数据，不把 Mock 持久化写进真实数据库。
