# 聊天上下文与提示词优化

## Goal

优化正常聊天的身份、状态、关系记忆和历史消息上下文，在保持人格连续性与时间事实可靠性的前提下控制长度并提升回复稳定性。

## Confirmed Facts

- 当前聊天 system prompt = 不可变身份层 + 生活状态层 + 关系/记忆层 + 系统能力层；另附最近 18 条用户/助手消息。
- 当前两个本地人格的实际近似输入长度分别约为 3,359 和 4,344 个字符；尚未达到不可用程度，但关系记忆和长消息会持续放大输入。
- 当前历史窗口仅按消息条数（18 条）裁剪，不按总字符/token 预算裁剪；关系层将全部活跃记忆直接拼接，未按相关性或预算选取。
- 系统能力层包含媒体意图、时间事实和用户可见回复形式三项应用拥有的不可覆盖约束。

## Requirements

- 保留不可变身份、当前生活状态、时间事实、关系边界和应用能力约束的正确优先级，不因压缩而允许人格/用户文本覆盖系统规则。
- 为消息历史和关系记忆建立明确且可测试的长度预算与选择策略，而不是只依赖固定消息条数。
- 在长对话、较多长期记忆、长用户消息和日计划存在时，保证 prompt 仍有稳定的上界。
- 优先保留与当前对话相关、近期或高置信的记忆；不要把不相关的长期记忆逐轮重复发送。
- 优化不应改变聊天 SSE 合约、用户可见消息落库方式或既有媒体意图/可信时间功能。

## Acceptance Criteria

- [ ] 正常聊天请求具有可验证的总长度预算，超出预算时有确定性的裁剪顺序。
- [ ] 身份、当前状态、可信时间事实和系统能力层在任何裁剪情形下仍被保留。
- [ ] 关系记忆的选择有相关性/新近性/置信度等明确规则，并有覆盖长记忆场景的测试。
- [ ] 长聊天和长消息不会使最近历史无限膨胀，且当前短对话体验不退化。
- [ ] 现有聊天、时间问答、媒体意图、睡眠延迟回复相关测试继续通过。
