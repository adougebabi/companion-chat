# 摇光前端功能盘点（阶段一）

## Goal

建立 Fluctlight 当前前端功能、真实可用程度、后端能力入口和核心领域数据关系的可追溯基线，支持下一阶段导航规划、功能原型和 Quasar 参考对照。

## Background

这是评审/审计任务，不是产品开发任务；文档作者工作是审计交付的一部分。

用户要求完整盘点当前前端路由、页面、隐藏交互、状态、API、实时通信、媒体、权限和模拟行为，并对必要的后端代码与已有文档做交叉核验。审计重点是功能和实际调用链，不是代码质量。

## Requirements

- **R1 — 前端页面清单：** 识别前端框架、路由、导航、动态页面、配置和全部页面/弹层/Tab/抽屉；记录交互、数据来源和页面跳转。
- **R2 — 功能矩阵：** 按功能域为每个真实存在或待核验的功能给出稳定 Feature ID、页面位置、主要操作、前后端证据、数据来源、A–F 状态、依赖、问题和原型备注。
- **R3 — 后端 UI 缺口：** 只记录代码或既有文档证实的能力；区分已有 API 可复用、缺 UI 入口、缺管理 API、部分实现、占位、废弃与仅规划。
- **R4 — 领域实体：** 说明实体、关系、权威来源、持久化方式；分别标记证实关系和待核验/建议关系，特别覆盖 World/Scene/Location、Actor/NPC/Persona、Goal/Schedule/Event、物品定义/持有/装备、静态设定/动态状态、Memory/Reflection/对话来源。
- **R5 — 重构保留约束：** 记录不能破坏的交互闭环、API 契约、状态与缓存、实时通信、媒体、兼容和回退要求。
- **R6 — 汇总与证据：** 完成六份文档，事实结论可追溯到代码行或现有项目文档；不可确认项明确标记并说明缺失证据；现有功能与规划严格分开。

## Constraints / Out of Scope

- 仅分析和文档；不得修改前后端业务实现，不改 Agent/Eino/ADK/Tool/模型调用或人格切换逻辑。
- 不新增功能、不重构、不开始 Quasar 实现，不设计视觉风格、配色或组件样式。
- 不因前端重做而建议未经证据支持地删除既有功能；不从历史需求推断当前实现。
- 不把模拟数据或仅有成功提示误判为持久化能力；结论不确定时标记“待核验”。
- 不创建重复领域模型；对建议关系与事实关系分开说明。

## Deliverables

目录 `docs/product/frontend-audit/`：

1. `01-current-pages.md` — 路由、页面功能区、交互、数据来源、页面跳转。
2. `02-feature-inventory.md` — 按功能域组织的完整功能矩阵与代码证据。
3. `03-backend-ui-gaps.md` — 后端能力、可复用 API、缺失 UI/API 闭环。
4. `04-domain-inventory.md` — 核心实体、关系、权威来源与持久化。
5. `05-restructure-risks.md` — 重构须保留的能力和兼容约束。
6. `06-audit-summary.md` — 分布、完整度、缺失、重复、历史遗留、可补入口、规划边界及原型待决问题。

## Acceptance Criteria

- **AC1 (R1):** 所有实际存在的前端路由及导航/动态入口均在 `01-current-pages.md` 有记录，并注明主要交互、数据来源和跳转。
- **AC2 (R2):** 重要交互逐项对应真实事件与后端链路证据；模拟/纯前端/部分接入/无法确认状态正确分类，矩阵包含所有规定字段。
- **AC3 (R3):** 重点后端能力仅按实际实现分层，能追溯到 API/Service/Tool 或明确说明缺少入口/证据。
- **AC4 (R4):** 核心实体关系和持久化有代码证据，事实与建议分开；重点实体问题逐项说明。
- **AC5 (R5):** 已有关键操作、接口、状态、实时、媒体、兼容及回退约束均有依据或被标记待核验。
- **AC6 (R6):** 六份文档完整位于约定目录，跨文档术语和结论一致；不得改动业务代码。

## Open Questions

无产品范围问题。所有实现状态和实体关系未知项通过代码/文档探索解决，无法确认时明确列为待核验。
