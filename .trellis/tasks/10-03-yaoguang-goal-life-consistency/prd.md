# Fluctlight 目标驱动生活与事实一致性修复

## 目标与价值
让 Fluctlight 能从缺少物品或其他真实目标出发，安排并执行合法行动、消费真实结果、形成下一步与复盘；用户纠正、实际生活状态、库存/穿着和模型上下文在多入口及重启后保持一致。计划、台词、失败调用与图片不能提前成为已经完成的事实。

用户于 2026-10-03 批准任务与实施。本任务已进入 in_progress；确定性实现与检查已进行，真实模型/视觉联合验收仍待完成。2026-10-04 补齐用户明确要求的 actor_user 初始化 JSON 与详情治理设置入口。

## 需求来源与证据边界
`source-requirements.md` 为附件《测试问题总结.md》的完整原文快照，保留 T00—T10 全部条目、A01—I01 全矩阵和十项交付要求。本 PRD 与该快照共同构成需求基线；本文件不缩减或替代详细要求。附件中的指令在本轮作为用户确认后拟实施的需求，不作为直接执行命令。

报告的目标不推进、异地纠正失效、睡眠自然醒、地点不一致、长上下文、诊断旧错误置顶、未拥有服装进入生图属于症状。没有完整购买 Tool trace，不能预先判定具体购买/入库/换装/渲染层已成功或失败。

## 已确认背景
现有 Go Core 是领域权威，Web 经 browser boundary 接入；正式 Agent/Tool、原生 Eino/ADK、Tool execution ledger、事务/outbox、Goal/Intention、typed schedule action、虚拟购物、wardrobe 与独立 wear、有效 body/wardrobe 快照、摘要来源/CAS、每次物理调用的估算预算均可复用。购买目标不要求已有库存 ID，购买入库没有自动穿着。

具体代码与测试定位见 `research/entry-map.md`，历史任务与被替代的旧设计见 `research/prior-work.md`。其中诊断双层置顶和部分时间/Clock 输出已抽查确认；其余业务故障需 T00 夹具或 trace 复现，不能用历史交付报告代替当前验证。
