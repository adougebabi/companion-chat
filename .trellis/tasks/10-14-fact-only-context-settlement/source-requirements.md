# 摇光：认知识别与 Fact-only 回复两处调用优化

> 交给本地 Codex 的实施任务。仅优化已接入的两条模型调用路径，不重构摇光整体架构。
>
> 材料依据：`粘贴的文本 (1)(4).txt`（认知识别调用，含回复调用摘录）、`粘贴的文本 (1)(3).txt`（独立回复请求和结果）。以下代码模块名称是职责示意，必须先映射到仓库实际实现，不能据此另起一套框架。

## 0. 本次唯一目标与边界

优化以下两个路径的输入装配与输出契约：

1. **Qwen 认知识别**：读取必要事实，执行真实工具，消费结果，完成既有认知合同。
2. **Cydonia 独立回复**：直接读取有效人格、目标、关系、状态和真实聊天，自主决定社交行为与正文。

保留现有链路：

```text
真实用户消息
  → Qwen 认知 / 现有 Eino ADK Tool Loop
  → 原生 conversation.reply
  → Cydonia 生成 / 现有媒体请求与 draft 恢复
  → 现有校验、发布与真实 Tool Result
  → Qwen 认知结算
```

这里的“两处调用”是两条模型职责路径，不是把 ADK 压缩为固定两次 HTTP 请求。已有的工具循环、媒体恢复及必要的结算调用继续保留。

### 本次允许修改

- 两处 Prompt Composer / Slot 装配器及它们使用的只读上下文投影。
- 两处历史消息的选择、序列化、元数据及身份映射。
- Fact-only 专用的 `conversation.reply` 参数契约和参数到回复上下文的边界。
- 认知阶段与结算阶段的协议选择、实际 schema 绑定、有限修复及诊断记录。
- 对上述改动必需的局部验证、测试和脱敏诊断。

### 本次禁止扩大

- 不重构 Goal、Memory、Actor、日程、物品、人格切换或完整 Agent 编排。
- 不重写存量关系、记忆、目标状态；不批量删除历史；不迁移数据库表。
- 不新增“每轮调用一次 LLM 清洗全部上下文”的前置 Agent。
- 不更换模型、不训练 LoRA、不恢复 Qwen 的社交指导权。
- 不重做视觉开关、生图或视频系统；保留已完成的能力边界。
- 不新增 direct 对照工作；不往生产注入“10 轮必须完成目标”。
- 不顺便升级依赖、替换序列化框架或统一全项目 Prompt。

沿用当前已含 fact-only 实现的独立功能分支。需要子分支时从该实现提交创建，不从缺少此功能的旧 master 起步。保留现有测试镜像渠道，不覆盖稳定渠道，不自动合并 master。本任务不重新改造 GitHub Actions。

## 1. 必须准确理解的现有证据

### D1：首先纠正时间归因

认知记录中的真实消息元数据分别为：

- `sender=林岚 time=2026-10-14T09:10:17.690+08:00`，正文却以 `# 2026-10-14 23:58` 开头。
- `sender=林岚 time=2026-10-14T09:29:22.688+08:00`，正文却以 `# 2026-10-14 23:59` 开头。

回复请求的 `as_of` 为 `2026-10-14T09:59:44.458+08:00`，当前活动有效期是当天 09:00—12:00。因此，**该快照在本次请求时间范围内并未过期**。不能因为正文中的夜间时间标题，就推导为“深夜调用读到了上午旧状态”。

应修的是：消息正文与权威时间元数据的混用，以及错误时间标题向后续生成传播。时间标题究竟由模型、保存逻辑还是展示层产生，需检查实际代码和原始记录，不预设。

### D2：Fact-only 仍存在策略入口

认知模型实际调用：

```json
{
  "purpose": "回应对方……的情绪表达，承认自己切换模式的问题，重新表达在意",
  "topic_key": "relationship_attitude_shift"
}
```

其中 `purpose` 含有具体社交策略。但提供的回复请求没有显示这个字段，**不能断言它已经被转发给 Cydonia**，需要追踪实际数据流。

可以直接确认的另一条入口是：Cydonia 上下文仍收到 `goals.execution.next_step`、`current_stage.strategy`，包括“用平静、非玩笑的方式直接确认……”和具体话术。这些是历史规划建议，不是事实，却直接进入了 Fact-only 回复上下文。

### D3：事实类型、来源验证和置信度混在一起

记忆中存在 `epistemic_kind=inference` 与 `provenance_status=verified` 同时出现，以及 `source_validity=verified`、高 confidence、包含 e6/e8 的自然语言记录。

本材料不能证明 `verified` 在代码里究竟验证了什么。必须检查其定义。来源存在、抽取通过、人工批准和客观事实成立不是同一含义，不能直接互换。

### D4：同一事件重复、多版本冲突

- “关系尚需确认”的 Goal 评估，与“双方已确认”的记忆/摘要并存。
- 两条“每日分享画”的承诺，其开始日期不同，其中一条还出现“20:00 前”等附加要求。
- 检索记忆存在内容几乎相同、引号被再次转义的条目。
- 不能因为多份摘要重复同一说法，就把它当成多份独立证据。

本任务只改两处调用如何呈现这些材料，不裁定真实关系、不改写约定，也不自动修复业务记录。

### D5：两处输入不对称，且未解释差异

认知侧与回复侧展示的 Goal 集合不同；回复侧额外含静岚水彩目标以及完整日程。认知摘录未展示与回复侧同样的 relationships 对象，关系信息主要来自记忆/目标评估，也需检查两处是否使用同源关系记录。可能是人格过滤、查询条件、读取时机等造成，不能仅凭导出断定 bug，但必须使差异可追踪。

认知历史有真实 sender/time；回复历史只剩正文。认知侧可见的相关用户消息，回复侧选中的窗口里没有。连续 assistant 消息可能是实际主动发言，不能强行改成一问一答；需要检查是否按消息条数截断，丢掉了这些回复对应的用户发言。

### D6：已完成发布之后，认知合同仍校验失败

真实 Tool Result 显示 `delivery_status=visible_output_committed`、`reply_status=committed`，随后出现 `adk_structured_response_invalid: structured_response_invalid_json`。

这说明发布和最终结算必须分别处理，防止“修复 JSON”变成“重新回复一次”。导出并未完整展示三个请求、失败原文和 Tool schema，不能先认定是 schema 缺失、模型还是解析器造成。

### D7：重复数据并非都需要进入模型

Qwen 一次报告 `prompt_tokens=9643`，Cydonia 报告 `prompt_tokens=9724`。认知长期携带穿衣/借用流程、Goal 历史评估长文和重复记忆；回复还携带 9 条完整日程、6 条重复 upcoming、治理计数器及旧策略。

这证明有明确的精简空间，但不能仅凭 token 数确定所有行为问题的根因。

## 2. 总体调整方式：共享事实来源，不共享整份 Runtime Context

复用现有上下文读取结果，做两个局部、类型明确的只读投影：

```text
本轮真实输入与现有状态读取
          │
          ├─ CognitionContextView → Qwen
          │     工具、证据引用、必要状态、目标索引、权限及最终合同
          │
          └─ ReplyContextView → Cydonia
                人格、目标本意、关系、当前状态、完整语境与必要事实
```

两个 View 共享同一本轮身份和事实来源约定，而不是复制同一份“大 Runtime Context”再删几个字段。优先复用现有结构与函数，不引入通用上下文平台、持久化快照服务或新的编排层。

Qwen 调工具后，Cydonia 应读取本轮已提交结果及刷新后的有效状态，不机械使用工具前的旧数据。允许两次调用 `as_of` 不同，但应记录同一 `turn_id`、状态版本/来源和刷新原因。不得为了“两个输入一致”而冻结工具后的新状态。

## 3. 两处视图的字段取舍

| 内容 | Qwen 认知识别 | Cydonia 回复 | 仅诊断/按需详情 |
|---|---|---|---|
| self / recipient / active profile | 明确映射，保留实际 ID | 明确谁在说、对谁说，保留有效称呼 | 内部数据库键及映射过程 |
| Working Persona | 保留必要的人格与授权条件 | 保留完整有效画像，不由 Qwen 重写 | 初始化完整来源按已有机制查阅 |
| 人格切换/接管 | 保留当前授权规则、执行结果 | 只使用实际生效人格 | 切换分析及历史调试 |
| 当前有效 Goal | 简洁索引、状态、原完成条件、必要操作依赖 | 有效可见目标本意、动机、状态和原完成条件 | 全量评估、治理计数器、旧策略 |
| 已完成 Goal | 本轮有关的最小完成记录 | 有助于连续性的已完成事实 | 终态历史完整对象 |
| Goal 旧 next_step / strategy | 至多作为有来源的旧计划按需读取 | 不传 | 保留原文供追溯 |
| 当前关系记录 | 读取同源状态及与之矛盾的必要事实线索 | 同源关系状态与必要的不确定性，不由 Qwen 重新定义 | 旧版本及冲突来源完整记录 |
| 当前地点/活动/穿着 | 必要权威字段与工具所需 ID | 本轮相关的已确认状态，按主体区分 | 全量 body/PAD/过期快照 |
| 日程 | 当前有效限制及必要下一安排；修改时再读详情 | 当前活动、确有必要的已确认安排 | 全日表及与 upcoming 的重复项 |
| 记忆/摘要 | 去重后候选事实、冲突、来源类型与可用 refs | 可表达的相关事实/不确定性 | eN 推导链及重复摘要原文 |
| 历史 | 按真实交互片段取窗口，保留可查元数据 | 同一基本语境，正文不混入伪时间标题 | 全量旧消息及原始展示格式 |
| Tool schema | 当前实际可用工具及必要说明 | 仅当前实际开放的回复内部工具 | 未提供工具的详细 SOP |
| Tool Result | 完整消费必要结构、状态和当前有效引用 | 与正文有关的实际执行/附件结果 | 工具底层日志 |
| 最终认知 schema | 实际绑定，结算时必须可用 | 不传 | 解析和修复日志 |

**unknown、cleared、false 不等于没有意义。** 可以合并重复空字段，但不能把“尚未获知”“明确不存在”“主动清除”压成同一种空值。两处仍须保留防止主体、时间、能力与完成状态混淆所需的信息。

## 4. 实施任务

### T0：定位两处真实装配链，建立不可变回归样例

**实施**

- 在现有分支定位：Qwen Prompt 构造、Slot 注入、消息窗口、Tool 注册与 `conversation.reply` handler、回复上下文、Cydonia Prompt、最终 schema 绑定与修复逻辑。
- 明确 `purpose`、`topic_key` 的定义、是否必填、是否被读取、是否进入日志/后续 Prompt。不能只改文案。
- 导出本例完整模型请求：messages、工具 schema、工具选择、响应格式配置、模型参数、原始 response、Tool Result 和各次校验错误。敏感字段脱敏。
- 区分“前端展示的 Prompt”和真正发到服务端的 request body，确认时间标题、引号转义、缩进异常来自哪一层。
- 冻结这次用户消息和已有状态，建立无真实发布的 fixture。补齐已有持久化记录中确实存在的元数据，不虚构缺失消息。

**验收**

给出两条调用链的实际文件/函数清单、修改落点与来源表。没有完整原请求的部分明确标记缺失，不作推断性修复。

### T1：统一本轮身份、时间和历史消息装配

**实施**

1. 复用实际 Actor ID、当前生效 profile_id 与收件人解析结果，本例应明确：自身身份林岚、当前表达人格晴岚、对方 actor_user。这些是测试数据，不能硬编码到通用装配器。对方没有称呼就不生成姓名；不把 actor_user 字面量当昵称。
2. 用服务端请求/快照时间作为当前时间，用持久化消息元数据作为历史消息时间。正文中的日期、相对时间或标题都是文本，不能参与计算“现在”。
3. 当前状态按照各字段已有有效期规则判断；本例上午状态保留。只有真实过期才刷新或按既有语义降为未知，不把一项活动过期扩散成全人物状态失效。
4. 历史选择以真实交互片段为单位：保留最后一组回复所回应的用户内容，必要时回溯到原始触发消息。保留合法连续 assistant，不补造 user 消息、不改角色。
5. 当前用户消息只入列一次；Runtime Context、schema 修复提示和 Tool Result 不能混入用户可见历史。
6. 历史存在真实发送的错误陈述时保留其发生事实，不把内容升级为客观事实，不为让模型表现好而改写对话。
7. 展示层生成的 sender/time 标记不拼进正文。对于正文中的疑似自动时间标题，只做有来源、可审计的模型视图归一化：确认是展示前缀或本系统生成的伪元数据后才移出正文；保留原文及 diff。无法确认时按不可信文本处理，不能全局正则删除用户的日期/Markdown。
8. 若适配器只支持有限角色类型，使用当前框架支持的消息结构；不要自行创造 provider 不支持的 role。元数据以明确的数据块或已有上下文槽位提供，不伪造成对方发言。

**验收**

本例两处均以 2026-10-14 上午为当前时间；不会把 23:58/23:59 标题当成系统时钟。身份映射一致；历史截取规则和所有删减理由可查。

### T2：建立调用局部的事实/引用视图，阻止重复和权威混淆

**实施**

- 先检查现有 `verified`、`confirmed`、`inference`、`confidence` 的真实定义。
- 在现有字段上做只读投影，至少区分：主体、内容、原始来源、认知类型、发生时间/有效范围、可追溯来源及本轮可引用 ref。
- 不把来源验证成功、置信度高、模型摘要重复，等同于真实事件已经成立。
- 对有相同来源或可确定相同内容的重复记录做归并，保留所有来源指针。引号重复转义在展示视图修正，但不改底层记录；不能用模糊相似去重合并相反立场、不同时间或不同 Actor。
- 将已有结构化关系状态、承诺开始日期、承诺时间要求等可识别冲突聚合成简短 `conflicts`，包含具体差异及来源，不把整段相互矛盾的评估/摘要同时铺满 Prompt。自由文本无法可靠解析时保留必要的来源标记短摘录，不声称确定性程序已经理解全部语义，更不能为本例硬编码关系结论。
- 有已加载的原始消息可作校验时使用原文。必须额外核实且影响本轮操作时，由 Qwen 调用现有查询工具；不新增每轮全量事实协调 Agent，也不默认要求用户再次证明关系。
- 所有 e2/e6 等旧评估局部编号留在诊断详情，不冒充本轮有效引用。复用现有 evidence registry，保证提供给模型的 refs 可解析、属于本轮授权范围，并在工具循环/结算时仍有效。
- Cydonia 不接收内部 ref/评估链。需要保留不确定性，但不能因为去掉编号就把“摘要声称”改写成事实。
- Assistant 曾说“发过图”只证明该句话已发；附件是否实际生成/送达，读取真实媒体和发布结果。未穿某鞋不等于衣柜没有该鞋。

**验收**

本例重复记忆缩为有来源的候选事实/冲突；两处不自行把关系改成已确认或未确认；原记忆、Goal、关系表均未修改。

### T3：Goal 改用专门投影，切断历史策略，但不切断主动性

**实施**

- 保留每个有效目标的原目标、动机、原完成条件、状态、主体/对象，以及原有真实期限。
- Cognition View 额外保留工具执行所需的 ref、明确依赖和实际失败结果；大段 `last_evaluation.judgments.reason`、治理计数器不常驻。
- Reply View 不传 `execution.next_step`、`current_stage.strategy`、带话术的 `wait_condition`、建议型 blocker、旧评估意见。
- 字段不能简单一删了之：真正的权限限制、工具未完成、物品未入库等客观前置条件，投影成有来源的操作条件；“等用户主动”“先保持平静”等是社交策略，不能转换成所谓事实限制。
- `needs_evidence` 表示后台证据不足，不直接推导为现实从未确认，更不能自动产生“必须再向用户确认”的话术。
- 不按本轮是否提到某关键词来隐藏长期社交目标。Cydonia 必须仍看到当前人格/Actor 按既有规则可见的有效目标简表，并能自行决定本轮是否推进。
- Goal 可见性使用已有授权/所有权规则，不从目标中文名称猜人格归属。不同 View 允许合法筛选差异，但必须记录原因；active_count 要区分源集合数量与投影后数量，不能误报。
- 已完成目标不重复提供全量执行对象；本轮相关的已完成事实简要保留，不重新激活。

**验收**

本例 Cydonia 不再看到“用平静、非玩笑的方式直接确认……”；关系目标及原完成条件仍在。不得因用户一句冷淡回复就删除目标或禁止社交推进。

### T4：收敛 Qwen 认知上下文

**建议结构**

```text
稳定认知协议
当前身份 / 有效人格及切换授权
当前用户消息对应的事件信息
当前必要状态、操作边界
有效目标简表 + 本轮必要操作信息
相关事实 / 冲突 / 本轮可用证据索引
真实聊天历史
当前用户消息
当前阶段实际 Tool schema 或最终认知 schema
```

**实施**

- 保留认知需要的人格、切换授权、权限、有效目标和事实；不是把 Qwen 缩成只有 ToolCall 的壳。
- 普通关系聊天不常驻完整“移动→借用→穿着→拍照→归还”SOP、鞋子失败评估全文及衣柜 ID 列表。必要规则下沉到对应已存在的 Tool/能力说明，或在实际准入该能力后加载。
- 核心协议始终保留真实执行/结果边界，不能为了省 token 删除必要授权和完成判定。
- 不通过纯关键词过滤阻止模型发现工具。沿用现有目录/准入机制，给出必要的能力索引，具体工具信息在实际需要时出现。
- 记忆与摘要只保留相关的非重复内容。明确角色背景、计划、说过的话和已执行事件的区别。
- 最终认知仍按现有业务 schema 执行，不擅自删 claims、influences、output_preference_decision、goal_event_candidates 等字段。

**验收**

Qwen 能查询、执行并结算；普通私聊输入明显减少冗余，但切换人格、图像请求恢复和真实操作的必要信息仍可获取。

### T5：收敛 Cydonia 回复上下文

**建议结构**

```text
精简回复协议
完整有效 Working Persona
明确的自身 / 当前人格 / 收件人身份
本轮时钟、必要当前状态、关系记录及必要冲突
有效目标简表（无旧策略）
本轮相关的已核验事实 / 不确定信息 / 实际执行结果
选取完整语境的真实对话历史
当前用户消息
实际开放的回复内部能力 schema
```

**实施**

- 从结构化数据生成专用 Reply View，禁止整体复制认知 Runtime Context 再删除几项；禁止用正则从整篇 Prompt 裁人格/目标章节。
- 不传 Goal 治理规则、评估重试时间、技术错误长文、内部证据链、完整日程、重复 upcoming、无关 PAD 数值、内部规划策略。
- 不机械压缩人格为少数形容词。保留用户当前有效的表达偏好、冲突方式、独立性和关系边界，不因节省 token 换成统一“温柔/简短/不列点”模板。
- 身份、关系和事实优先代码取值；Qwen 不每轮重写 persona/goal/relationship，也不筛掉它认为“不适合推进”的目标。
- 关系冲突只作必要的数据说明，不强制 Cydonia 本轮讨论这个冲突。用户正在谈态度时，不把后台目标验证问题自动替换成对话议题。
- 当前场景仍按 Actor 区分；远程渠道和地点未知不能推导为同处一室。允许不改变现实状态的神态表达，不凭描述搬家、换衣或新增会议。
- 现有图像请求工具继续可用。通用正文协议只保留短的能力边界，完整参数与结果语义放在真实 Tool schema/结果中；未启用视觉不得声称看图，关闭视觉不关闭生图。

**验收**

Cydonia 仍可自行决定接话和目标推进。其输入不含 Qwen 社交策略、不暴露内部 ref；不会因为省略无关执行数据而失去人格、有效目标或当前用户语境。

### T6：修正 Fact-only Tool 参数与两套运行协议

**实施**

1. 审计 `purpose` 实际去向；Fact-only 契约不得依赖其自由文本来生成正文或构造社交限制。
2. Fact-only 可用参数限制为现有实现真正需要的路由、draft 恢复及当前有效事实/结果引用。参数名沿用实际实现，不凭此任务新造一批字段。
3. `topic_key` 如为去重/路由所需可留在服务端，不作为回复指导。`purpose` 若属于旧模式契约，应在 Fact-only 分支做明确隔离，不无差别破坏旧模式。
4. 拒绝或受控处理 Fact-only 下的正文、语气、reply_intent、社交 direction；校验不只盯字段名，防止换名字后仍进入 Writer。
5. Qwen 内部是否产生社交分析不是本轮的控制对象；关键是它不能通过工具参数、记忆片段、Goal 旧计划或隐藏字段控制 Cydonia。不要解析 reasoning_content 作为回复输入。
6. 删除“另一模型不许……”等重复宣告，保留简洁职责；不同阶段使用适配协议。模型/采样/Thinking 设置先保持已有基线，避免同时改变多个变量。

**认知阶段协议参考**

> 你负责本轮认知、必要事实查询、授权内的真实工具及最终认知结算。使用当前生效人格、Actor、状态和 Goal，不自行改写它们。当前状态、计划、历史陈述和推断按来源分别处理，未知保留未知。
>
> 普通私聊通过真实 conversation.reply 完成；该工具使用独立上下文生成正文。你可提供当前有效的事实或执行结果引用，不提供正文、语气、社交策略或目标推进话术。必要操作先执行并消费结果；未安装/未准入能力按既有发现流程处理。
>
> 待执行媒体或未发送草稿按真实工具结果恢复同一 draft。仅以实际执行/发布结果认定完成。最终认知只负责结算，遵循本次提供的 schema，不能再次发送。

以上只替换两处局部协议，必要人格切换/权限/工具条件使用原有实际规则与 schema，不以这一短文取代全部业务条件。

**回复阶段协议参考**

> 你以当前有效人格和对方私聊。根据原人格、有效目标、关系和实际对话，自主决定表达与互动，不需要另一模型提供话术。保留自己的态度，并识别真实推进机会；明确拒绝按实际语境处理。
>
> 当前时间、人物归属和已发生事件以本轮提供的权威元数据及实际结果为准。历史中的说法、摘要和计划不自动成为事实；后台待核验不等于现实否定。不要用正文创造状态变化或虚构已完成操作。
>
> 按人格自然输出正文。不要输出内部编号、推理、认知 JSON 或伪造的时间标题。神态表达不代表移动、换衣或同处一室。需要额外能力时只使用当前真实提供的工具及其结果。

不加入全局“永远短回复、禁止列点、必须安慰、不得主动”等风格限制。媒体请求与草稿未发送语义通过该调用真实开放的工具说明补齐。

**验收**

构造包含“暂不推进、先道歉”等字段的 Qwen Tool 参数，确认无法进入 Cydonia 请求；同时保留有效工具引用与 draft 恢复。修改日志写明 legacy/Fact-only 的兼容处理。

### T7：修正认知结算阶段，避免校验失败污染聊天和重复发送

**实施**

- 获取本例三次认知请求及失败原文，核验：schema 是否真的发送、阶段协议是否冲突、是否截断、解析器是否误读 reasoning_content、完整 Tool Result 是否保留。
- 工具执行阶段允许 ToolCall；回复已 committed 且进入结算时，使用“仅完成原认知合同”的阶段协议，避免继续强调“本轮必须再次调用回复工具”。不另建第三个 Agent。
- 实际绑定现有完整 schema，不只写一句“依原 schema”。优先使用项目已验证的结构化输出机制，不假定当前服务支持未验证的响应格式参数。
- 合同必要字段、当前有效引用、当前用户语境和实际发布结果必须存在。保留合法的 assistant ToolCall → tool result 配对。
- JSON 无效时按现有机制进行有限结算修复，修复阶段禁止执行发布工具，不重新生成已发送正文，不把验证消息存进对话历史。
- 发布成功和结算成功分别记录；结算失败不能将已发布状态改为未发送。后续重试恢复该次结算，不重进整轮发送流程。
- 实际发布的错误正文不能静默替换成“正确正文”再写进历史；错误诊断保留，修正属于后续真实消息，非本任务自动补发。

**验收**

复现“已 committed + 非法 JSON”，确认真实发布次数仍为一次；结算修复只影响合同。不得用代码伪造一份看似合法 JSON 掩盖模型结算失败。

### T8：加入两处输入预算与可解释诊断

**实施**

- 分别记录认知、回复、结算/修复请求；不要把多个请求 token 加起来当成单次上下文大小。
- 统计：协议、人格、身份/当前状态、Goal、事实/记忆、历史、Tool/schema 各模块的估算 token，以及服务返回的实际 prompt_tokens；估算值明确标注。
- 优先删除重复/内部诊断，其次缩减无关详情，再按真实交互片段缩短远期历史。不得字符串尾截断导致 schema、当前用户消息或 Tool 配对缺失。
- 人格关键设定、当前用户消息、Actor 映射、必要权限、有效目标本意、实际结果、输出 schema 属于受保护内容。超过预算时报告原因、按既有错误路径处理，不能无声遗漏。
- 初始实验参考：Qwen 普通关系私聊约 3k–5k；Cydonia 约 1.5k–3k。不是硬上限，也不是性能保证；涉及更多有效历史或工具时允许扩大，报告保护了什么、裁掉什么。
- 日志提供 source/selected counts、过滤理由、prompt_version、turn_id、snapshot as_of、实际模型参数、路由和最终结果。完整输入仅在授权调试模式脱敏记录，不默认收集长 reasoning_content。

**验收**

使用本例给出前后模块分布和每次真实 token；不能以牺牲人格/Goal/工具能力换取“下降百分比”。不扩展为独立监控平台。

## 7. 最终验收定义

成功不是两份 Prompt 都变短，而是：

**Qwen 拿到能做事实处理与真实执行的清晰输入；Cydonia 拿到不含旧策略、主体/时间明确、保留人格与目标的回复输入；两者通过真实 Tool Result 完成同一轮链路，且不改变原业务状态规则。**

若修复装配后仍有业务数据冲突，保留可追溯冲突并报告；若模型仍生成错误内容，记录真实失败。不要通过自动更改关系、把旧记忆“修成正确答案”、再次强制 Qwen 指挥正文或取消目标来掩盖问题。
