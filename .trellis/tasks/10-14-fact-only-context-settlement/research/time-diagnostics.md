# Time, actor, state and physical diagnostics evidence

Read-only source research; no tests, external calls or DB connection performed. Paths below are repository-relative. Findings describe inspected paths, not a guarantee about imported historical records.

## Text versus generated time/sender decoration

- **Proven generated prefix:** `apps/core-go/internal/core/provider_context.go:365`, recent-message fragment construction, runs `content = fmt.Sprintf("[sender=%s time=%s]\\n%s", sender, stamp, content)`. It starts from stored `message["text"]` (347), derives the timestamp from `created_at` using a default timezone (353), and resolves actor display information (358). WakeUp excludes this decoration. Thus this particular prefix has a code-proven producer at rendering time; do not treat the entire prefixed string as user-authored content.
- `provider_context.go:1537`, `compactRecentMessagesForActors`, preserves message text separately as `content` and generates `time`/`sender` metadata (1566 onward); it uses sender timezone with a Shanghai fallback, but formats `created_at`, not sender_sent_at. This differs from the UI's clock semantics.
- `apps/web/src/views/ChatView.vue:174` renders a separate `<time>` element. `apps/web/src/lib/message-time.ts:9`, `messageTimeLabel`, uses persisted senderSentAt + frozen offset where present; legacy fallback is viewer-zone createdAt and explicitly says sender timezone is unknown. It does not prepend the timestamp to message text.
- Stored publication provenance is real and separate: `apps/core-go/internal/core/tool_publication.go:201` inserts assistant text plus turn_id/source_fact_id/correlation_id/sender timezone-offset-sentAt/reply_metadata. User acceptance does the analogous insert in `agent_result_adapter.go:213`. `message_time.go:18` validates the sender snapshot, including completeness and zone-offset consistency.
- **Limit / unresolved origin:** narrow searches of apps/scripts/packages for literal `# YYYY-MM-DD HH:mm`, Go minute-format strings and dated markdown headings found only schedule date parsers, not a producer of `# YYYY-MM-DD HH:mm` inside conversation text. That is not proof no producer exists. No inspected path persists a `this substring was generated timestamp decoration` marker. Existing message IDs/author/time/source facts establish message-level origin; they do not prove arbitrary heading-like text inside its text was generated. Pattern stripping would lack origin evidence.

## Actor and state semantics

- `apps/core-go/internal/core/intelligence.go:347` picks self display name from identity.name, then identity.display_name, then 摇光. `buildActorProjection` at 529 constructs actor_self and current speaker. Human speaker maps to actor_user; other speaker maps to actor_b (550–559). Other actors load actor_type; Fluctlight names load identity.name (540–547). Human display name falls back to the semantic ref in this path. The self display is identity-derived, not an active profile name.
- `intelligence.go:212` reads personality runtime; WorkingProfileID can override active_profile_id at 216–222. This is a separate scope from actor identity/display name. Context serializers should avoid conflating selected profile with conversation actor.
- `provider_context.go:682`, `compactActorForSurface`, emits display_name/type/role/label and suppresses storage refs; actor_user/actor_self are explicitly retained as semantic display aliases when no usable name exists (698–703). `provider_context.go:1274` represents the speaker as target_actor for targeted context. No independent recipient display-name loader was located in the inspected projection/render paths; targeted actors use actorRefForID and this actor display projection (951–952, 1402).
- `apps/core-go/internal/core/effective_life.go:14` documents explicit known/cleared/unknown appearance semantics: missing initial-card field means unknown and must not restore a cleared later field. `readEffectiveLifeSnapshotWith` inserts unknown defaults at 175. `provider_context.go:785`, `compactBodyFieldsForSurface`, omits unknown fields, preserves cleared as `{status:"cleared"}`, emits known value only when present/non-null. Alternate body row compaction turns cleared into literal `"cleared"` (2355–2367), so consumers currently see two representations.
- `provider_context.go:540`, `cleanPromptValue`, drops null/empty string/empty containers but retains false and zero via the default branch. `compactBodyFieldsForSurface` also preserves known false because it checks presence/non-null, not truthiness. Preserve these distinctions during reduction.
- `apps/core-go/internal/core/life_context.go:176` selects confirmed/inferred events only inside start/end and explicit expiry, prioritizing confirmed. Effective expiry is event end capped by expires_at (187–189). Presence selection independently requires active status and nonexpired expiry (202); overlay includes current_task/user_presence with its own expiry (210). Schedule current-item expiry uses end_at (249). This is object/scope expiry, not a universal timestamp on all state fields.
- `effective_life.go:250`, `readActiveLifeActivities`, reconciles expired activity runs on near-present reads, then queries scheduled/in_progress/deferred with active_until > at and a still-live authority event (260). Published activity entries include profile_id, kind/status, not_before, ready_for_resolution and request, but **not active_until** (274–280). `provider_context.go:733` further allowlists activity fields. A fact-only design can retain activity validity without treating status alone as permanent authority; current output lacks its explicit deadline.

## Physical request diagnostics and local verification seams

- `apps/core-go/internal/core/eino_model_request_policy.go:31`, `physicalRequestOptions`, computes task-owned physical choice/catalog/format policy immediately before each request; installed tools force response-format omission (73). `applyPhysicalModelRequestPolicy` (106) uses `WithRequestPayloadModifier` (122) to inspect final adapter JSON and overwrite string tool_choice, enable_thinking and remove response_format. Final repair has a separate modifier (169–181) removing tools/tool_choice/parallel_tool_calls and disabling thinking. This is a concrete raw-payload seam for a small allowlisted effective-request record. Modifier composition/order needs explicit verification before choosing implementation; do not assume another modifier automatically composes.
- Generate and Stream both call physicalRequestOptions (`eino_model_runtime.go:96,208`) and record input diagnostics (`117,236`). `recordEinoModelInputDiagnostic` (437–499) already writes adk.model.input with run_id, model_call_id, sequence, role, counts, source_map and context versions, but not effective sampling/tool_choice/format. Budget diagnostics at 362–391 use a reconstructed messages/tools/response_format estimate, not final raw JSON.
- `diagnostics.go:94`, WithPromptDiagnostics, bounds and redacts its metadata; `redactDiagnostic` at 266 hides secret-key fields and image payloads. It **does not inherently remove private natural-language prompt text**. For the requested effective config record, select only approved fields (choice/format type or presence/sampling and request identity), rather than passing full raw payload through this redactor. RecordDiagnosticEvent at 678 persists through existing redaction at 697.
