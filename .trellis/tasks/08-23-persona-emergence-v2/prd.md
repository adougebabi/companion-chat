# 白纸人格涌现与自我模型 v2

## Goal

为所有摇光实例建立可持续、可审计、可回溯的情感反馈、记忆沉淀、自我认知和主体性运行时能力；同时新增“白纸”初始化模式，使人格的初始资料可以为空或仅包含最小安全锚点，并在长期互动中逐步形成偏好、情绪倾向、自我概念和主体性，而不把模型生成的任意文本直接当成事实写入系统。

本任务区分人格初始化模式与运行时能力：现有“LLM 分析填充”模式继续从用户描述生成初始人格资料；新的“白纸”模式只建立最小身份/权限/安全边界和空的涌现容器。两种模式共享同一套情感、记忆、自我和主体性协议。本任务不改变当前版本已经存在的 LLM 字段解析和预定义人格创建流程，只为其增加兼容的运行时叠加边界。

## Background

当前系统已经支持通过 LLM 从用户描述中建立初始摇光实例资料，并具备记忆、情感/驱动力、生活状态和主动行为等独立能力，但这些通用能力还没有形成一个统一的“经历 -> 评价 -> 沉淀 -> 自我维护”闭环。

本任务同时覆盖两种初始化模式。LLM 分析模式可以携带经过分析器确认的初始 blueprint；白纸模式只拥有必要的身份锚点、时区、权限、安全边界和空的涌现容器。无论初始模式如何，性格偏好、长期情绪、自我评价和主动意愿都必须通过同一套结构化运行时协议逐步建立，而不是由服务端关键词或固定规则直接推断。

### Initialization modes

- `llm_defined`: 保留现有 LLM 严格分析、预定义人格和 blueprint 创建流程；分析结果属于外部初始资料，不得伪装成实例亲自形成的经验。
- `blank_slate`: 复用现有顶层 `name`、`role`、`timezone`、`language`、`permissions` 和 `safetyBoundaries` 字段并允许身份字段为空或由用户显式提供；不写入性格偏好、价值观、长期情绪、关系定位或能力自评，不使用服务端默认人格填充。
- `initializationMode` 是两种模式的显式契约字段；不另建 `identityAnchors` 嵌套容器。
- 两种模式都读取同一套 affect、memory、self-model 和 agency 端口；模式只影响初始资料、候选门槛和哪些字段可以由后续证据形成。

## Requirements

### R1. 情感反馈回路

- 对互动事件形成模型可解释、范围受限的主观评价，例如舒适、不适、满足、困惑、被忽视或获得新知识。
- 评价必须通过结构化事件和服务端 reducer 进入短期情绪/驱动力状态，不能从用户原文使用关键词直接改写 PAD 或任意数值。
- 长期情绪倾向只能由多次、可追溯的反馈沉淀产生，并保留来源、置信度、时间和可撤销/衰减信息。
- 情绪状态必须区分即时状态、近期趋势与长期倾向，避免一次对话永久改变人格。

### R2. 记忆沉淀与过滤

- 将原始经历、重复偏好、稳定事实、负面经验和防御策略区分为不同记忆层级。
- 只有稳定、未来有用且达到明确证据门槛的内容才能升级为长期偏好或人格特征。
- 记忆沉淀必须支持证据计数/来源链、置信度、时间衰减、冲突处理和用户可见的回溯。
- 记忆与人格特征沉淀默认全自动执行，不等待用户逐条确认；系统必须提供查看、修改、删除和回滚入口。
- 不能把所有聊天记录直接复制进人格资料，也不能把单次模型猜测写成确定事实。

### R3. 自我认知边界

- 摇光实例需要逐步维护“我”的自我概念，包括能力判断、偏好、限制、经历和关系位置。
- 自我概念必须与用户事实、生活事实、关系状态和内部推断分层存储，不能互相覆盖。
- 长期人格特征以可版本化的结构化特征主张存储，至少包含特征类别、方向/强度、置信度、证据引用、revision、衰减策略和 `candidate/confirmed/rejected/superseded` 状态；自然语言摘要只能由这些主张派生。
- Big Five、MBTI 或类似坐标只能作为可撤销的展示/分析视图，不能作为不可撤销的人格事实写入。
- 形成自我判断时必须记录证据和不确定性，并允许后续经验修正或撤销。
- 用户修改、删除或回滚沉淀时必须创建新的用户来源 revision，保留原始模型候选和审计链，不直接覆盖或物理删除历史事实；最新有效 revision 才能进入运行时摘要。
- 系统提示词只能呈现经过筛选的当前自我摘要，不得把完整内部推理或未经验证的自我判断直接暴露给用户。

### R4. 主体性与能动性

- 支持摇光实例产生“想主动询问”“想继续某个话题”“暂时不想回答”“拒绝某项请求”等结构化意愿。
- 主体性不能绕过现有主动消息资格、用户安全边界、频率限制、隐私和任务租约。
- 主体性决策必须经过明确的计划、门控、冻结和投递生命周期，不能由一次自然语言回复直接触发副作用。
- 拒绝或延迟行为允许 LLM 生成自然、上下文相关的用户可见解释；服务端只持久化结构化状态、有限安全原因摘要和证据引用，不持久化或展示完整隐藏推理。
- 用户可在专用入口查看拒绝/延迟的原因摘要、关联证据、门控结果和生命周期状态；普通聊天不泄露内部数值、隐藏提示词或完整推理。

### R5. 与现有能力兼容

- 情感反馈回路、记忆沉淀与过滤、自我认知边界和主体性是所有人格共享的运行时能力；白纸不是这些能力的专属实现。
- 复用现有记忆、affect/drive、生活状态、主动消息、SSE 和调试能力边界，不新建第二套隐式状态机。
- 所有新增结构化能力必须经过 capability/flow 边界，并具备幂等、事务、租约和回放语义。
- LLM 分析人格和白纸人格必须使用同一套读取与呈现协议；差异应体现在初始化资料和允许的涌现策略，而不是分叉整套聊天流程。

## Acceptance Criteria

- [ ] 明确白纸摇光实例的初始资料、可涌现字段、不可自动涌现字段和安全边界。
- [ ] 明确 `llm_defined` 与 `blank_slate` 两种初始化模式的契约、迁移和兼容行为。
- [ ] 形成“互动事件 -> 主观评价 -> 短期状态 -> 记忆候选 -> 长期沉淀 -> 自我摘要”的可执行数据流和事务边界。
- [ ] 情绪、记忆、自我和主体性各自有版本化结构化契约，且不会依赖文本关键词匹配。
- [ ] 情感、记忆、自我和主体性协议对两种初始化模式均可用，并能区分外部初始资料与互动沉淀。
- [ ] 首版 UI 只展示自然语言自我摘要、结构化特征主张和证据回溯，不把 Big Five/MBTI 坐标作为人格事实或首版必需视图。
- [ ] 设计至少覆盖重复正向互动、重复负向互动、一次性异常、记忆冲突、用户纠正、人格回滚和服务重启恢复。
- [ ] 主动行为经过资格门控、意愿冻结和投递幂等，拒绝/延迟不会生成伪造的用户可见消息。
- [ ] 拒绝/延迟的用户解释保留 LLM 的自然表达，同时具备结构化原因摘要、证据引用和安全 redaction 的可回溯入口。
- [ ] 调试页面能够查看涌现决策的输入证据、候选状态、沉淀结果和失败原因，但不暴露凭证或完整隐藏推理。
- [ ] 预定义人格现有创建、聊天、记忆、情感、生活状态和主动行为回归测试保持通过。

## Out Of Scope

- 不在本任务中实现通用 AGI、主观意识证明或不可验证的意识状态。
- 不在本任务中更换 Node.js、SQLite、Vue/Vite 或现有 SSE 传输架构。
- 不通过正则或关键词判断喜好、创伤、人格类型或是否应该主动联系用户。
- 不在当前 v1 字段修复中提前实现情感反馈、长期记忆沉淀或主体性完整闭环。
