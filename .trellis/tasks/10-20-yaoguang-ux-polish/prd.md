# 摇光全站 UI/UX 体验打磨

## 目标与用户价值

以产品体验负责人的标准，主动完成真实运行产品的全站体验检查与正式前端打磨，让个人用户在桌面和手机上顺畅交流、阅读人物生活、创作和管理配置。保留已认可的 v3／鼠尾草青绿方向及现有全部功能，交付经过实际画面和连续操作复看的整体效果。

## 背景与确认事实

- 用户授权自主调整局部细节，仅重大风格、导航和业务语义变化集中确认。已批准创建任务并进入规划。
- 正式入口为 apps/web/src/main.ts → App.vue → v3/proto/app.js，实际样式为 styles/v3-proto.css；不恢复旧前端。
- 路由注册共有 104 个 URL 模式（含别名），不能等同于 104 个独立页面。主要工作区为交流、生活成长、世界人物、创作治理。
- 真实 NAS 入口为 http://192.168.1.20:13001/。本轮已亲自打开角色库、对话、日程、日程建议抽屉、系统设置、模型连接；完成日程抽屉取消和交流→管理切换。尚未完成全站走查。
- 当前部署 SHA 未知；旧 NAS 回归与本地最新修复不能替代当前部署验证。本地未发现可用 Web/Core 监听。
- 开始时已有两份 NAS 证据修改及未跟踪 profile-types.ts，本轮保留。
- .impeccable.md 中的历史蓝色/玻璃表面描述与最新要求不一致时，以用户的 v3 鼠尾草青绿要求及现行 v3 tokens 为准。

## 需求

### UX-01 全站覆盖与产品主线

建立逐路由/页面族覆盖表，按交流阅读、人物生活、世界创作、设置诊断推进。每页主动检查视觉、布局、层级、阅读、路径、表单、反馈、动效及跨页连续性。Bug 检查仅处理阻断当前体验的问题，其余登记，不持续挤占 UI/UX 工作。

### UX-02 共享体验规则

收敛页面标题、正文宽度、间距、列表与卡片、主次操作、链接状态、表单标签与帮助、空态/加载/错误/成功、弹层/焦点/取消、滚动及减弱动效偏好。保留所有动作和数据访问能力；技术原文渐进披露，未知状态保持未知。

### UX-03 逐页实际改进

以现场观察和源码差距共同决定修改：角色库卡片的进入与管理层级；对话重复标题与范围信息、异常/头像/等待反馈；日程重复信息和时间输入负担；设置入口同质描述和连接长表单。上述为初查线索，已在本地修复的项不重复实施。继续覆盖其余页面，不只修这份初查清单。

### UX-04 连续性与功能保留

检查列表→详情→编辑→取消/返回、工作区切换、窄屏全部导航、人物切换、草稿与异步反馈隔离。保留原服务权限、CAS、幂等、未知结果恢复、事实/计划/候选边界。不能以视觉简化隐藏功能或宣称尚未发生的业务完成。

### UX-05 可核验交付

修改进入当前正式前端。用真实 NAS 产品建立现状基线，用当前正式构建连真实 API 复验修改；必要的缺数据/失败边界可用明确标注的受控数据补充。逐项记录实际运行版本、画面和操作证据，明确尚未覆盖项，不以构建/接口/按钮可点击代替体验完成。

## 验收标准

- AC-01 每个注册路由归入覆盖表，记录实际 URL、对象来源、设备、页面状态、观察、修改与复看结果；无真实对象的参数页明确标阻塞，不充当通过。（UX-01/05）
- AC-02 各工作区主要页面完成桌面与实际 390px 核验；必要时补 320px/中间宽度。无非预期横向溢出，正文与主操作可达，弹层头尾可达且滚动所有者明确。（UX-02/03）
- AC-03 各主要页面族完成至少一条连续路径，记录返回位置/草稿/焦点/取消结果；写入仅使用专用隔离对象，模型或发布类动作不对日常数据随意触发。（UX-04）
- AC-04 共性改动落实共享组件/样式及交互约定，状态和技术详情可理解且可查，全部原功能仍可达。（UX-02/04）
- AC-05 修改通过适用类型、正式构建及定向回归，完成实际画面复看与 console 检查；真实 API、受控回放、部署后验证分别报告。（UX-05）
- AC-06 最终由主代理先完成全站体验检查，再交付用户确认整体效果；环境阻塞如实列出，不称全站完成。（UX-01/05）

## 范围外与风险

不替换设计方向、不删功能、不擅改导航结构或业务语义、不做无关后端重构、不随意改写用户角色生活。正式 NAS 发布与重启属于交付部署步骤，待具体改动及验证结果可审阅后确认。当前真实产品与本地 HEAD 可能不同，须分清已修未部署和待改；缺数据页面、真实模型长期任务和环境访问限制可能影响验证，需要单独留证。
