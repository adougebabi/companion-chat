# 全站体验打磨设计

## 方向与边界

保留 v3 的鼠尾草青绿 tokens、明亮安静的工作面、交流/管理双工作区和现有路由。以减少阅读与操作负担为目标，先建立清楚的标题、内容、次级信息与动作层级，不新增竞争性的颜色/阴影系统。重大导航或业务含义变化另行集中审阅。

## 实现拥有者

- apps/web/src/styles/v3-proto.css：当前 token、布局、共享控件、响应式与动效。
- apps/web/src/v3/proto/app.js、components/shell.js：页面标题、范围、返回、主滚动面、导航反馈。
- components/forms.js、cards.js、overlay.js、async-page.js、toast.js：可复用控件与反馈；pages/provider-page.js 及领域异步拥有者要一并核对，避免只改一层。
- components/semantic-fields.js、records.js、共享显示字典：可读摘要与折叠原文。
- pages/real-*.js 与 providers：仅在领域专属呈现/交互需要时修改，不恢复旧 Vue 页面。服务数据和持久状态的权威继续在现有 provider/client/Core。

## 体验组织

每页先读当前信息和主要动作，再逐步披露编辑、治理与技术详情。布局按内容目的选择，避免一律堆叠同型卡片。表单按用户任务分组、说明属于哪个保存范围，错误留在动作发生处，草稿与原提交身份不被轮询覆盖。时间输入显示本地可理解字段，若修改则适配回原带 offset 契约，不能改变实际时刻或猜测时区。低频动作可以折叠但必须可发现、可键盘操作。

## 连续性和兼容

保留路由及别名、交流/管理分类、角色作用域和原返回规则；统一视觉不会改变后端授权。原版本/CAS、幂等、提交未知恢复、取消语义、候选和已接受、计划和实际、空与未知均不变。弹层的关闭、Escape、焦点恢复、Tab 范围和页面滚动统一检查。

## 运行和证据

NAS 当前真实页负责建立现状基线。正式 dist 优先通过本地同源静态代理连接真实 NAS，延续原 Origin/CSRF/Cookie 流程；先核验代理能力，再宣称真实联调。现有 serve-preview 只有跨源 API 地址，不解决认证/CORS，不能直接当可用方案。Vite 现成代理可用于开发辅助；最终画面必须来自正式构建。

现成 CUA 支持显式 viewport；核验实际 window.innerWidth、document client/scrollWidth，并在视口变更后重新观察页面，不能只凭截图尺寸。真实 UI 截图目前以工具输出为证，若可用导出再保存，不伪造路径。受控回放只补无法安全生成的边界，不能替代真实主流程。

## 协作和回退

遵守当前 AGENTS：探子仅做只读定位/独立核验，主代理亲读将改代码、进行取舍、修改和最终验证。避免默认实施代理与用户限制冲突。每批改动按共享规则或页面族形成可独立回退的 diff；保留开始时 WIP。正式部署待可审阅结果后确认，不自动迁移或改后端环境。
