# 摇光当前有效自我、动态生活与上下文装配闭环

## Goal

让摇光的当前有效自我与虚拟生活形成可持续的业务闭环：意愿影响选择与计划，正式行为和事件产生结果，结果更新权威状态，Main、WakeUp、查询、摘要和生图随后读取一致的当前事实。保留不行动、暂缓和空闲的选择。

## Background and confirmed baseline

- 当前正式运行时是 Go Core、Eino 原生 Agent/Tool Loop 和 PostgreSQL 权威状态。Main/WakeUp 已共用 ContextProjection、Prompt 装配和 Tool 执行入口；完整人格来源与编译画像分离。
- 初始化保存原文、结构化分析、Foundation、初始 Goal/Intention 和编译画像；当前 life_profile.appearance 仍承载静态外观描述及穿搭偏好，没有持久衣柜、当前穿着或身体变化权威记录。
- life_habits 是初始化字段，但画像编译的逐项覆盖检查读取 habits；编译源仍含完整 life_profile，可变事实可能被编进画像。对应证据见 research/baseline.md。
- Schedule/Event/Presence、Affect、Goal/Intention 和 Tool receipt 已有不同权威来源；初始日程只以 identity/life_profile 生成，intention.due 的 Agent 结果引用未贯通 ActionOutcome 结算。
- persona.detail 默认读取有效 overlay，但尚不能消除原始卡中已过时的当前外观含义；外观 Tool snapshot 读取 identity.appearance，而初始化规范存于 life_profile.appearance。

## Requirements

### R1 语义归属与当前有效自我

- 保存原文、结构化来源、版本与历史；原文和旧摘要不作为当前状态兜底。
- 区分受保护身份/价值/边界、可更新偏好习惯、共享身体外观、当前穿着、衣柜物品、意愿计划、事件结果和历史。保留未知、明确清空、取消、false、0、空集合的语义。
- Working Persona 是由当前有效稳定来源编译的派生产物。迁出发长、当前衣服等可变事实；短稳定偏好和行为例外不丢失。画像失败不发布不一致版本；单次换装和身体变化不触发无关人格重编译。
- 同一 Fluctlight 的身体、衣柜和真实事件共享；人格的审美、习惯和意愿按现有 profile 作用域。人格切换不得恢复旧身体或衣着。

### R2 持续物品、搭配与穿着

- 衣物有稳定 ID、描述/类别、归属或使用关系、可用状态、获得来源和版本；搭配引用衣物，当前穿着引用合法衣物或可追溯的初始已知记录。
- 初始化只把明确拥有/穿着的衣物入库，未知所有权不伪造购买，喜欢或想买不视为拥有；重试不重复入柜。
- 查询支持物品列表、详情、搭配和当前穿着，并说明分页/匹配范围，未命中不等于完整不存在。
- 获得必须有经校验的有效来源和成立结果；购买完成不自动穿上。换装更换指定部位，整套更换移除旧衣物，未涉及部位保留；失去或不可用衣物不得继续正常穿着。

### R3 意愿、计划、活动与事件结果

- 沿用 Goal/Intention；可创建、读取、调整、暂缓、取消、完成，并关联计划、活动与 ActionOutcome。同目标重复出现可更新，不同目标不按类别合并。完成由结果确认，不能由到期或计划替代。
- 日程区分已确立约束、可调计划、实际活动和完成结果。身份不自动成为每日课程或固定模板；生成和重排考虑持续意愿、现实约束、当前状态与最近结果，允许空闲与合理重复。
- 通过正式 Tool/领域通路处理即时换装、临时发型、持续剪发、虚拟购物、有效身体事件及其结果；持续活动按现有时间/工作流推进。没有根据模型过去式或计划直接创建既成事实。
- 情绪由有效事件更新并在下一轮参与判断；情绪阈值不强制绑定具体行为。伤势影响相关活动约束，跨日和切换不被重置。
- 虚拟购买只产生虚拟物品与结果，不进行现实支付或下单。外显消息仍遵循原有自治权限。

### R4 正式 Agent、Tool 和上下文

- Main 与 WakeUp 通过各自正式任务及注册的原生 Tool Loop 使用同一权威业务实现；Tool 可用最小合法上下文独立调用，执行时再校验身份、作用域、权限、前置条件和幂等。
- Tool 的完成、接受、延后、拒绝、冲突与失败准确返回。模型必须收到真实 Tool 结果才能继续决定；外层不二次执行或伪造结果。
- 每轮按主体、profile、时点和任务装配当前画像、生活/情绪/身体/穿着、必要关系/约束、持续意愿、较早摘要、近期原文及恰好一次真实输入。完整衣柜和历史按需查询。
- 当前事实不由 Prompt 渲染创造；工具续接消费已提交结果且不重新注入旧初始化事实。实际 Provider 请求包含预算、来源、版本、选取和排除诊断，敏感内容默认脱敏。

### R5 查询、摘要、视觉与存量

- 人格详情默认给当前有效设定；历史/原始查询显式标注时点，不能把过时当前事实当作现在。摘要只记录过去的决定、纠正、承诺和真实结果，不写权威状态，也不混淆想买、已计划、购买失败、已拥有、已穿着。
- 图片任务冻结当前身体、穿着、物品描述和版本/拍摄时点；历史视觉参考不恢复旧发长或衣物，过时生成图不标为最新当前状态。
- 提供存量预览、幂等迁移、诊断与失败恢复；优先保留最新有效领域事实，证据不足保留未知。迁移不得重复入柜、恢复已替代事实或触发未授权的生产付费调用。
- 删除或替换会覆盖当前事实的旧读写路径；保留原文与历史证据。

## Acceptance criteria

- [ ] A1 有能力接线表、初始化语义去向表、实际 Provider 请求证据；可区分提取、存储、读取、预算和适配断点。
- [ ] A2 初始长发经有效剪发变短后，Main、WakeUp、详情查询和图片输入只把短发视为当前；“喜欢长发”仍可为偏好，旧长发可按历史查询。
- [ ] A3 衣物与搭配独立持久；初始化、获得、重试、不可用、借用/未知归属、分页、并发换装均得到正确结果。地点/日程/人格切换不自动换衣。
- [ ] A4 “没有靴子→形成或调整意愿→安排并完成虚拟购买→入柜→后续独立查询及换装复用同一 item”可追踪；失败购买不入柜或完成意愿。
- [ ] A5 单次穿着不修改普通习惯；明确习惯决定更新后当前穿着暂不变，旧衣物仍在，后续选择可采用新倾向。
- [ ] A6 intention.due 经正式 Agent/Tool 产生的 outcome 带正确引用并结算 attempt；日程计划不能冒充活动完成，跨日未完成事项持续可见。
- [ ] A7 事件→情绪持久化→下一轮认知有效，且无固定情绪行为模板；身体事件影响相关活动并跨日保留。
- [ ] A8 所有新增/修改 Tool 在真实测试存储上独立执行，覆盖成功、拒绝、未找到、冲突、延后、失败、重试；Main/WakeUp 原生 ToolCall→执行→结果回填→后续模型消费有正式入口证据。
- [ ] A9 摘要、详情、记忆、媒体输入不把旧状态作为当前；摘要有范围/来源且失败不丢未覆盖原文；最终 Provider 请求与图像任务输入有脱敏样例和版本证据。
- [ ] A10 提供预览/执行迁移命令及本地或可丢弃环境实测结果、失败恢复说明；新增与受影响测试零失败零意外 SKIP，缺少真实 Provider/ComfyUI 环境单列 BLOCKED。
- [ ] A11 报告首轮与工具续接累计请求的字符、字节、估算/实际 Token、Tool/schema 成本与调用次数，并列出删除的冲突旧路径。

## Out of scope

新 Agent OS、通用世界引擎/事件溯源、独立决策模型、每轮筛选 Agent、频繁强制生活事件循环、现实电商支付/物流、医疗仿真、全局格式迁移、整体运行协议重写、为了省 Token 关闭有效功能。

## Planning decisions

- 作为一个任务按依赖实施与整体验收，不拆成需要逐阶段批准的多个用户任务。
- 复用当前 Go Core、Eino、Capability、Goal/Intention、Schedule/Event、Affect、Visual Identity、事务/幂等/权限机制。
- 真实外部模型与 ComfyUI 验证在可用环境运行；不可用时明确 BLOCKED，不用脚本化模型冒充真实模型。
