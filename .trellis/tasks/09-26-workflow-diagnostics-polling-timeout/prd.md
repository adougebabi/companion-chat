# 修复诊断中心工作流列表高频请求与超时

## Goal

诊断中心继续提供及时的模型运行、事件与生命周期信息，同时避免反复触发耗时的工作流运行时列表查询；运行时无响应时，工作流控制区应及时给出明确反馈。

## Confirmed facts

- `DiagnosticsView.vue` 在页面可见时每 2 秒调用 `loadDiagnostics()`；该方法当前每次都调用 `client.listWorkflows()`，即使用户没有打开工作流控制区。
- `/api/diagnostics/workflows?query=` 最终调用 Core `WorkflowList`，后者对 Temporal 执行最多 200 条的列表查询；当前没有独立的短超时。
- 本机没有正在运行的项目服务，无法直接测量用户环境中的实际 Temporal 延迟。

## Requirements

1. 诊断中心其他数据保持既有自动刷新；非工作流区的自动刷新不得请求工作流列表。
2. 进入工作流控制区时读取一次列表；用户可手动刷新。慢请求期间不再发起第二个列表请求。
3. 工作流列表失败或超时时显示工作流专属反馈，不阻塞模型运行、事件和生命周期数据的读取。
4. Core 为 Temporal 工作流列表查询设置短而明确的时间边界，并保留既有 Owner 授权、查询参数及列表上限。
5. 不改变工作流状态、历史、暂停、恢复、取消、重启和 Reset 命令的语义。

## Acceptance criteria

- [x] 在诊断中心的非工作流区经过多次 2 秒刷新，`/api/diagnostics/workflows` 请求数为零。
- [x] 进入工作流控制区产生一次列表请求；定时刷新不增加该请求数；点击“刷新工作流列表”产生一次请求，进行中重复点击不会并发请求。
- [x] 工作流列表请求失败时，该区显示专属提示，其他诊断数据仍可更新。
- [x] Core 传给工作流运行时的列表查询带有不超过 5 秒的 deadline；运行时阻塞时接口在边界内返回可诊断错误。
- [x] 前端测试、Go 针对性测试、typecheck 和构建通过；工作区不包含调试代码。

## Out of scope

- Temporal 服务部署、可见性索引调优、工作流历史查询优化和工作流管理命令改造。
- 修改诊断中心其他数据源的 2 秒刷新策略。
