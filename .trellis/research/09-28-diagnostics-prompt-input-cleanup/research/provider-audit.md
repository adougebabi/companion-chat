## Already narrow or no active model path

- Initialization model input contains Owner description without Core IDs (`app.go:344-398`), though ordinary diagnostics intentionally use metadata-only (`provider.go:919-965`; `.trellis/spec/backend/fluctlight-diagnostics-contract.md:81-92`). Physical ADK diagnostic row bypasses that wrapper (`eino_model_runtime.go:94-105`), making current policy inconsistent. User chose all non-image text visible, so both paths must converge under a revised spec.
- Conversation summary, segment and daily memory use narrow role/text/time/attachment or semantic segment payloads (`conversation_summary.go:332-340`; `model_tasks.go:186-240`); existing tests cover raw storage IDs staying out (`conversation_summary_test.go:48-62`; `conversation_segment_test.go:41-71`).
- `ProcessAutonomyAction` replays a frozen command without a new model decision (`workflow_ops.go:15`). Production has no separate `action_realization` model call. Legacy takeover judge/reply and visual vision/patch have no production caller; record the dormant state, but avoid broad rewrites unless they become active.
- Conversation output schema repeats visible text and related plan fields at root and under `response_plan`, with different consumer precedence (`provider_schemas.go:179-194,244-263`; `agent_result_adapter.go:107-117`; `intelligence.go:675-760`). This is a response-contract duplication rather than an input metadata leak; include in the cleanup only after a conflict fixture proves the observable defect.

## Diagnostic display versus actual request

Visual Identity, schedule and media quality text may be made as intermediate JSON then converted to readable YAML/TOON before Provider I/O (`visual_identity_agent.go:165`; `model_tasks.go:304`; `media_quality.go:147`; `internal/ai/prompt/format.go:20-68`). Vue serializes the whole prompt container as JSON (`apps/web/src/views/DiagnosticsView.vue:80,209`). Assertions must inspect `messages[].content` or multimodal text parts on captured HTTP wire, not just the page's outer braces. Physical Eino diagnostics currently omit `UserInputMultiContent` (`eino_model_runtime.go:890-906,1058-1085`), so diagnosis and wire need a comparison test.

## Timeout deferred by user

One `context.WithTimeout` covers the full Agent loop (`provider.go:342`); no five-round production cap (`internal/ai/agent/loop.go:248-270`). UI empty binding is 60 seconds; DB/backend fallback 120 seconds; initialization minimum 600 seconds. The persisted running value is unknown locally. User asked to try configuration first and defer timeout code changes. Increase `generic_llm.timeout_seconds` above the expected cumulative model+Tool+queue latency, bounded by relevant Temporal Activity timeout, and measure before revisiting implementation.
