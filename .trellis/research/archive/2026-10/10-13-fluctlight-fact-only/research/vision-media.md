## Disabled/unconfigured behavior and durable compatibility

- Ordinary generation already has non-blocking skip: `media.go:318-334` converts non-cancellation quality infrastructure errors to `mediaQualityVerdictSkip`, records diagnostic reason, persists `skipped` against candidate SHA/job, then continues storage/publishing/completion (`media.go:365-393`). This is the reusable path for explicitly disabled/unconfigured vision **before** model invocation. Do not synthesize pass/observed facts. Cached pass/skipped reuse is SHA-bound (`media.go:313-315`), so enabling vision later will not automatically re-review previously skipped same candidate without policy change.
- Current quality enums `media_quality.go:14-20`: `pass`, `retry`, `reject`, `skipped`, `retry_accepted`. First non-pass retries once; second retry/reject delivered as retry_accepted (`media.go:337-360`; `media_quality.go:198-210`). `prepareMediaQualityRetry` fence: matching `provider_job_id`, status running, `quality_retry_count=0`; reset job and pending (`media_quality.go:288-304`). Verdict persistence: matching job/status (`277-285`). Vision disable should not trigger retry/regenerate.
- Current missing visual Provider config returns accepted waiting + `provider_config_pending` / `visual_identity_agent_role_missing` (`visual_identity.go:1085-1093`). This waits indefinitely: workflow terminates only completed/failed/cancelled/awaiting_review (`workflow.go:246-249`), otherwise sleep 5s and ContinueAsNew. For disabled/unconfigured image inspection, `awaiting_review` is an existing compatible terminal session checkpoint; classifier treats it as no action (`visual_identity_agent.go:426-429`). It can preserve candidate without promotion. A new status needs classifier, workflow termination, reconcile (`workflow.go:1779-1848`) and output schema (`visual_identity_tools.go:177`) changes. Existing `awaiting_review` is already used for max_attempts and renderer config (`visual_identity_tools.go:263,430`).
- Creation is a single DB transaction and inserts textual/default runtime data before enqueuing visual (`app.go:1895-1915`); ensure function performs no provider calls. Ensure errors still abort nonvisual creation, so a new vision config requirement must not return an error here. Keep generation/identity intent or deferred human review optional.
- `visual_identity_agent.go:21-22`: “A queued media intent is accepted work, never a completed image.” Agent final response is cross-checked with reloaded durable state (`175-180`). On no action state, it returns before model (`118-120`). This supplies a useful disabled checkpoint escape.

## Promotion fences, manual tools, and unverified assets

- All production direct and Agent tools use ExecuteTool. `tool_execution.go:96-110` explicitly supports business tools without an Agent run and invokes capability-owned authorization before preparation/replay. `visual_identity_tools.go:77-102` routes direct target session to generate/review/finalize. There is **no inspection provenance requirement** in commit_review: callers can supply valid observations and accepted decision without this function checking a model saw the image. `executeVisualIdentityCommitReviewTx` at 343-398 validates bounded observations/decision, session owner, matching replay, running/queued, completed media intent, ready asset + owner. At 405 it CAS-writes only `decision IS NULL`; at 414-421 it writes timeline saying “正在查看真实候选图片” / “视觉理解完成” even for direct tool submission. Gate/manual-confirmation semantics must cover this entry; preserve explicit owner confirmation as distinct provenance rather than claiming a visual call.
- Accepted review -> `visual_identity_tools.go:461` / `promoteVisualIdentityCanonicalTx` (`visual_identity.go:1251-1285`). Locks profile revision FOR UPDATE; increments immutable revision; sets active canonical; creates deterministic character-sheet media/workflow intent; session update fence requires current attempt and queued/running, rows affected exactly one. This is the canonical fence to preserve. Disabled/skipped quality does not independently satisfy identity review, and should not auto-promote.
- Finalize (`visual_identity_tools.go:549-610`) requires character_sheet_pending, completed character media intent, ready asset + owner; sets active character_sheet asset, revision linkage, session completed with CAS and settles ActionOutcomeCompleted. It does **not** visually inspect character-sheet pixels; quality acceptance is its only image check, and skipped quality is enough for ready media. A vision-disabled candidate/character sheet can remain durable ready media while visual identity stays awaiting_review; it should not receive automatic confirmed canonical semantics.
- There is no current `media_assets.verified` or vision-validation status field. `migrations/runner.go:396` has status (pending default) / ready_at, bytes/hash/ownership; generator writes ready at `media.go:369`. `media_assets.status='unverified'` is technically varchar but breaks every ready-only read (including serving and inspection), so use separate epistemic verification metadata / existing skipped quality, not overload asset readiness. Identity profile missing/renderer_config_pending/active is separate from asset storage readiness. “Unverified asset” can be preserved as **ready bytes + skipped/unverified inspection**, withheld from canonical until proper review/explicit confirmation.
- Important intent-as-observation bug risk: `media_workflow_policy.go:199-228` / `validateMediaReferenceAsset` reads `media_intents.prompt` via ready asset, then `source["purpose"] == "visual_identity"` immediately permits subject reference. Scene/object/animal checking (`180-197`) trusts frozen capture plan `human_presence`, `self_in_frame`, primary_subject; `validateLatentIdentityReference` (`334-343`) trusts prompt appearance snapshot. These are ownership/capture-intent consistency checks, **not actual-pixel validation** despite `*_unverified` error labels. Gate must not assert these checks observed picture contents. `media.go:210` current-capture unverified error is similarly policy/reference readiness, not a new model call.
