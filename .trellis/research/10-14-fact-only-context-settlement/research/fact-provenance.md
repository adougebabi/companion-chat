# Provenance and structured comparison evidence

Read-only source inspection; no tests executed, no database access. Paths below are relative to repository root. Scope: additional evidence beyond the existing reply/provider context map.

## What verified means

- `apps/core-go/internal/core/memory_provenance.go:39`, `resolveMemorySourceTx`, explicitly states: “Source resolution proves a reference exists in the authorized Fluctlight scope. It does not claim that the source semantically supports the derived text.” It resolves inbox sequence/fact IDs, conversation messages, action outcomes, authenticated commands and owner confirmations. Message resolution records `md5(msg.text || msg.attachment_refs::text)` and original message ID (`:71`); outcomes record revision and request fingerprint (`:88`). Owner confirmation is the governance command, not an invented conversational event (`:111`).
- `memory_provenance.go:188`, `writeMemorySourceLinksTx`: stores `source_ref`, source kind/ID/revision/fingerprint, occurred time and valid/unknown status. At `:226`, active row + all links resolved => `verified`; some resolved => `partial`; none => `pending`; nonactive row => `invalid`. This classification alone does not establish truth or entailment.
- `memory_provenance.go:234`: epistemic kind defaults to `inference`; owner actor => `user_statement`; episodic with outcome => `action_result`; authenticated direct => `self_report`; proposal => `summary`, in that precedence. These are creation-route classifications.
- `apps/core-go/internal/migrations/withdrawn_source.go:6`, `memory_source_is_live_deep`: rechecks fingerprints, revisions and existence; inbox additionally rejects `source_message_invalidated`. Memory ancestry has depth/cycle guards. Daily memories require all links; other memories need at least one live link. `owner_confirmation` checks an applied/no-change governance record. Again no semantic entailment check.
- `apps/core-go/internal/core/memory_retrieval.go:343`: retrieval recomputes verified/partial from live/total link counts and excludes pending/invalid. `legacy_unknown` is allowed without live proof and receives a ranking penalty (`:406`). Test `memory_provenance_test.go:14` verifies source loss gives partial with only remaining `effective_source_refs` (`:55`), then changed final source removes the memory (`:88`).

## Loaded lineage, subject and time

- `memory_retrieval.go:428`: loaded Memory retains ID/revision, actor refs, conversation ID, event/evidence refs, `effective_source_refs`, request digest, created/occurred time, epistemic kind and provenance. Actor refs are an association set, not a typed subject/predicate/object. Original message pointer exists if evidence/source refs use `message:<id>`; a `sequence:` or `fact:` ref requires inbox resolution. The loaded map does not expose per-link fingerprint/revision tuples or explicit valid-from/until.
- `apps/core-go/internal/core/active_memory.go:456`, `RetrieveActiveMemory`: loads actor refs, source_fact_id, evidence refs, validity interval, original time expression, precision/timezone, revision and scope. Filters current time and live supported commands (`:472`). `activeMemoryRowMap` at `:579` preserves those fields. Compact provider representation at `:591` omits actor/source/evidence refs and row revision.
- Active `source_validity=verified` means a nonempty latest matching command source kind, with liveness separately checked; absent source kind remains `legacy_unknown` (`active_memory.go:461`). `withdrawn_source.go:37` only supports inbox fact fingerprint or authenticated command fingerprint. This is provenance, not a commitment truth/fulfillment judgment.
- Resident snapshot SQL `apps/core-go/internal/migrations/resident_memory.go:23` retains Memory source refs, actor refs, conversation, occurred time and request digest. Its Active subset (`:47`) retains evidence refs and validity interval, but omits actor refs/source_fact_id, precision/timezone and epistemic kind. Content is truncated to 512 characters. Thus resident and full retrieval rows differ materially.
- `apps/core-go/internal/core/actor_facts.go:124`: explicit message source records author/kind/type/fingerprint. Only human user message authored by the subject, without inference assertion, becomes active user_statement (`:147`); otherwise uncertain inference. Direct owner definitions use owner-command provenance. This verifies source authorship/scope, not text-to-value entailment.
- `readActorFactsWith` (`actor_facts.go:263`) enforces active non-inference, time and source-message fingerprint. Loaded current facts preserve actor_id, attribute, typed JSON value, effective_at, revision and transition_kind. `source_ref`, replaced_by and valid_until are only emitted for history (`:296`); original `source_message_id` and fingerprint are not emitted. Persistence retains them (`:240`).

## Structured comparisons and confirmation limits

- Actor facts provide strongest exact key: owner + subject actor + attribute + value/time. Writer explicitly returns correction-required for assert with unequal JSON value (`actor_facts.go:203`), and change/correction retires or closes prior assertions. No NLP needed for equality, identity, interval or revision comparisons.
- Relationships: `relationship_edit.go:163` loads profile/target, role, metrics, trend, summary, emotional association, provenance and revision. Role schema (`:45`) allows arbitrary label/category/secondary strings and preferred addressing/self-reference; categories are not an exclusivity ontology. Exact target/profile/role-category/label/addressing/revision comparisons are possible; deciding incompatible social roles from arbitrary labels requires semantics beyond these fields. Metrics are bounded numeric values (`:96`), not factual predicates.
- `goal_evaluation_persistence.go:66` requires relationship scope, completed impact, matching target and evidence drawn from satisfied relationship judgments; `:356` writes role category `mutually_confirmed`. `goal_closure.go:205` checks valid scoped success-supporting sources, conversation-message authority, recipient participation, both speakers and one conversation (`:233`). It does not parse whether either message actually consents to the supplied label. Label remains evaluator supplied.
- `GoalCommitment` (`goal_closure.go:34`) has IDs, goal/stage/profile, status/revision, criteria version and window interval; expected_result, criteria text, opportunity condition and blocker are free text. Active Memory has kind/status/time/actor/source metadata but its promise is content text. Deterministic checks can detect stale revision, differing scope/actor, interval overlap, status and shared evidence identity; they cannot establish conflicting promises from arbitrary text or prove completion.

## Reference registry coverage

- `apps/core-go/internal/core/context_reference.go:245`, `buildContextReferenceIndex`, registers actor facts, resident/full Memory, selected-profile relationships, goals/intentions, outcomes, developing-self, overlays, drives/preferences/triggers, state/affect/appearance, schedule/items, scene/presence/life context. Active Memory is added separately via `addActiveMemoryReferences` (`:220`), with owner/conversation/status checks; calls include `intelligence.go:449` and `provider_context.go:128`.
- Thus the existing registry covers these structured entity groups, including Active Memory, but not every raw source group: no message or conversation-summary reference kind/registration appears in this file. Original evidence refs and ancestry links are not independently converted into reference entries. Registry validity proves scoped snapshot/ref integrity, not semantic corroboration.
