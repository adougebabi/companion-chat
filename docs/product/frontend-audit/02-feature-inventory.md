# 02 — 前端功能矩阵

本矩阵以实际交互/调用链为单位。路径相对仓库根目录；“后端实现”给出浏览器 API、Core route/service/tool 的入口；“数据来源”区分服务端权威数据与本地临时状态。A–F 表示交互闭环程度，不表示代码质量。
> 本文提及的 `App.vue`、`InstancesView.vue` 等前端文件名简写均相对 `apps/web/src/`；`stores/`、`components/`、`views/` 为该目录下子目录。 Go Core 简写 `server.go` 指 `apps/core-go/internal/httpapi/server.go`，`browser/routes.go` 指 `apps/core-go/internal/httpapi/browser/routes.go`，`core/...`、`migrations/...`、`builtin_capabilities.go`、`operations.go` 等相对 `apps/core-go/internal/`；`BrowserClient` 指 `packages/browser-client/src/index.ts`。
行内“待核验”表示当前证据没有闭环。

## 状态定义

- **A** 前后端接入且有有效交互；**B** 部分接入或管理流程不完整；**C** 只有界面/模拟行为；**D** 已有后端能力但无相应前端入口；**E** 仅有设计/文档而无有效实现；**F** 遗留、停用或证据不足待核验。
