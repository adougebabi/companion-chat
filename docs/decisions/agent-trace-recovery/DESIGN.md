# Agent 已提交 Trace 恢复

2026-11-19。实现记录，现行 Diagnostics 与 Cognitive 合同仍是规范来源。

## 决策与范围

重复 admission 先核对 Owner 与输入摘要，再读取该 Fluctlight/Agent/run 的工具账本。对于 running 和 failed 记录，从真实已提交账本补齐 Trace，不执行工具或模型。completed 保留已完成结果。五分钟过期策略不变。

Trace 合并以 capability 与业务 operation 为强身份，原生调用 ID 仅用于关联回执。已有查询、失败、模型调用与顺序保留，不按数组位置配对。旧记录缺 operation 时，只在账本原生调用唯一且调用参数一致时补身份；歧义记录保留原条目，并补带业务身份的真实回执。一个回执条目不能抵扣两笔操作。比较允许 ExecuteTool 在落账后补充的诊断坐标，以及顶层 replayed 布尔标记的变化，不更改业务输出。

Trace 与账本输出使用 json.Number 解码，保留大整数和不适合 float64 的数。Completion 延用既有解码。持久恢复只补 Trace 字段，不改未知结果扩展字段。

超时状态、失败码与补全 Trace 同一次条件更新；条件包含原状态和原结果。更新失败返回错误；并发正常 finish 或其他恢复获胜则重读实际终态。既有 failed 的补齐不伪造历史 finished_at。

## 威胁模型与信任边界

输入冲突必须先于结果解码和账本读取，防止混用另一请求的回执。账本查询同时限定 Fluctlight/Agent/run；校验账本列和序列化身份一致。损坏记录明确报错，不重放副作用。

返回与持久 Trace 都通过既有诊断脱敏投影，包括部分解码失败路径；失败输出不能回流凭据。成功业务回执遵守现有诊断规则，账本原始内容不被修改。SQL 使用绑定参数。
