# 媒体附件发布时间证据

2026-11-19。实现记录；不修改既有媒体质量与主体核验规则。

## 决策

新增线性迁移 0119_media_publication_time，前驱 0118_claim_evidence_versions。media_references.published_at 为 nullable timestamptz，无默认值、不回填历史。reference.created_at 可能是修复引用的时间，不代表附件交付。

正式新增消息附件、专用媒体结果消息、Moment 附件及正式出版消息/Moment 在同一业务事务插入明确 published_at，使用数据库 clock_timestamp。目标消息/Moment 已有该附件而只缺 reference 时写 NULL。已有引用冲突不更新：重复调用和并发重试不能刷新首次时间。附件与引用任一步失败整体回滚。

私聊旧消息后补附件只读明确 published_at；专用媒体消息和已发布 draft 的附件可保留既有消息创建时间证明。Moment 不从创建时间推断附件时间。没有证据仍返回 unknown；不是用户已读、浏览或下载时间。

时间以 UTC 精确表示参与 scope 内的 delivery ref 摘要；模型获得的快照与发布事务的受锁重验使用同一来源，时间变化令旧引用失效。

## 安全边界

写入时间由 Core 事务控制，不信任模型或调用者提供的时间。现有 Owner、参与者、素材归属、ready 与真实附件关联检查保留；时间本身不能证明画面主体或模型质量。SQL 参数绑定，不引入图片、凭据或业务数据证据上传。模型入口与提示词不变。

## 验证与限制

隔离 PostgreSQL 验证旧目标新挂载、并发首次与重复挂载、引用修复与历史 NULL、回滚、正式消息引用，以及私聊/Moment 发布前时间变化拒绝旧证据。迁移从 0118 升级、重复执行不改已知或未知历史，完整已发布迁移链回归。
