## L01 初始化、受控人格和长期状态

1. 只在需要验证创建时，用带测试标记的虚构描述走“描述→分析→预览→正式激活”；记录 analysis/source ID、激活 request ID 和最终角色 ID。中途刷新后以相同请求身份恢复，不重复激活。
2. 查询初始资料、Goal、世界/地点、当前人格、外貌和衣柜；服务重启后核对同一 ID 与版本。多人格均应可查询，合法 default 资料不能缺习惯或画像。
3. 在具有明确可评估的持久人格切换规则的测试角色中，从资料页提交受控切换。记录 Owner request→评估→执行→读回；允许规则拒绝。不能直接改 `active_profile_id` 验收。
4. 切换前后核对有效发型、穿着、物品和当前生活状态，已经生效的变化不能回到初始化。

先前环境的澄岚样例没有可用于正向切换验收的 typed persistent switch rule，仅作历史问题线索。当前脚本使用本次run-dir的实际角色；规则拒绝不能冒充切换成功，也不要临时伪造规则绕过。

## L03 取消、断流、失败与合法重试

1. 以一个新的测试回合观察请求处理阶段。先测试换页/关闭浏览器观察，确认 Worker 不因此被取消；返回后查询真实 turn 状态与消息。
2. 另一个回合使用页面的明确取消命令。确认取消指向正确会话与 turn，最终状态由服务器决定，已提交消息和副作用保留。
3. 对真实失败且 `turnRetryable=true` 的回合执行页面重试；必须保留原 turn、幂等键、用户消息、发送时区/偏移/时间。
4. 核查没有第二条相同用户消息，没有再次执行已成功的购买/媒体/发布；`agent_partial_committed` 等不可整回合重试状态不能误变成普通重试按钮。
5. 传输错误、Provider 失败、业务拒绝和已受理仍处理分别显示。从业务错误进入请求/实际任务详情，再读回原页面结果。

不能通过换新 turn ID、直接更新任务终态或重复整条 Agent 循环“修复”失败。

## L04 真实世界、NPC 和相遇

2. 连续浏览地图、附近、地点和 NPC，核对前后领域版本/事件不变（普通非 LLM 回归可先完成此项）。
3. 通过正式日程/活动路径令角色实际到达相应地点。记录确认的活动结果、在场证据与相遇机会；观察决策是否互动。
4. 若互动发生，读取实际事件、关系/记忆来源和 NPC 身份；若没有互动，必须有实际未触发/拒绝结果，不能为符合剧本强制结识。
5. 重复处理同一来源不重复结识；取消或失效在场不产生相遇。另一个运行世界使用同一 NPC 定义仍有独立的身份、事件与关系。
