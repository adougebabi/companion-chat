T04：调整主对话链，迁移而不是丢弃认知结算\n\n## 7.1 主链\n\n普通聊天：\n用户消息 → MeroMero 主对话 Agent → 正式发布。\n\n需要能力：\nMeroMero → 真实 ToolCall → Plugin/Core → 真实结果 → 按需继续决策和表达。\n\n不再固定：\nQwen 认知 → Writer；\nMeroMero 意图 → Qwen 代理 → MeroMero 文案。\n\n确定性插件不必再调用语言模型。\n插件内部确有提示词规范化等任务时，按其独立配置调用。\n\n## 7.2 正文生成与发布边界\n\n核对 conversation.reply、moment.publish 和现有 Writer 的真实职责。\n\n如果正文已经由负责表达的 Agent 生成：\n- 发布能力不得无条件再调用另一个 Writer 改写一次；\n- 不为了沿用旧接口保留隐式二段生成；\n- 仍复用已有唯一发布入口、持久草稿、媒体关联与幂等机制。\n\n允许独立的动态、日记、异步媒体附言 Agent。\n它们是任务不同，不是每条聊天的固定后处理。\n\n## 7.3 保留认知结算\n\n逐项核对现有：\n- claims；\n- influences；\n- output_preference_decision；\n- goal_event_candidates；\n- 其他认知、偏好、关系、Goal 和事件字段。\n\n为每项明确：\n- 原生产者；\n- 原消费者；\n- 迁移后生产者；\n- 触发时机；\n- 证据来源；\n- 一致性和幂等。\n\n不能因为旧认知 Agent 不再主导聊天，就让这些字段永久为空或丢掉下游消费。\n\n不需要阻塞聊天的派生分析，可以使用现有持久任务机制在已提交消息/事件之后处理。\n必须真实落地，不是无持久化保障的随意 goroutine。\n结果不能反过来伪造先前已经发生的行动或关系。\n\n## 7.4 保持交互\n\n保留现有流式显示、消息状态和新 UI 交互。\n涉及完成声明或附件的部分，在通过对应核验前不得作为正式内容落库/发布。\n\n不要为了安全，把所有普通聊天都改成固定模板或多模型审核。\n异步任务可以用真实任务状态展示进度，不伪造角色的动作和完成台词。\n\n验收：\n- 不需要工具的聊天不经过 Qwen；\n- 查询和行动仍能通过原生 ADK Loop；\n- 同一正文不会生成两遍、发布两遍；\n- 旧认知结算的业务效果没有丢失。\n\n---\n\n# 8. T05：恢复生图、动态的完整领域插件\n\n## 8.1 插件不是 Tool 的别名\n\n插件可以拥有：\n- Agent/Task；\n- Tool；\n- 配置；\n- Prompt/Context 声明；\n- 事件处理；\n- 持久任务；\n- 领域校验；\n- 必要的结果呈现注册。\n\n优先扩展现有 Capability/注册机制。\n不要创建一个并行的“新插件平台”绕开旧正式入口。\n\n所有 Tool 必须能脱离 Agent，通过同一正式实现独立调用和测试。\n权限、前置条件、幂等和领域校验在独立调用时也必须生效。\n\n## 8.2 最低生命周期能力\n\n实现或补齐：\n- 稳定 ID、版本；\n- 配置声明；\n- 必需/可选依赖；\n- 注册和初始化；\n- 启用/停用；\n- 状态查询；\n- 错误报告；\n- 工具与 Agent 发现；\n- 独立测试入口。\n\n停用策略必须明确：\n- 不删除已有数据；\n- 新请求不再获得已停用能力；\n- 在途任务是继续收尾、暂停还是取消；\n- 不重复提交或交付；\n- UI 不显示虚假可用状态。\n\n## 8.3 Image Plugin\n\n将现有生图领域逻辑归入清晰边界：\n- 角色拍摄意图；\n- 媒体主体与视角处理；\n- 冻结相关事实；\n- 提示词规范化；\n- 实际渲染请求；\n- 异步状态与恢复；\n- 质量判断；\n- 资源结果；\n- 与统一交付机制衔接。\n\n保留现有 ComfyUI/渲染适配、视觉身份及衣柜权威来源。\n\n媒体链必须明确：\n- 无人物画面不注入角色外貌与穿着；\n- 有人物时使用该入镜主体资料；\n- 自拍、他拍、镜前、设备是否入镜不能混淆；\n- 未知性别/外貌不能根据名字猜；\n- 当前画面不能为了“有氛围”擅自改变天气、时间、身份和穿着；\n- 创作性的场景设计与“当前真实生活照片”必须区分。\n\n保留现有 KEV 开关与接口。\n逐点核查 KEV 是推荐、筛选还是现有准入规则，不新增重复决策层。\n关闭/失败时沿明确的既有回退路径，不恢复固定自拍模板，也不放松 Core 权限。\n\n## 8.4 Moment Plugin\n\n覆盖现有：\n- 动态文案；\n- 可选媒体；\n- 发布；\n- 查询；\n- 已有评论/互动；\n- 状态和持久化。\n\n角色文案默认 MeroMero。\n不能把动态变成“直接发布一段随便拼的文本”。\n\n文字动态不能硬依赖生图插件。\n附图动态应明确对图片能力的可选依赖及失败处理。\n关闭动态插件不影响普通聊天和生活运行。\n\n## 8.5 Core 与插件边界\n\nCore/共享基础设施继续提供：\n- 身份与权限；\n- 事务；\n- 持久任务；\n- 事件；\n- 幂等；\n- 资源引用；\n- 统一发布/交付。\n\n领域规则放到对应插件或领域服务。\n不得把一致性全部挪进 Prompt，也不得让插件绕开 Core 直接改状态和发送消息。\n\n验收：\n- Image 与 Moment 都是实际可调用的完整能力，不是空壳注册；\n- 关闭 Image，文字聊天与纯文字动态仍可运行；\n- 关闭 Moment，其他能力仍正常；\n- Tool 独立调用和 Agent 调用经过同一实现与校验。\n\n---\n\n# 9.
